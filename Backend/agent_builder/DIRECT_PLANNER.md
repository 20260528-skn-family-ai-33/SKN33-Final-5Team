# 로컬 메인 모델의 초안 생성·코드 검증 경로

`A4B_PLANNER_MODE=direct`로 선택하는 실험 경로다. 기본값 `deepagent`는 기존 동작을 유지한다. 모델 가중치 학습·파인튜닝은 하지 않는다.

## 처리 순서

1. 실제 도구 16종, 포트, 자료 ID·열·프로파일·문서 앞부분, 대화와 기존 초안을 모델에 제공한다.
2. 모델은 AgentDraft JSON 하나를 생성한다. list_tools/validate_workflow를 부르기 위한 추가 생성은 없다.
3. Python의 AgentDraft, 기존 정규화, 노드 참조 계약, validate_node가 초안을 검사한다.
4. 의미·연결 오류는 기존 graph의 validate → supervisor → conversation 경로에서 한 번 수정한다. 스키마 오류 재시도도 이 두 번의 생성 예산에 포함한다.
5. 검증 통과 후에도 사용자 승인을 기다린다. 이 경로 자체는 실행·저장하지 않는다. 질문이 있으면 실행 초안을 제거하고 대기하며, 지원 불가는 별도로 안내한다.

```sh
export A4B_PLANNER_MODE=direct
export A4B_MAIN_PROVIDER=ollama
export A4B_MAIN_BASE_URL=http://127.0.0.1:11434/v1
export A4B_MAIN_TIMEOUT_S=90
```

기존 앱 시작 명령에 위 환경을 적용하고 메인 모델을 `qwen3.5:4b` 등 실제 설치된 이름으로 선택한다. 원복은 `A4B_PLANNER_MODE=deepagent`다. 현재 direct transport는 Ollama 전용이며 인증이 필요한 원격 서버 연결은 별도 구현이 필요하다.

## 생성 조건과 계약

native `/api/chat`, num_ctx=16384, num_predict=4096, temperature=0.7, top_p=0.8, seed=42, think=false, stream=false를 사용한다. 기존 모델 설정·가중치를 변경하지 않는다. 모델·버전에 따라 thinking 제어 지원 여부가 다르므로 실제 토큰·반환 로그도 확인한다. seed 고정만으로 완전한 재현을 보장하지 않는다.

16개 도구별로 전체 노드 스키마를 복제하지 않고 공통 AgentDraft 스키마를 쓴다. 로컬 grammar 문제를 피하려고 디코더 스키마에서 maxLength/pattern을 제외하지만 **최종 Pydantic 길이 제한·도구 enum·자료 범위·포트·근거 원문 검사는 유지**한다. 형식 준수는 업무 의미의 정답을 보장하지 않는다.

자료 ID를 파일명에서 추정하거나, 없는 문서 ID를 현재 자료로 덮어쓰지 않는다. 잘못된 ID·원문 인용은 수정 대상이다. 문서 설계 입력은 앞 12,000자이며 전체 문서를 이해했다고 간주하지 않는다. 기존 SVM 추천 hint는 이 실험 경로에서 사용하지 않고 전체 도구 목록을 제공한다.

trace에는 planner_mode, 모델 호출 수, 토큰 수·시간(서버가 반환한 경우), 코드 오류를 남긴다. 모델 출력에 맞춰 정답을 변경하지 않는다. 모델 오류·통신 실패를 업무상 unsupported 정답으로 바꾸지 않는다.

## 확인할 항목

- 단위·회귀 검사: `python -m pytest agent_builder/test_direct_conversation.py agent_builder/test_deep_agent_conversation.py agent_builder/test_ollama_planning.py agent_builder/test_workflow.py agent_builder/test_node_library.py -q`
- 실제 모델: 충분 조건/누락 조건/지원 불가/답변 이후 조건 반영을 같은 예산으로 비교한다.
- 표 업무: 실행기 결과와 별도 정답 계산을 대조한다. 문서 업무: 실제 추출 모델의 값·인용을 따로 측정한다.
- 기존 Deep Agent 경로와 다른 프로토콜이므로 점수를 합산하지 않는다. 개발용 파일럿으로 프롬프트를 조정했다면 최종 평가는 새 원본으로 분리한다.

승인·DB 저장·실제 앱 UI·문서 추출 모델까지의 전체 통합 검증은 별도 단계다.

## 판정 품질 개선 실험 (2026-10-22 후속)

`A4B_PLANNER_PROMPT=v1`이 기본이다. `v2`는 판정 우선 순서·스키마 필드 순서·자료 문맥을 바꾼 개발 실험이며, 불필요한 실행 가능 판정과 결과 조건 누락이 나와 채택하지 않았다. 기본 앱을 v2로 전환하지 않는다.

`request_judgement.py`는 워크플로우 생성과 분리한 실험용 판정 모듈이다. 다음처럼 명시적으로 호출하며 기존 graph에는 자동 연결하지 않았다.

```python
from agent_builder.experiments.request_judgement import judge_request

result = judge_request(
    {"messages": [{"role": "user", "content": "사용자의 실제 요청"}],
     "resources": [], "draft": None},
    "qwen3.5:4b",
)
decision = result["judgement"]["decision"]
```

Ollama 환경은 위와 동일하다. 이 모듈은 학습된 새 가중치가 아니라 기본 모델에 검수한 예시 6개와 출력 계약을 제공한다. 예시는 실제 사용자 이력과 분리하고, 출력 키 순서는 디코더 스키마와 맞춘다. 근거 원문은 모델이 재작성하지 않고 실제 요청별 evidence_id를 선택해 코드로 연결한다.

`ready`/`clarify`/`unsupported`와 조건별 상태·질문의 논리적 일관성, 근거 ID 소속을 검사한다. 잘못된 응답은 예외로 보류하며 업무상 unsupported로 바꾸지 않는다. 인용 연결의 정확성은 근거가 주장을 뒷받침하는지와 별개다. ready가 곧 워크플로우 결과의 정확성·사용자 승인·실행 허가라는 뜻도 아니다.

`OllamaPlanner(model, thinking=True)`는 연구용으로 생각 모드를 명시하는 인자다. 기본값은 False이며 기존 앱 동작은 바뀌지 않는다. 이번 3건 시험은 2건이 요청 상한 90초에 도달해 생각 모드를 기본으로 채택하지 않았다.

`binding_repairs.py`는 실제 앞 노드의 유일한 호환 출력과 명시된 파일의 읽기 자기참조만 보정하는 별도 함수다. 변경 내역을 반환하며 도구·조건·연결 구조는 만들지 않는다. 현재 생성 경로에 자동 적용하지 않았다. 잘못된 의미를 가진 초안을 포트 보정만으로 승인해서는 안 된다.

## v3: 입력 경로와 오류 수정 문맥 실험

`A4B_PLANNER_PROMPT=v3`는 v2에 다음 정보를 추가하는 선택 경로다. 기본 v1과 기존 Deep Agent 설정은 유지한다.

- 설계 시 파일이 없더라도 읽기 노드를 생략하지 않고 `file_ids=[]`로 실행 자료를 받는 규칙.
- edges와 입력 bindings가 별개이며 실제 앞 단계 출력에 연결해야 한다는 규칙.
- 현재 초안의 노드별 선언 포트·미연결 포트·기존 bindings. 선택 포트도 포함하므로 미연결 목록 전체를 필수 오류로 판단하지 않는다. 실제 오류는 기존 검증기가 결정한다.
- 재생성 시 코드 오류를 마지막 수정 요청으로 전달하고 정확했던 조건·원문 인용을 보존하도록 안내.

모델이 전체 초안을 다시 생성한다. 코드가 누락된 읽기 노드를 넣거나 인용을 원문으로 치환하지 않는다. 스키마·연결·자료·근거·조건 검증, 총 생성 2회 한도, 사용자 확인은 유지한다.

실제 모델 개발 비교 기록은 작업공간 `research/a4b_direct_planner_20261026`에 별도로 보관한다. 샘플 점수만으로 기본 경로를 변경하지 않는다.

## v4: 원문 선택 제약과 명시적 workflow 반환

`A4B_PLANNER_PROMPT=v4`는 v3의 입력·수정 안내에 생성용 제약을 더한다. 실제 사용자 발언·자료 본문·열 이름에서 정확한 부분 문자열 후보를 만들고, `requirements.quote`의 디코더 enum으로 제공한다. 최근 사용자 발언 12개(발언별 앞 4000자)를 최신순으로 우선하고 제공 자료 발췌·열 이름을 더하되 최대 64구간·총 6000자로 제한한다. 문서 전체 검색이나 근거 관련성 판정이 아니며, 목록 밖의 근거·오래된 대화는 빠질 수 있다.

모델의 반환 인용을 코드가 대체하지 않는다. 기존 코드 검증은 출처 ID와 실제 원문의 일치 여부를 계속 검사한다. 원문이 존재해도 해당 업무 조건을 뒷받침한다는 의미는 아니다.

생성용 스키마에는 `workflow`를 필수 키로 추가한다. 질문·미지원 상태의 `null`은 허용한다. 실제 업무 초안이 없으면 기존 검증이 차단한다. 공개 AgentDraft 스키마, 저장 계약, 승인 절차와 기본 프롬프트(v1)는 변경하지 않는다.

개발 중 `candidate_v4` 기록은 workflow 필수 키 보완 전이며, `candidate_v4_required_workflow`는 보완 후다. 각 실행의 소스 사본과 해시로 구분한다. v4의 다회 대화 시험은 실제 worker처럼 사용자 답변마다 생성 횟수를 초기화한다. 초기 v2/v3 시험의 다회 대화는 이 초기화가 없어, 그 대화 점수를 직접 전후 비교하지 않는다. 단일 요청의 표 선별·중복 제거 사례는 동일한 생성 예산으로 비교한다.

## v5: 업무 조건 이름과 실제 열 이름 구분

`A4B_PLANNER_PROMPT=v5`는 v4에 다음을 추가한다.

- 생성 입력의 조건 장부를 읽기 전용 업무 설명으로 투영한다. `duplicate.field` 같은 내부 키를 그대로 전달하는 대신 ‘중복 판단 열’이라는 의미와 실제 값(예: 주문번호), 실제 열 여부, 상태, 원문 근거를 전달한다.
- 중복 제거만 요청한 경우 filters/sort를 비우고 실제 중복 열과 보존 정책을 사용하도록 안내한다. 빈 값 처리 정책을 is_empty 필터로 변환하거나 임의 정렬을 추가하지 않도록 명시한다.
- 원래 조건 장부와 생성 응답은 변경하지 않는다. 조건 감사·저장 전 검증은 원래 장부를 사용한다. 잘못 생성한 필터를 코드가 삭제하거나 정답 초안으로 교체하지 않는다.

이는 프롬프트와 입력 표현 개선이다. 모델 학습·SVM 변경·새 도구 생성·코드 템플릿 생성이 아니다. 선택 실험 경로이며 기본 v1/deepagent/조건 검사 off는 유지한다. 실제 재검증과 요구사항별 적용 범위는 작업공간 `research/a4b_requirement_audit_20261026`에 보관한다.

v5 후속 보완에서는 단일 중복 제거의 생성용 ExecutionPlan에 filters/sort 최대 길이 0과 이미 확정된 중복 열·보존 정책 등을 제약으로 제공한다. 같은 제한을 원래 조건 장부의 코드 감사·저장 검사에서도 강제한다. 선택 경로의 제약 기반 생성이며, 무제약 Qwen이 모든 설정을 독자적으로 맞혔다는 결과는 아니다. 임의 코드나 워크플로우 토폴로지를 제공하지 않는다. 초기 `candidate_v5`와 강화 후 `candidate_v5_enforced`는 소스 해시로 구분한다.

## v6·v7: 자료·포트 제약과 확정 조건 보존 (2026-10-27)

v6 이상은 디코더에 현재 자료 ID·등록 도구별 입력 포트·호환 출력 이름을 제공한다. 실제 선행 노드가 해당 출력을 제공하는지는 기존 코드 검증이 다시 확인한다. 잘못된 자료 ID나 연결을 정답으로 덮어쓰지 않는다. 새 사용자 답변에서는 이전 초안보다 현재 조건을 우선하고, 오류 수정 요청에는 실패 초안과 실제 선행 출력 후보를 제공한다.

v7 이상은 조건 검사 enforce에서 단일 선별·중복 제거의 필수 조건이 이미 확정된 경우, 생성기가 다시 업무 질문을 만들어 초안을 제거하지 않도록 출력 계약을 제한한다. 이 제한은 조건 판정 자체를 생략하거나 사용자 승인을 대신하지 않는다.

## v8: 선택한 단계로부터 연결 구조 컴파일

`A4B_PLANNER_PROMPT=v8`의 좁은 적용 범위에서는 Qwen이 `workflow.steps`로 도구·순서·설정을 선택한다. `linear_plan.py`가 이를 공개 AgentDraft의 노드 ID·시작점·순차 연결·유일한 호환 입출력으로 변환한다. 일반 코드가 구조를 구성하는 **컴파일 보조 생성**이며, Qwen이 원시 그래프 JSON 전체를 독자적으로 맞히는 평가와 구분한다.

- 적용 조건: 조건 검사 enforce, READY, 단일 선별 또는 중복 제거, 필수 조건 확정, 저장 노드 참조 없음.
- 선택 가능한 도구: `read_table`, `filter_sort`, `write_result`, `finish`. 첫 읽기 단계도 모델이 명시해야 한다.
- 컴파일러는 도구 삽입·순서 변경·형변환·실행을 하지 않는다. 유일하게 연결할 수 없는 순서는 오류다. 누락된 업무 처리는 기존 조건 감사에서 차단한다.
- 범위 밖 요청은 일반 디코더 경로로 돌아간다. 분기·복합 업무·문서 업무·저장 노드 재사용의 성공을 이 시험으로 주장하지 않는다.
- 생성 후 정규화·조건 감사·구조 검증·사용자 확인·저장 직전 검증은 계속 적용한다. 실제 결과 정답은 저장 후 별도 실행으로 확인한다.

기본 `v1`/`deepagent`/조건 검사 `off`는 유지한다. 실서비스나 팀 API에 자동 활성화하지 않았다. 실제 모델 개발 기록과 중간 실패·소스 사본은 작업공간 `research/a4b_workflow_repair_20261027`에 보관한다. 이 사례는 프롬프트 개발에 사용했으므로 일반화 성능은 새 사람 검수 평가셋에서 따로 확인해야 한다.
