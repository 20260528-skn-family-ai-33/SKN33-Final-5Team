# 교차검증 및 전달 판정

검증일: 2026.10.20. 기준 모델은 로컬 Ollama Qwen3.5-4B이며 추가 학습은 0회입니다. 검증 기록은 `reports/`에 보존합니다.

## 완료한 교차검증

1. Pydantic 계약과 별도 `jsonschema` Draft 2020-12 검증기로 같은 JSON을 대조했습니다. 저장된 스키마가 코드에서 내보낸 스키마와 일치하는지도 확인했습니다.
2. 자동 검사 17개를 통과했습니다. SQLite 문서 버전 저장·정확한 조회, 가짜 원문, 없는 열·잘못된 포트, 순환, 초안 미반영, API 시간초과·미완료, 모순 응답, NaN, 정렬·집계 이후 열 스키마를 포함합니다.
3. 대표 fixture 13건의 후속 경로를 수작업 기준표와 대조했습니다. 고정 예제 응답이므로 Qwen 모델의 13/13 정확도를 뜻하지 않습니다.
4. ‘200만원 초과’와 ‘200만원 이상’의 기대 행을 별도의 Decimal 비교로 검산했습니다. 초과는 D행, 이상은 C·D행으로 다릅니다.
5. 실제 로컬 Qwen에서 같은 3건을 초기/최종 두 번 실행했습니다(총 6호출, 독립 6문항이 아님). 최종 결과와 입력·소스 해시를 보존했고, 저장된 실제 모델 응답에 코드 검사만 다시 적용해 같은 경로·진단이 나오는지 대조했습니다.

## 실제 모델 연결 결과: 품질 미통과

| 사례 | 기대 | 최종 결과 |
| --- | --- | --- |
| 01_ready | ready, 초안 pass, 다음 검토 | 일치 |
| 02_missing_selection | clarify, 선택 기준 누락, 사용자 확인 | 모델이 ready/pass로 오판. 잘못된 원문 인용을 코드가 발견해 manual_review |
| 05_reflection_wrong_operator | ready, 반영 fail, 초안 수정 | 모델이 반영 검증을 비적용으로 잘못 판단. 코드가 검사 생략을 발견해 manual_review |

**JSON 응답·계약 형식은 3/3, 전체 의미 축·기대 경로는 1/3입니다.** 두 오판이 이번에는 코드에 걸렸다고 모든 의미 오류를 코드가 잡는다고 일반화하지 않습니다. 정확한 원문을 인용하면서 의미를 틀리는 오류는 남을 수 있습니다. 실행 허가는 모든 경우 false입니다.

이 3건은 연동용 작은 합성 예제입니다. Macro-F1이나 일반화 정확도로 보고하지 않으며, 과거의 label-only 실험 수치와 직접 비교하지 않습니다. 입력에는 16개 도구·실제 초안·증거 은행이 추가됐고 출력도 길어졌습니다. 최종 호출 지연과 모델 digest는 `reports/live_smoke.json`에서 확인하세요. 예열·모델 적재를 제외한 표준 속도 벤치마크가 아닙니다.

## 테스트 중 발견해 수정한 사항

- JSON 모드 직렬화가 비유한 숫자를 null처럼 바꿀 수 있어 직렬화 이전의 Python 값으로 NaN/Infinity를 검사하도록 수정했습니다.
- 집계 출력의 count/sum 열을 후속 필터에서 정확히 추적하고, 정렬 열·방향·자료형을 검사하도록 보완했습니다.
- 답변 반영 판정에 실제 최신 사용자 답변의 인용이 필요한지 검사합니다.
- live 의미 검사가 실패하면 검사 스크립트도 종료 코드 1을 반환하도록 했습니다.

모델이 틀린 두 예제를 맞추기 위한 추가 파인튜닝·프롬프트 변경은 하지 않았습니다. 코드 검증·오류 보고를 보완했고, 실패 원문도 보존했습니다.

## 재현 명령

```bash
python scripts/run_tests_report.py
python scripts/run_suite.py --mode fixture --output local_runs/fixture_suite.json
python scripts/crosscheck.py
python scripts/verify_manifest.py
```

crosscheck는 전달본의 reports와 현재 코드를 대조합니다. 코드를 변경하면 과거 live 소스 해시는 의도적으로 맞지 않게 됩니다. 새 live 기록을 만들고 확인해야 합니다. manifest는 전달 파일 그대로인지 검사하므로 reports를 덮어쓴 후에는 해당 파일 변경을 감지합니다.
