# 기존 ML 도구 추천 모듈 — 선택 검토용

여기에는 어제 실험에서 사용한 **기존 팀 SVM 도구 추천 모델**과 관련 정책 함수를 원본 그대로 담았다. 새로 학습하거나 성능을 개선한 모델을 전달하는 것은 아니다. 모델 SHA256은 출처 기록과 동봉 캐시 기록으로 확인할 수 있다.

`model_bundle/tool_rec/recommend.py`의 `recommend_tools(request, kind, columns)`는 도구별 점수 `probs`, 후보 ID `candidates`, 전체 목록으로 돌아갈지 나타내는 `full_list`를 반환한다. 실제 요청과 파일 구조를 입력하며 정답·평가 라벨을 입력하지 않는다.

연결 시 구분할 것:

- 원본 `candidates`에는 규칙으로 finish 등이 추가된다. 이를 ML이 예측한 필수 도구라고 취급하지 않는다.
- 어제 비교는 전체 16개 도구 명세를 유지했다. 원본 함수의 설명처럼 전체 도구 명세를 후보로 대체한 새 실험 결과와 혼합하지 않는다.
- `policy/checker_feedback.py`는 설계 **후** 점검 경고다. 경고는 자동 삭제·자동 불합격 판정이 아니며, 호출만으로 앱에 자동 연결되지는 않는다.
- 점검 함수는 `models/tier_thresholds.json`을 읽거나 `warnings(draft, probs, th=...)`로 기준값을 받는다. 동봉 값은 D1 학습 OOF에서 고정한 high=0.5, low=0.03이다. 이번 평가 문항으로 조정하지 않는다.
- 추천 원본을 읽는 환경은 `requirements-ml-reference.txt`에 당시 확인한 버전을 적었다. 팀의 전체 앱 의존성을 무조건 이 파일로 덮어쓰지 않는다.

현재 이 ML 점검 방식이 기본 Deep Agent보다 업무 성공률을 높였다는 결과는 확보하지 못했다. 팀 통합 시 Qwen 연결 수정과 ML 도입을 각각 독립적으로 확인한다. 선택해 사용하지 않더라도 Qwen 연결 클래스는 별도로 적용할 수 있다.
