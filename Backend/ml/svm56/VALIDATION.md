# ML 서비스 정합성 변경 및 검증 (2026-11-02)

기준 main: `378b7b9`. 실행 그래프의 기본 흐름을 유지하며 ML 힌트·서비스 입출력·학습 산출물의 정합성을 보완했습니다. 기본 추천 모드는 계속 `off`이며 새 모델을 자동 적용하지 않습니다.

## 변경 내용

- 단일 요청과 다중 사용자 턴을 구분하고, 행위 부정·취소는 전체 도구 계획기로 넘깁니다. 원본 첨부와 도구의 중간 출력 포트를 구분해 필요한 후보를 보존합니다.
- 표/문서 저장 도구 연결, CSV 생성 의도, 열 이름의 저장 키워드, 인용 명령 및 영문 소유격·축약 부정문의 처리를 보완했습니다.
- 후보 모델의 도구별 기준값과 유한한 점수를 검증하며, 정확한 모델 SHA256 확인 후 로딩합니다.
- 사람 미검수 합성 보강 48건과 후보 학습·그룹 내부 선택·OOF 비교 도구를 추가했습니다. 미확인 레이블 -1을 음성으로 바꾸지 않습니다.
- 기존 학습 출력 폴더 재사용을 거부합니다. 완료 매니페스트, 원본/산출물 해시, fold별 학습/검증 ID를 검사하고 저장된 fold 모델로 검증 대상 예측을 재계산합니다. 이전 실험은 새 형식으로 재학습해야 합니다.
- 입력 설명 기반 모의 첨부 평가와 실제 파일 파싱·저장·reader 회귀 검사를 추가했습니다. 모의 메타데이터를 실제 업로드로 간주하지 않습니다.
- Docker의 선택 ML 의존성·읽기 전용 모델 마운트와 capability/condition 설정 전달을 추가했습니다.
- Ollama의 기본 :latest 모델 이름 비교를 보완했습니다. 현재 Ollama가 무시하는 max_completion_tokens를 Ollama 전송 복사본에서만 max_tokens로 변환해 요청한 출력 한도를 적용합니다.
- ML 패키지 미설치 환경에서는 학습 전용 테스트를 명시적으로 건너뜁니다.

## 데이터·모델 결과의 한계

원본 5,431건의 고정 분할 개발 평가에서 원시 56-label micro-F1은 92.4537%→92.7607%, FP 514→499, FN 909→868, 복합 요청 필수 도구 포함은 402/515→406/515로 재현됐습니다. 재학습 후보 SHA256은 `560cefdb7fd24204945332e9d2450048733360de00be2971752841670a9710c6`입니다. 가중치 파일과 원본 전달 자료·실험 산출물은 이 커밋에 포함하지 않습니다.

후처리의 공통 16-label 일치도는 첨부 미확인 조건에서 92.3460%, 설명 기반 모의 첨부 조건에서 90.9923%로, 리뷰 전 약 92.42%/91.04%보다 소폭 낮습니다. 모든 지표가 개선됐다고 주장하거나 후보를 자동 승격하지 않습니다. XLSX 요약의 불필요한 read_table 후보 1건도 남아 있습니다.

원본과 반복 사용한 합성 요청은 개발·회귀 자료이며 사람 승인 정답이나 독립 최종 평가가 아닙니다. 한 개 실제 업무 실행 성공은 일반적인 추천 정확도나 모든 요청의 성공을 보장하지 않습니다.

## 재현

1. 저장소 기본 Node/Python 환경을 준비합니다. ML 검증에는 `Backend/requirements/ml-svm56.txt`도 설치합니다.
2. `python -m pytest Backend/tests -q`, `npm run check`, `npm run build`를 실행합니다. Node 전체 검사는 `A4B_AGENT_PYTHON`을 준비된 Python 경로로 지정한 뒤 `npm test`를 실행합니다.
3. 전달받은 원본 통합 패키지의 데이터/카탈로그/고정 분할을 사용해 `Backend/ml/training/README.md`의 새 디렉터리 학습·비교 절차를 실행합니다.
4. Docker는 `.env.example`의 선택 ML 빌드/마운트 설정과 정확한 모델 SHA256을 사용합니다. 기본 Qwen 프로필은 `Backend/scripts/setup-ollama-model.sh`로 준비합니다.
5. 컨테이너의 `/app/Backend`에서 `python -m ml.svm56.verify_service --bundle /app/ml-bundle --model /app/ml-bundle/model/candidate.joblib --model-sha256 <검증한 SHA256>`로 실제 모델 진단을 실행합니다.

## PR #21 후속 수정 (1af944a 리뷰)

- Docker의 condition enforce가 좁은 선별·중복·예약 검사 밖의 문서 작업까지 차단한 회귀를 수정했습니다. 유효한 `other` 판정은 조건 검사 승인이 아니라 기존 설계 경로로 넘깁니다. 이전 표 조건·질문은 해제하고, 기존 지원 판정·설계·검증·승인 절차를 거칩니다. 혼합 작업·명시적 미지원·취소·입력 장애는 이 경로로 우회하지 않습니다. shadow의 진단 결과도 보존합니다.
- 영수증→CSV 요청이 `other`로 분류됐을 때 실제 설계 그래프가 기존 항목 질문까지 도달하는 회귀 테스트를 추가했습니다. 이후 표 선별 요청에서는 다시 조건 검사가 적용되는 것도 검사합니다. 이 테스트의 분류/설계 응답은 고정 fixture이며 실제 LLM 분류 정확도 시험은 아닙니다.
- 학습 안내를 `PYTHONPATH=Backend python -m ml.training.train_candidate`로 수정했습니다. 직접 파일 실행도 완료 매니페스트 모듈을 정상 import하도록 지원합니다.
- `PYTHONPATH`를 제거한 실제 직접 명령으로 원본 5,431건+보강 48건의 5-fold 학습·모델 저장·`COMPLETE.json` 생성과 후속 비교기의 파일/fold/모델 재계산 검증을 통과했습니다. 이 실행은 CLI 검증용 char 후보이며 기존 운영 설정이나 모델을 바꾸지 않습니다.
- 후속 검사: 조건·학습 무결성 관련 230개 통과, Python 전체 949개와 하위 테스트 4개 통과, 최소 ML 환경 74개 통과·3개 선택 모듈 건너뜀, 타입 검사·빌드 통과. 직접 파일 실행에서 `ml` import 루트가 없는 상황도 자동 회귀 검사합니다.
