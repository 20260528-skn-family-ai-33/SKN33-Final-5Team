## 설명 문구

버튼 이름 → 사용자가 하는 일 → 나타나는 결과 순서로 설명한다. 실제 지원하지 않는 편집·외부 전송 기능을 안내하지 않는다. 내부 모델·도구 계약·포트 이름을 첫 설명에 노출하지 않는다.

| 이전 문제 | 수정 |
| --- | --- |
| 처음에 역할부터 준비해야 하는 것처럼 설명 | 업무 설명 → 처리 순서 확인 → 저장·실행으로 소개. 라이브러리는 선택 사항 |
| 설계 에이전트·등록된 공통 코드 등 구현 관점 설명 | 문서 읽기·행 선택·정렬·그룹별 집계·결과 저장 등 실제 동작 설명 |
| 저장된 설계에 새 업무를 입력하라는 안내 | 저장된 내용 확인 → 설정 수정 → 새 버전 저장으로 구분 |
| 설정해서 저장 버튼이 즉시 저장하는 것처럼 보임 | ‘설정하기’로 변경. 양식의 ‘작업 저장’이 실제 저장 동작 |
| 준비된 AI 작업마다 똑같은 일반 설명 | 각 역할의 목적은 유지. 데이터 처리 기능은 공통 사용자 설명 사용 |
| 작업 준비·설계·실행의 메뉴 혼동 | 작업 라이브러리 / 워크플로우 설계 / 워크플로우 실행을 구분 |

도구 설명은 `app/tool-copy.ts`에 한 번 정의한다. 기존 사용자 작성 목적·서버 계약·도구 ID·저장 형식은 바꾸지 않는다.

## 버튼을 따라가는 안내

긴 사용설명서 창을 제거하고 실제 버튼·화면 영역을 강조하는 안내를 구현했다.

- 이전 / 다음 / 나중에 보기 / 안내 닫기 / Esc
- 첫 작업 공간 방문 시 자동 안내. 완료·건너뛰기는 브라우저에 기억하고 ‘사용 안내’로 재시작 가능
- 목록 안내 마지막의 ‘설계 시작’으로 새 설계 화면을 열고, 설계 안내를 이어서 표시
- 새 설계: 업무 설명 → 자료 연결 → 처리 순서 → 설정·저장 → 실행 탭
- 저장된 설계: 저장한 업무 확인 → 처리 순서 → 저장된 설정 → 설정 수정 → 실행 탭
- 라이브러리: 설정하기 → 이 작업으로 설계 → 새 작업 → 작업 설정 → 저장한 작업
- 실행: 저장한 흐름 선택 → 실행 요청 → 실행 버튼 → 결과 (현재 화면에 존재하는 대상만 안내)
- 저장한 흐름이 없으면 ‘새 워크플로우’부터 안내
- 샘플 미리보기는 저장·실행되는 실제 화면과 구분
- 모바일에서는 해당 패널을 열어 보여 준 뒤, 안내 종료 시 원래 패널·스크롤로 복원
- 안내가 저장·실행·파일 선택 버튼을 대신 누르지 않음. 실제 실행이나 모델 요청을 자동으로 보내지 않음

키보드 포커스 관리는 기존 Radix Dialog를 재사용한다. 위치 측정은 ResizeObserver와 resize/scroll 리스너로 갱신하고, requestAnimationFrame으로 묶으며 닫힐 때 정리한다. 별도 투어 패키지를 추가하지 않았다.

## 코드·효율 개선

- 로고 SVG 1개, 공통 헤더·사이드바, 공통 도구 설명으로 중복을 줄였다.
- 삭제된 헤더·긴 안내용 CSS를 정리했다.
- 실행 기록 조회의 무제한 Promise.allSettled 호출을 동시 4개 요청으로 제한했다. 개별 실패·원래 순서를 유지하며, 화면 이동 후 대기 요청은 시작하지 않는다.
- 신규 안내·비동기 유틸은 기존 큰 화면 컴포넌트에서 분리했다.
- 기존 agent-studio.tsx는 여전히 여러 업무 기능을 포함한 큰 컴포넌트다. 이번에 전체를 새로 작성했다고 주장하지 않는다. 추가 분리는 상태 복원·동시 요청·저장 동작을 보존하는 별도 변경으로 검토해야 한다.
