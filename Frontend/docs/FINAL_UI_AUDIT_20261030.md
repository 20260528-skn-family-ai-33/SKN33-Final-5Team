## 일반적인 AI 템플릿 느낌을 줄인 기준

- 장식용 반짝이 아이콘을 기능을 나타내는 문서 검색·워크플로우 아이콘으로 교체했다.
- 내부 화면은 흰색·중립 구분선·짙은 파랑의 주요 행동을 중심으로 유지했다. 살구색은 AI 작업 분류와 안내 강조에 제한한다.
- 메뉴·폼·실행 영역의 둥글기는 작게 유지하고, 목록은 큰 그림자 카드 대신 구분선과 텍스트 중심으로 구성했다.
- 화면별로 반복되는 환영 문구 대신 입력할 내용·확인할 설정·다음 행동을 설명한다.
- 실제 기능이 AI인 경우에는 AI 작업이라는 명칭을 남겼다. 기능을 이해하는 데 필요한 표현이다.
- 사용자가 유지하기를 원한 첫 진입화면의 스크롤 구성은 보존했다.

이는 디자인 검토 기준과 수정 내역이다. 시각적 취향을 자동 테스트가 보증하는 것은 아니다.

## 브라우저 재연결 후 실제 Qwen 검증

설정 화면의 브라우저 토글은 이미 켜져 있었다. 도구 연결이 복구된 뒤 검증을 재개했다. 이전에 설정이 꺼져 있다고 단정한 기록은 정확하지 않다.

- 기존 테스트 Pod `bzkujchxwiwb6r`는 GPU 가용성 부족으로 시작할 수 없었다. 사용자에게 동일 구성 이전을 승인받아 `gturg4pr9kq5ss` L40S 한 대를 사용했다. 실제 표시 요금 $1.10/시간, 승인 상한 $5.
- 이전된 workspace가 비어 있어 기존 설치 ZIP으로 Qwen3 8B와 검수 모델을 복원했다. 원격 모델은 기존 Bearer 인증 게이트웨이로만 연결했다. 개인 설정의 두 모델 URL은 새 Pod 주소로 갱신했으며 비밀키는 산출물에 넣지 않았다.
- 로컬 3151 서버는 RunPod 모델을 사용하고 데이터는 별도 임시 폴더에 저장했다. 3150의 UI 예제 서버와 구분한다.
- 합성 CSV: A=10, A=20, B=40. 요청: team별 amount 합계, JSON 저장.
- 최초 모델 초안은 요청하지 않은 `missing_policy=exclude`를 추가했다. 실제 filter_sort 노드가 없어 검증에서 차단했고 저장되지 않았다. 검증기를 느슨하게 바꾸지 않았다.
- 생성 지침에 filter_sort가 없을 때 중립 정책을 쓰고, 합계 숫자 검증을 빈 값 삭제로 대체하지 않도록 명시했다. 사용자 역할의 테스트 수정 요청으로 빈 값·중복 유지 조건을 전달한 뒤 모델 응답은 검증을 통과했다. 이 결과가 최초 생성의 보편적인 성공률을 증명하지는 않는다.
- 실제 브라우저에서 수정 → 저장 → 실행을 수행했다. workflow `1f49d64c-297f-4909-90b9-bbe813b7e979`, run `c8d94889-3511-49c2-8a59-67d01f396365`.
- 실행 결과 `succeeded`, A=30 / B=40. 새 탭에서 저장된 설계·동일 실행 결과가 복원되는 것도 확인했다.
- 결과 보고서 HTTP 200 및 JSON 내용을 로컬 파일로 보존했다. 브라우저 다운로드 완료 이벤트는 시간 초과됐으므로 파일 저장 UI 완료로 판정하지 않는다.
- 테스트 후 새 전용 Pod만 중지했다. RunPod의 **Not running / Total $0.00/hr**를 실제 확인했다. 다른 Pod는 변경하지 않았다.

실행 화면 안내도 데스크톱·390px 모바일에서 네 단계 모두 진행했다. 모바일 네 안내 카드가 화면 안에 표시되고 가로 넘침이 없으며, 종료 후 사용 안내 버튼으로 초점이 돌아왔다.

이 과정에서 추가 수정한 사항:

- 실행 화면 로딩 중 ‘저장한 워크플로우가 필요합니다’가 먼저 표시되던 문제를 로딩 상태로 분리했다. 회귀 검사 추가.
- 설정 패널도 작업 라이브러리와 같은 도구 설명 함수를 사용하도록 통일했다. 실제 저장된 설계에서 집계·완료 도구 설명 확인.
- 저장 안내에 남아 있던 ‘에이전트 생성’ 표현을 워크플로우 저장으로 수정했다.

## 남은 검증 한계

실제 Qwen은 이번 합성 표 처리 설계·수정에 사용했다. 계산 실행은 생성된 워크플로우의 결정적 도구 코드가 수행했으며, AI 작업 노드의 응답 품질 전체를 시험한 것은 아니다. 최초 모델 초안 실패는 숨기지 않고 보존했다.

브라우저 다운로드 완료, 기존 네이티브 이탈 확인창의 실제 취소 동작은 아직 별도 검증이 필요하다. 해당 상태 전환은 DOM 자동 검사로 확인했다. 모든 문서 형식의 분석 품질·사용자 고유 데이터 전체·모든 브라우저와 운영 환경의 동작을 보장하지 않는다.

코드는 로컬에 저장되어 있으며 커밋·푸시는 수행하지 않았다. 테스트 후 GPU는 중지했으므로 새 Qwen 생성 요청에는 서버 재시작·복원이 필요하다. 저장된 결과 조회는 로컬에서 가능하다.
