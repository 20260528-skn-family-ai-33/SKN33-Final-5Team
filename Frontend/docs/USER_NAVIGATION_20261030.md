# 사용자 메뉴와 모델 설정 분리 — 2026-10-30

## 사용자에게 보이는 구조

| 위치 | 메뉴 | 목적 |
| --- | --- | --- |
| 공통 작업 공간 | 워크플로우 | 저장한 업무 흐름 확인·새로 만들기 |
| 공통 작업 공간 | 실행 기록 | 이전 실행의 상태와 결과 확인 |
| 공통 작업 공간 | 작업 라이브러리 | 문서 읽기·집계·AI 분석 등 반복 사용할 작업 준비 |
| 워크플로우 내부 | 설계 | 업무 설명, 흐름 확인, 설정·저장 |
| 워크플로우 내부 | 실행 | 저장한 흐름에 요청·자료를 넣고 실행 |
| 작업 라이브러리 | 설계로 돌아가기 | 작성하던 흐름과 입력을 유지한 채 돌아가기 |

‘노드 만들기’는 ‘작업 라이브러리’로 바꿨다. 화면의 노드 이름·새 노드·노드 저장도 작업 이름·새 작업·작업 저장으로 통일했다. 내부 API의 node 식별자와 저장 형식은 유지한다.

## 사용자에게서 제거한 항목

- 공통 메뉴의 Qwen 연결 페이지와 헤더의 Qwen 상태 창
- 워크플로우 설정의 모델 이름·서버 응답 상태
- 작업 작성 양식의 모델 입력
- 도움말의 Qwen·LangGraph 구현 설명

모델 선택과 연결은 서버 설정으로 계속 처리한다. 기존 작업을 수정할 때 저장된 모델 값은 보존한다. 화면 시작 시 내부 프로필만 읽도록 connection?profile=1을 사용하고, 운영 점검용 기존 connection API는 유지한다. 예전 screen=models 링크는 워크플로우 목록으로 정리한다.

## 검증

- TypeScript 검사와 배포 빌드 통과.
- 전체 회귀 검사: 684개 통과, 실패·건너뜀 0개.
- DOM 검사에 모든 주요 사용자 메뉴의 Qwen·모델 필드 미노출, 이전 모델 페이지 링크 처리, 입력 보존, 브라우저 뒤로/앞으로 이동, 라이브러리 복귀를 포함했다.
- 실제 브라우저: 1280px 설계·작업 라이브러리·실행 화면에서 메뉴 확인, 390px에서 가로 넘침 없음과 설명/흐름/설정 패널 전환 후 입력 보존 확인.
- 실제 브라우저에서 미저장 입력의 이탈 확인창을 열자 제어가 멈춰, 확인창 취소 후 복원은 DOM 자동 검사로만 검증했다. 실제 브라우저 검증을 완료한 것으로 표기하지 않는다.
- 분리된 임시 데이터 폴더에서 표 읽기 → 집계 → 결과 저장을 실제 실행하여 A=30, B=40을 확인했다. 이번 검증에서 Qwen을 통한 새 흐름 생성은 실행하지 않았다.

검증 주소는 http://127.0.0.1:3150/ 이며, 브라우저 검증용 예제 데이터가 표시된다. 실제 사용자 데이터와 분리되어 있다. 변경은 로컬에 저장되어 있으며 이 작업으로 커밋·푸시하지 않았다.

## 화면 간 일관성 재검증

사용자 스크린샷에서 확인한 차이는 목록 화면의 문자 A 로고와 내부 화면의 연결 아이콘 로고, 화면별 헤더 구성 및 반응형 사이드바 폭이었다. 목록과 내부 화면이 서로 다른 컴포넌트와 CSS 규칙을 사용하고 있었다.

- WorkspaceHeader / WorkspaceBrandMark: 작업 공간 전체와 샘플 미리보기의 헤더·로고를 공통화. 소개 페이지의 구성·스크롤 동작은 유지하고 로고 마크만 같은 컴포넌트를 사용한다.
- WorkspaceSidebar: 목록·실행 기록·라이브러리·설계·실행에서 같은 전역 메뉴와 폭·간격을 사용한다.
- 새 워크플로우와 사용 안내는 전역 헤더 오른쪽에 고정한다. 목록으로/설계로 돌아가기/설계·실행 탭은 페이지 본문에 둔다.
- 이전 화면 전용 컨테이너 스타일을 정리하고 workspace-chrome.css에서 공통 영역을 관리한다. 상위 화면의 button font 규칙에 영향을 받지 않도록 메뉴 글꼴·줄 높이를 명시한다.
- 자료 로딩 중에는 ‘지원 기능 0종’·‘저장한 작업 0개’·빈 작성 양식을 표시하지 않는다. 로딩·실패·실제 빈 목록을 구분한다.
- 모바일 새 워크플로우 전환 시 입력칸 자동 포커스 때문에 페이지가 아래로 이동하는 문제를 수정했다. 포커스는 preventScroll을 사용하고 대화 갱신은 대화 영역 안에서만 스크롤한다.
- 1280×720 설계 화면에서 설명 입력 하단과 저장 버튼 하단이 화면 안에 들어오도록 편집 패널 높이를 조정했다.

### 실제 브라우저 측정

1280px에서 목록·기록·라이브러리·설계·실행의 공통 좌표가 일치했다.

| 항목 | 값 |
| --- | --- |
| 헤더 높이 | 68px |
| 로고 위치 / 크기 | x=24, y=17.5 / 32×32px |
| 사이드바 시작 / 폭 | y=68 / 208px |
| 전역 메뉴 시작 / 높이 | x=12, y=86 / 145px |
| 현재 선택 메뉴 | 화면당 1개 |

390px에서 목록·라이브러리·설계의 로고 위치는 x=16, y=19.5, 크기는 28×28px, 헤더 높이는 68px로 일치했다. 새 워크플로우 동작 후에도 헤더 y=0을 확인했다. 320·390·768·1280px에서 문서 전체 가로 넘침이 없었다. 1280×720에서 입력 영역 하단은 y=676.54, 저장 영역 하단은 y=688.54로 확인했다.

실제 브라우저에서 라이브러리 → 설계 → 실행 → 기록 → 목록 이동, 새 워크플로우, 도움말 열기·닫기를 확인했다. 브라우저 콘솔 오류는 관찰되지 않았다. 이 검증은 분리된 임시 예제 데이터로 수행했으며 실제 Qwen 새 흐름 생성이나 외부 서비스 실행을 새로 검증한 것은 아니다.
