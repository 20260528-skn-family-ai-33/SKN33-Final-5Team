# A4B · AI for Business

A4B는 반복되는 업무를 한국어로 설명하고, 그 처리 절차를 **다시 실행할 수 있는 워크플로우**로 저장하는 AI 업무 자동화 플랫폼입니다. 재고표에서 발주할 상품을 고르거나 고객 응대 초안을 검수할 때, 담당자는 어떤 자료를 보고 무엇을 기준으로 판단할지 정합니다. A4B는 그 기준에 맞춰 자료 읽기, 비교, 집계, 결과 저장 등의 작업을 연결합니다.

## 업무 예시 · 부족 재고 보고서

> “재고표에서 현재 수량이 발주 기준보다 적은 상품만 골라 CSV로 정리해 줘. 수량이 비어 있는 상품은 제외해 줘.”

이 요청에서 중요한 건 상품마다 **같은 행의 현재 수량과 발주 기준**을 비교하는 일입니다. 아래와 같은 재고표라면 보고서에는 키보드 한 품목만 남습니다.

| 상품 | 현재 수량 | 발주 기준 | 처리 결과 |
| --- | ---: | ---: | --- |
| 키보드 | 20 | 30 | 부족 재고에 포함 |
| 모니터 | 10 | 10 | 기준을 충족하므로 제외 |
| 마우스 | — | 5 | 수량이 비어 있어 제외 |

담당자는 화면에서 **재고표 읽기 → 부족 상품 선별 → CSV 저장** 순서와 처리 조건을 확인합니다. 이 흐름을 저장하면 다음 재고표에도 같은 기준을 적용할 수 있습니다. 관리할 표 파일을 연결해 매일 또는 매주 정해진 시각에 보고서를 만들 수도 있습니다.

## 활용할 수 있는 업무

| 업무 | A4B로 얻는 결과 |
| --- | --- |
| **매출 집계** | 거래 내역을 팀별로 묶어 매출 합계를 계산하고, 조건에 맞는 팀만 추려 보고서로 저장합니다. |
| **문서·영수증 정리** | 문서나 영수증 사진에서 품목명·금액처럼 지정한 항목을 읽어 행 단위로 정리하고 CSV로 내보냅니다. |
| **문서 기반 답변** | 반품 기한처럼 정책 문서에서 확인할 내용을 찾고, 답변 초안과 그 근거가 된 원문을 함께 보여줍니다. |
| **고객 응대 검수** | 고객 문의, 답변 초안, 정책을 대조해 빠진 요청이나 근거가 부족한 표현을 표시합니다. 담당자는 근거와 수정안을 읽고 최종 답변을 승인하거나 거절합니다. |

## 작업 공간

- **워크플로우**에서 업무를 설명하고 자료를 연결합니다. 필요한 조건이 빠지면 A4B가 질문합니다. 담당자는 캔버스에서 처리 순서를 확인하고, 대화로 조건을 고쳐 새 버전으로 저장할 수 있습니다.
- **작업 라이브러리**에는 여러 업무에 공통으로 쓰는 작업을 보관합니다. 예를 들어 ‘팀별 금액 합계’를 한 번 정의해 두고 다른 보고서를 설계할 때 다시 사용할 수 있습니다.
- **실행 기록**에는 실행에 사용한 워크플로우 버전과 단계별 처리 결과가 남습니다. 보고서를 다시 내려받거나 어느 단계에서 사람의 응답을 기다리고 있는지 확인할 수 있습니다.
- **예약 실행**에서는 예약이 있는 워크플로우의 반복 일정, 활성·중지 상태, 다음 실행 시각을 모아 봅니다. 매시간·매일·매주·매월을 지원하며, 예약 관리를 누르면 파일이나 서비스 연결을 확인하고 예약을 켜거나 중지할 수 있습니다. 파일이 필요한 작업에만 파일을 요구하며, 비파일 작업은 저장한 설정과 연결된 서비스로 실행합니다.

## 예약 주기와 자료함 연결

업무를 설명할 때 “매시간 15분에”, “매월 1일 오전 9시에”, “매월 말일 오후 6시에”처럼 주기를 함께 지정합니다. 매월 29~31일처럼 해당 날짜가 없는 달은 건너뛰며, 말일 예약은 그달의 마지막 날에 실행합니다. 시간대와 다음 실행 시각은 예약 실행 화면에서 확인합니다.

표·문서를 읽는 예약은 **예약 관리 → 자료함에서 읽기**에서 대상 작업과 개인·팀 공간, 폴더를 고르고 다음 방식을 저장합니다.

| 읽기 방식 | 실행할 파일 |
| --- | --- |
| 고정 파일 | 선택한 파일 ID를 계속 참조합니다. 파일 이름이나 폴더가 바뀌어도 같은 공간의 파일을 읽으며, 같은 이름의 새 업로드로 바뀌지 않습니다. |
| 최신 파일 | 선택한 폴더에 가장 최근 등록된 파일 하나를 실행 시점에 선택합니다. 하위 폴더는 포함하지 않습니다. |
| 새 파일만 처리 | 선택한 폴더에서 해당 연결 설정으로 성공 처리하지 않은 파일 버전을 찾아 파일별 실행을 대기열에 넣습니다. 실패한 파일은 완료 처리하지 않습니다. |

팀 자료는 매번 현재 팀 권한과 원본을 확인해서 읽습니다. 개인 자료함에 영구 사본을 추가하지 않으며, 실행 기록과 재시도에는 당시 선택한 파일·버전·내용을 고정한 스냅샷을 사용합니다. 실행 근거의 원본 보기에도 현재 접근 권한을 확인합니다.

연결 설정을 실제로 변경하면 예약을 중지하고 아직 시작하지 않은 이전 설정의 자료함 대기 작업을 취소합니다. 진행 중인 실행은 기존 스냅샷으로 마칩니다. 공간·폴더·읽기 방식·대상 작업을 바꾸면 새로운 처리 기준이 되어 이전 성공 파일도 다시 대상이 될 수 있습니다. 같은 설정을 다시 저장하는 것만으로 처리 기록을 초기화하지 않습니다.

운영 PostgreSQL에는 [007 자료함 예약 마이그레이션](infrastructure/db/migrations/007_schedule_library_sources.sql)을 명시적으로 적용해야 합니다. 애플리케이션은 운영 스키마를 자동 변경하지 않습니다.

## Gmail 메일 요약 예약

서비스 연결에서 Gmail 읽기 권한을 연결하고, 새 워크플로우에 “매일 오전 9시에 전날 온 Gmail 메일을 요약해줘”라고 설명합니다. 초안을 확인해 저장한 뒤 **예약 실행 → 예약 관리 → 예약 켜기**로 활성화합니다. 실행 결과는 실행 기록에서 확인합니다. 서버가 실행 중이어야 예약이 처리됩니다.

전날 범위는 예약된 시각의 한국 시간 기준으로 매번 계산하며 재시도에도 같은 날짜를 사용합니다. 기본 조회 한도는 100건이며, “최대 250건”처럼 요청해 1~500건으로 정할 수 있습니다. 메일은 다음 페이지까지 조회하고 여러 묶음으로 요약합니다. 조회 한도에 도달하거나 본문 일부를 생략한 경우 결과에 표시합니다. Gmail 날짜 검색은 [공식 가이드](https://developers.google.com/workspace/gmail/api/guides/filtering)에 따라 시간대를 반영한 Unix 초 값을 사용합니다.

## 프로젝트 구성

화면은 **React와 TypeScript**, API는 **Node.js**, 업무 설계와 실행은 **Python**으로 구성했습니다. 설계 단계에서는 언어 모델과 등록된 도구 목록을 바탕으로 처리 순서를 만들고, 도구에 필요한 입력과 단계 간 연결을 검사합니다. **LangGraph**는 대화와 실행 상태를 관리하고, 실행기는 저장된 버전에 따라 필터·집계·파일 생성 등의 작업을 수행합니다.

문서 분석기는 표와 본문을 읽고, 사진이나 스캔 자료의 글자는 OCR로 추출합니다. 설계 중에는 **SVM56** 모델을 사용해 요청에 맞는 도구 후보를 추천받을 수 있습니다.

에이전트 빌더는 로컬에서 SQLite를, 운영 환경에서 PostgreSQL을 사용합니다. 설정과 기존 데이터 이전 절차는 [업무 데이터 저장소](docs/business-data-storage.md)에서 확인할 수 있습니다.
