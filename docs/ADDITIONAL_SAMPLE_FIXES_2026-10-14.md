# 추가 평가 사례에서 확인한 생성·실행 계약 보완

현재 main 기반 `c9f8429`의 기존 AgentDraft → 검증 → 사용자 확인 → 저장 → 등록 런타임 실행 구조를 유지한다. 모델이나 별도 코드 생성 에이전트를 추가하지 않는다.

- 생성 의도를 구조화하여 텍스트 역할, 명시 항목 추출, 표 처리, 복합 업무를 구분한다. 실행 때 받을 날짜·원문·메모는 생성 필수 질문으로 차단하지 않는다. 실제 외부 전송/등록 등 미지원 동작과 자동 예약의 필수 조건은 계속 차단·확인한다.
- 단순 텍스트 역할은 `agent_node → export_result`, 명시 항목 추출은 `read_document → extract_information → export_result`, 필터·정렬·중복 조건이 없음을 별도로 확인한 순수 표 집계는 `read_table → aggregate_table → write_result`의 기본 계약을 사용한다. 기존 초안 수정, 필수 재사용 노드, 복합 흐름은 기존 설계 경로를 사용한다.
- 사용자가 나열한 명시 항목은 그대로 사용하고 추출할 값과 근거 메타데이터를 구분하여 근거 문장을 새 데이터 항목으로 만들지 않는다. null과 정확한 원문 인용 검증을 유지한다.
- 정상적인 천 단위 쉼표 숫자는 합계할 수 있다. 잘못된 쉼표 구분, 빈 값, 논리값, NaN/Infinity는 계속 실패한다.
- JSON 구조화 응답 오류는 한 번 재생성하며 일부 JSON만 잘라 수용하지 않는다. 텍스트 JSON 내보내기도 JSON 문서 파싱 후 저장한다.
- 중복 첫/마지막 행은 원본 순서로 처리한다. 미정 중복 정책을 임의로 첫 행으로 정하지 않는다. 자동 예약에서 미정 시각·시간대·요일을 확인한다.

Python 전체 테스트 211개 통과. 수정 효과는 추가 100샘플에서 고정된 무작위 50문항과 기존 30문항으로 검증한다. 개발 과정의 중간 실패와 결과도 보존한다. 같은 진단 문항을 재사용한 개발 검증이며 독립적인 미사용 평가 성능을 의미하지 않는다. 제공 정답은 사람 검수 전이며 표현 동등성·일부 중복 의미 등 채점 제한이 있다.
