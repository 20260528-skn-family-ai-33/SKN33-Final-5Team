# 현재 Git 기반 신뢰성 수정

기준 main: ee2715876a2804a96ae794d801e620d7aa03f8d0.

기존 초안 설계 → 검증 → 사용자 확인 → 저장 → 등록된 런타임 실행 구조를 유지합니다.

- 설계 전 업무 계약 확인으로 미정 기준·예약 시간대·추출 항목·중복 정책을 질문합니다. 지원 불가 요청은 Workflow 없이 정상 안내합니다. 이미 정한 조건이나 구현 설정을 다시 묻지 않도록 합니다.
- 미완성 초안의 질문 대기와 ready 저장 계약을 구분합니다. 구조 오류가 있는 ready 초안은 저장하지 않습니다.
- 실제 선택한 node_ref/tool과 읽기/처리 노드 binding 규격을 생성 스키마에 반영합니다. 참조 적용 오류는 기존 수정 경로로 전달합니다.
- agent_node는 inspect_inputs를 실제 호출한 뒤 응답하게 합니다. 답변/검수의 근거 조회도 강제합니다.
- 요청한 파일 저장이 단순 마지막 결과에서 빠진 경우 등록된 출력 노드를 연결합니다. 검수 후보·분기·재사용 workflow를 자동 최종 내보내기로 바꾸지 않습니다.
- export_result의 answer 포트를 실제 실행 계약에 맞춰 처리합니다. records+answer 확인 정보 JSON 동작도 유지합니다.
- 그룹 결측 정책과 집계 sum 출력 열 참조를 실제 처리에 반영합니다.
- 검수 인용은 실제 구절을 검사하고 실패한 인용만 한 번 수정합니다. 승인 우회는 허용하지 않습니다.

출처: 사용자가 제공한 A4B 평가실험 검토용 및 Git 데모100샘플 Promptfoo 평가 묶음의 실패 분석·평가 원칙. 기존 개발판에서 확인한 표/근거/검수 수정도 현재main 코드에 맞게 선별 적용했습니다. 코드 생성 에이전트·실행 Python 생성·학습 경로는 가져오지 않았습니다.

새 테스트는 test_current_git_reliability.py, 실제 모델 평가는 evaluation/reliability를 사용합니다. 실제 평가 수치와 제한은 배포 ZIP의 검증결과 문서에 있습니다.

기존 연결에서 시작점이 하나로 명확한데 entry 이름만 잘못된 경우 그 시작점을 사용합니다. 후보가 여러 개인 경우나 유효한 시작점을 임의로 바꾸는 경우는 해당하지 않습니다.
