# 팀원 Demo 선별 통합 — 2026-10-13

원본: 프로젝트 루트의 `Demo/`. 대상: `finalproject/`. 원본 코드와 운영 데이터는 변경하지 않았습니다. 사용자 지시에 따라 파일 통합과 테스트만 수행하며 Git 작업은 사용자가 별도로 처리합니다.

## 채택한 개선

| 개선 | 실제 동작 |
|---|---|
| 노드 라이브러리 | 역할 지침·참고 텍스트·처리 설정을 저장하고, 새 버전으로 수정. 기본 노드 5개 준비 |
| 고정 버전으로 설계 | 선택한 노드 최대 10개를 반드시 연결. 서버가 저장한 설정을 다시 적용해 모델의 설정 변조 방지 |
| 범용 에이전트 노드 | 실제 요청·앞 단계·자료를 inspect_inputs로 조회한 뒤 답변 작성. 임의 코드·외부 발송 없음 |
| 3화면 구성 | 노드 만들기, 워크플로우 설계, 서비스 실행을 구분. 기존 예약·기록·승인 기능 유지 |
| 캔버스·설정 확인 | 확대·축소·화면 맞춤과 노드 입력·출력·지침·버전 조회 |
| 좁은 화면 대응 | 고정 1360px 최소 폭을 제거하고 작업 패널을 화면 폭에 따라 재배치 |

같은 노드를 v2로 수정해도 기존 워크플로우는 v1 스냅샷을 사용합니다. 설계에서 이미 고른 v1도 체크와 버전 표시를 유지하며, v2 저장 후 최신 목록에 가려지지 않습니다. 새 역할 자동 제안은 초안에만 존재하며, 워크플로우 확인·저장 시 함께 게시됩니다. 저장 실패 시 역할과 워크플로우를 함께 롤백합니다.

## 기존 검수와 연결

Demo의 별도 승인 중단 엔진은 통합하지 않았습니다. A4B의 성공 실행 후 검수·수정·승인, `candidate_reply/candidate_revision`, 중복 제거, 중첩 재사용의 승인 전 내보내기 차단을 유지합니다.

`agent_node`의 reviews 입력에 검수 보고서 1건을 연결하면 최종 수정문을 기존 승인 후보로 기록합니다. 다건을 하나의 답변에 배정하는 연결은 모델 호출 전에 거부합니다. 원래 검수 보고서와 운영자의 최종 승인 문장은 각각 보존합니다. 검수 보고서 필터·집계·저장과 예약·체크포인트 재개도 기존 실행기를 사용합니다.

## 실제 범위와 제한

- 등록 도구는 16종, 한 흐름은 최대 15개 노드입니다.
- 캔버스는 조회·선택·확대용입니다. 직접 연결 편집·노드 이동은 지원하지 않습니다.
- 노드 라이브러리 화면의 필터는 한 개 숫자 비교 조건을 지원합니다. 집계는 건수·합계와 그룹 열을 지원합니다.
- 에이전트 입력 컨텍스트는 45,000자, 출력은 12,000자 이내입니다. 큰 문서는 앞 단계에서 검색해야 합니다.
- 모델을 비우면 현재 워크플로우 모델을 사용합니다. 지정 모델이 실행되지 않으면 오류를 표시하고 임의로 교체하지 않습니다.
- 모델 응답만으로 실제 외부 조치나 문서의 정책 정확성을 보장하지 않습니다. 기존 검수와 사람 승인에 연결할 수 있습니다.

## 검증

자동 검사는 임시 SQLite·실제 노드 실행·모의 모델 응답을 사용합니다. 버전 고정, 동시 수정 충돌, 선택한 노드의 필수 연결, 저장 트랜잭션, 입력 조회, 검수 후보와 승인 CSV, 기존 예약·재시도·중첩 승인 등을 확인합니다. 실제 API 키·사용자 데이터는 테스트에 사용하지 않습니다.

최종 결과: Python 172개 통과, 서버·화면 520개 중 519개 통과·기존 1개 제외, 실패 0. TypeScript 검사와 빌드도 통과했습니다. 이전 검수 수정판의 회귀 검사는 모두 유지하고, 노드 라이브러리 관련 Python 26개와 서버·선택 버전 관련 5개를 추가했습니다. 기본 노드 ID를 API에서 직접 덮어쓰지 못하도록 검사하며, 기본 노드 복제는 새 ID로 저장합니다.

화면 검사는 별도 임시 데이터 폴더의 로컬 서버에서 처리 노드 저장과 선택, 이전 버전 표시, 설계·실행 화면 이동, 좁은 화면 배치를 확인합니다. 실행 안내는 README에 반영했습니다.
