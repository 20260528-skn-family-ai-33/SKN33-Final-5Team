# A4B 코드 통합 및 전처리 검증 — 2026-10-12

이번 변경은 기존 A4B의 대화 기반 생성·LangGraph 실행·예약·DB를 유지하면서 제공된 세 프로젝트의 유용한 구조를 보완한 것이다. 다운로드 폴더의 원본은 수정하지 않았다.

## 전처리와 DB

`integrations/workflow_preprocessing/`에 제공된 파일럿 원본을 보존했다. `python/agent_builder/preprocessing.py`는 그 normalize/validate 함수를 직접 사용하며 실제 백엔드 규격과의 연결을 담당한다.

`preprocessing_batches`: 배치 ID, 원본 경로, 규약 버전, 합성 자료 여부, 사람 검수 상태, 통계.

`preprocessing_examples`: 배치·사례 ID, 시나리오 그룹, train/validation/test 분할, 중복 검사용 해시, 원본 JSON, 정제 JSON, 정답 JSON, 변환된 설정, 호환 상태·오류. 배치 외래키와 배치별 사례·내용 유일성을 적용했다.

기존 `registered_tools`, `builder_assets`, `agent_versions`, `builder_sessions`, `agent_tests`, `builder_data_sources`, `builder_schedules`, `builder_schedule_jobs`는 유지한다. 합성 평가 사례를 사용자 자동화로 자동 저장하지 않는다. 실행 DB와 학습/평가 데이터의 목적을 분리하되 같은 SQLite 안에서 관리한다. 새 테이블 추가 방식이라 기존 설정과 실행 기록을 삭제하지 않는다.

실행:

```bash
.venv-agent/bin/python scripts/import-preprocessing.py
```

기본 DB는 `data/agent-builder.sqlite`. 다른 DB에는 `--directory /path/to/data`를 지정한다. 반복 가져오기는 같은 배치를 중복 삽입하지 않는다. 원본/분할 파일 불일치나 동일 시나리오의 분할 간 누출이 있으면 가져오기를 거부한다.

## 실제 결과

- 원본 32건 → 정제 30건, 완전 중복 2건 제거.
- 분할: train 18 / validation 6 / test 6. 시나리오 그룹 누출 0.
- 실행 규격 변환 가능 12건, 추가 질문 필요 6건, 현재 어댑터 미지원 12건.
- 변환 가능한 재고·매출·지출·빈 이메일 사례 12건을 격리된 임시 DB에서 실제 등록 노드와 LangGraph로 실행하고 보고서 파일 생성을 검증했다.
- 웹훅·외부 알림·대화형 문서 검색 파일럿은 현재 표 어댑터에 맞지 않으므로 unsupported로 보존한다. 제품의 문서 기능 부재를 뜻하는 것이 아니라 해당 파일럿과의 실행 매핑이 미완료라는 뜻이다.
- 파일럿에 명시되지 않은 결측·중복·출력 형식은 평가 변환용 정책(keep/keep/CSV)으로 별도 기록한다. 사용자 생성의 기본 요구로 해석하지 않는다.
- 그룹별 합계는 Decimal 누적 후 결과 숫자로 변환한다. 0.1+0.2=0.3, 빈값·논리값·NaN·Infinity·비숫자는 실패. 전체 빈 집계는 sum=0 또는 count=0이다.
- 시험 예약 취소는 queued 상태에서만 가능하며 실행 중 취소는 거부한다. 취소한 작업은 예약 실행기가 가져가지 않는다. 다른 자동화의 작업 취소도 거부한다.
- 노드가 잘못된 출력 형식을 반환하면 실행을 실패로 기록하고 후속 노드를 실행하지 않는다. 성공 단계 로그에는 처리 시간, 포트별 행/항목 수·열·문자 수, 기존 실행 인자·입출력 연결을 함께 표시한다.

## 검증과 한계

Python 생성·실행·예약·전처리 테스트 69건 통과. 서버 회귀 테스트 508건 중 507건 통과·기존 1건 제외, 실패 0. TypeScript 검사와 프런트/서버 빌드 통과. 실제 모델 생성 및 로컬 API 통합 결과는 `INTEGRATION_LIVE_CHECK.json`에 별도로 기록한다.

원본 30건은 모두 합성 자료이며 사람 검수 pending이다. 학습은 수행하지 않았다. 사례의 구조·변환·실행 통과는 모델 생성 정확도나 업무 생산성 개선의 증거가 아니다. 표본이 작으며 일부 테스트 분할 사례의 규격 호환성 검사는 모델 성능평가와 구분해야 한다.

아직 외부 알림·웹훅을 표 파일럿의 도구 ID만으로 실행하지 않는다. 운영 서버 배포·다중 사용자 권한은 이번 변경 범위가 아니다. 현재 로컬 서버가 켜져 있어야 예약이 실행된다.

실제 모델 API 생성까지 재검증한 결과: ‘팀별 금액 합계 정기 집계 및 보고서 저장’ 자동화를 대화 요청으로 생성·저장했다. A팀 0.3, B팀 200의 합계 CSV를 서버에 실제 저장하고 다운로드 응답을 확인했다. 시험 예약 등록→취소도 실제 API에서 통과했다. 정규 예약은 중지 상태로 유지했다. 첫 생성에서 검토 모델이 합계 노드의 숫자 검증 기능을 알지 못해 불필요한 검사를 요구했고, 도구 설명·검토 프롬프트에 실제 실행 규칙을 반영한 후 다시 통과했다. 이 한 건의 성공을 일반적인 생성 정확도로 확대 해석하지 않는다.

브라우저에서도 합계 자동화의 결과·4개 노드 연결·노드별 입출력과 시간을 확인했다. 시험 예약 등록→취소 버튼 흐름을 수행하여 ‘시험 예약을 취소했습니다.’ 상태를 확인했다. 별도의 15초 시험 예약은 실제 성공 결과를 생성했다. 화면 기록: `integrated-demo-2026-10-12.png`.
