# 노드 연결 구조 수정 — 2026-10-13

기존 v2.1의 예약·전처리·검수·승인·복구 기능을 유지하며 노드 연결 구조만 확장했다.

## 실제 코드 연결

registry의 각 노드 module_path가 `agent_builder.executors.<id>:execute`를 가리킨다. 공통 execute_node는 등록된 모듈만 불러오는 디스패처다. 실행 함수는 node.settings와 bindings로 전달받은 값을 사용하며 이전·다음 노드 ID를 상수로 알고 있지 않다. LangGraph가 저장한 edges와 조건 판단으로 실행 순서를 정한다. 업무별 새 소스 코드를 생성하는 방식은 아니다.

## 인스턴스별 설정

filter_sort의 실행 계획은 settings.execution_plan에 저장한다. 동일한 노드를 두 번 배치해도 조건이 다를 수 있다. write_result는 자신의 format을 사용한다. 이전 데이터의 글로벌 execution_plan은 개별 설정이 없는 경우에만 호환 기본값이다. 생성 모델도 필터가 여러 개인 경우 각 노드의 계획을 독립적으로 구조화한다. 화면과 실행 로그에 실제 노드별 인자를 표시한다.

입출력 타입, 선후 관계, 모든 분기에서 출력이 존재하는지, 집계 후 바뀐 열 이름을 검사한다. “반드시 read_table 다음이어야 한다”는 식의 전역 도구 조합 제한을 실제 포트 검증으로 대체했다.

## 검수 후 연결

reply_review의 terminal 제한을 제거했다. reviews를 condition으로 전달하고 all_pass/any_revision으로 분기할 수 있다. compose_answer는 검수 의견을 데이터로 받아 수정안을 작성한다. review_summary는 검수 결과를 후보 보고서 표로 변환하여 write_result에 전달한다. approval_state=pending을 기록하고 파일도 검수_보고서로 표시한다. 최종 응대 승인·CSV는 기존 사람 승인 경로를 유지한다.

## 저장한 흐름 재사용

saved_workflow의 agent_id·agent_version·output_node·output_port가 대상을 정한다. 저장 시 대상과 하위 의존성의 스냅샷을 workflow_dependencies에 보관한다. 출력 노드가 모든 종료 경로에서 실행되는지 검증하며 없을 수 있는 출력 선택은 거부한다. 같은 모델·계정인지 확인하고 자기 자신·재귀 호출을 막는다.

실행은 LangGraph 체크포인트를 상속하는 하위 그래프다. 앞 table/documents를 읽기 노드에 입력으로 전달하고, 저장 흐름의 선택한 출력을 부모 노드의 출력으로 반환한다. source의 최신 버전으로 임의 변경하지 않는다. 대상의 예약은 실행하지 않는다. 대기·재개는 부모 실행에 연결되며 내부 단계·대상 버전은 로그에 표시한다. 검수 출력 ID는 부모 인스턴스의 ID로 구분해 서로 다른 재사용 노드의 승인이 섞이지 않게 했다. 단순 표 하위 그래프는 모델·키 조회를 요청하지 않는다.
