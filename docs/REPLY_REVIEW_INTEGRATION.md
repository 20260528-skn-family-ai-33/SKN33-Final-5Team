작업은 2026-10-12에 시작했고 마지막 검증은 2026-10-13 한국 시간에 진행했습니다. 팀장 A4B 폴더를 수정했으며 별도 검수 앱 전체를 복사하지 않았습니다. 통합 전 소스 백업은 작업 중 로컬 임시 보관함에 보존했습니다.

- OpenAI 암호화 계정 저장소와 선택한 모델
- 자료 업로드·CSV/XLSX/JSON 파싱, 문서 읽기·검색, 원본 파일 보관

- 기존 관리 데이터 소스 버전, 일일/주간 예약, 15초 시험 예약·취소·작업 큐

## 데이터와 승인 규칙

`reply_review`는 `documents`, `table` 또는 앞 노드의 `text`를 받을 수 있습니다. 단일 검수는 실행 화면의 고객 문의·초안을 직접 받고, 표 검수는 `fields=[문의 열, 초안 열]`을 사용합니다. 정책 연결이 없으면 정책 없음도 실제 조회 결과로 반환합니다. 문서를 읽었다는 사실만으로 답변 가능하다고 판단하지 않습니다.

원문·정책·초안 조회 도구가 **실제로 성공하고, 조회 결과를 받은 뒤 보고서 도구를 호출했는지** 확인합니다. 정책·고객 인용과 문제 초안 구절을 원문과 대조하고 판정·지적의 모순을 거부합니다. 모델 오류나 부정확한 보고서를 고정 응답으로 바꾸지 않습니다.

검수는 마지막 노드입니다. 보고서와 원래 초안은 실행 기록에 남으며 승인된 응대와 구분됩니다. 최종 응대가 승인 전에 자동 저장되는 것을 막기 위해 검수 흐름에 `write_result`/`export_result`를 연결하지 않습니다. `compose_answer`가 바로 다음 검수 노드에 자신의 `text`를 전달하는 경우만 기존 내부 검토를 생략합니다. 다른 기존 답변 흐름은 내부 검토를 유지합니다.

AI 실행 성공 상태와 운영자 결정 상태는 별도입니다. 실행 성공 후 `approval_status=pending`이 되고, 각 검수 항목은 승인·거절될 때까지 대기합니다. 정책·고객 자료·원래 초안·보고서는 바뀌지 않습니다. 사람이 편집한 문장과 결정 시각은 별도 테이블 `reply_review_decisions`에 보존됩니다. `(run_id,review_id)` 유일 제약과 SQLite 트랜잭션으로 반복 승인과 동시 요청을 보호합니다. 같은 결정을 반복하면 기존 결과를 반환하며, 이미 결정된 내용을 바꾸려는 요청은 오류로 처리합니다.

예약은 검수 보고서 생성까지만 실행하고, 운영자는 나중에 기록 화면에서 결정합니다. 승인 CSV에는 승인된 편집 문장만 들어가며 대기·거절된 응대는 제외됩니다. 스프레드시트 수식으로 해석될 수 있는 셀은 CSV에서 이스케이프합니다. 외부 발송은 수행하지 않습니다.

## 인터페이스

- 기존 `POST /api/agent-builder/test`에 선택 `replyDraft` 추가
- 기존 `GET /api/agent-builder/run?id=...`, `agent?id=...`의 실행에 `reviews`와 결정 상태 포함
- `POST /api/agent-builder/review_decision`: `id`, `reviewId`, `decision=approve|reject`, `editedReply`
- `GET /api/agent-builder/review_report?id=...`: 원래 보고서와 현재 결정의 JSON
- `GET /api/agent-builder/approved_replies?id=에이전트ID`: 승인 결과 CSV
- `POST /api/agent-builder/retry_run`: `id`, 실패한 같은 실행을 기존 체크포인트로 재시도

## 검증과 범위

자동 테스트는 명시적으로 모의 모델을 사용하며 실제 SQLite·LangGraph·자료 읽기·예약·HTTP·승인·다운로드 경로를 검증합니다. 실제 호출 결과는 `REPLY_REVIEW_LIVE_CHECK.json`에 별도로 기록합니다.

- Python: 기존 69개와 통합 검수 19개, 총 **88개 통과**.
- Node.js 서버: **509개 중 508개 통과, 기존 제외 항목 1개**, 실패 0개. Python과 합계 596개 통과.
- 형식 검사와 프런트·서버 빌드 통과.
- HTTP 통합: 수정 승인, 반복 승인, 반대 결정 차단, 잘못된 ID·빈 승인 차단, 기록 복원, 승인 CSV·보고서 다운로드 통과.
- 실제 OpenAI `gpt-4.1-mini`: 자연어 검수 흐름 생성, 잘못된 초안 `revise`, 정책에 맞는 초안 `pass`, 편집 승인·중복 승인·거절·승인 결과만 다운로드 통과.
- 실제 화면: 관련 없는 환불 정책으로 배송 보상 초안을 검수해 근거 없는 확정 표현을 지적, 운영자 수정·승인 확인.
- 기존 15초 시험 예약: 실제 모델 검수 `revise`, 자료 버전·정책 스냅샷과 보고서 보존, 실행 후 승인 확인. 정규 예약은 켜지 않았습니다.
- 화면 새로고침 후 수정 승인 문장과 결정 이력 복원 확인.
- 실패 단계 재시도와 설정 버전 변경 후 기존 실행 스냅샷 유지 확인.

실제 생성 검증 중 일시적인 요청 실패와 잘못된 연결 제안이 관측됐습니다. 실패는 차단됐으며 검수의 외부 입력과 표 입력을 구분하는 도구·설계 안내를 보완했습니다. AI 생성이 잘못된 연결을 제안하면 검증 오류를 표시하므로 사용자가 생성 대화에서 수정해야 할 수 있습니다. 모델의 의미 판단 자체를 완벽하게 보증하지 않으며 최종 문장은 운영자가 확인합니다.

지원 한도: 한 실행 최대 10행, 문의 8,000자, 초안 12,000자, 정책 범위 12,000자. 큰 범위는 기존 검색·필터로 선택합니다. 재시도는 완료된 앞 노드를 재사용하지만 실패한 검수 노드 안에서 이미 호출된 행은 다시 호출할 수 있습니다. 자료에서 선택된 구간만 검수하므로 정책 전체가 검토됐다고 표시하지 않습니다.
