# 검수·재사용 코드 리뷰 수정 — 2026-10-13

수정 위치는 Git이 연결된 `finalproject`입니다. 기존 실행 방법·자료·예약·모델 연결 방식을 유지했습니다.

## 1. 재사용 흐름의 승인 우회 방지

`saved_workflow`가 `text` 등 선택한 포트만 반환하면서 하위 검수 기록을 잃던 문제를 수정했습니다. 선택한 포트 외에 `_reviews`를 실행 기록에 보존하고, 재사용 인스턴스별 `노드ID:순번`으로 승인 항목을 구분합니다. 기존 선택 `reviews` 포트의 순번과 원본 `source_review_id`를 유지합니다.

저장 시 고정한 하위 의존성을 재귀 검사해 검수와 `export_result`가 함께 있는 흐름을 거부합니다. 실행 전·내보내기·최종 파일 보관 단계에도 검사를 적용하므로 수정 전 저장된 설정이나 오래된 체크포인트의 재시도로 승인 규칙을 우회할 수 없습니다. 사람 승인 CSV는 실제 승인 결정만 사용합니다.

`review_summary → write_result`는 승인 대기 상태의 진단 보고서이므로 계속 저장할 수 있습니다. 필터·정렬·집계·재사용도 진단표의 출처를 유지하고 결과 파일에는 `review_report=true` 표시를 붙입니다. 표시가 없던 이전 직접 저장 결과도 실제 작성 노드의 연결 입력과 진단 파일명을 확인해 허용합니다. 과거 재사용 체크포인트에 하위 검수 정보가 전혀 없는 경우에는 자동 내보내기를 차단하므로 최신 버전으로 새 실행해야 합니다.

## 2. 최신 수정문을 승인 대상으로 연결

검수 뒤 `compose_answer`가 작성한 문장은 `_review_updates`에 `candidate_reply`, 근거, 작성 노드와 후보 버전으로 기록합니다. 원래 `report`의 판정·수정 제안은 변경하지 않습니다.

승인 화면과 보고서 표는 최신 후보를 사용합니다. 같은 실행을 재개해 후보 버전이 바뀌면 승인 입력란도 갱신합니다. 운영자가 승인하면 편집한 실제 문장만 결정 기록과 CSV에 저장합니다.

하나의 작성 결과를 여러 고객에게 잘못 배정하지 않도록 답변 작성의 검수 입력은 보고서 1건만 지원합니다. 다건은 모델 호출 전에 오류로 처리하고, 승인 가능한 12,000자를 넘긴 수정문도 오류로 처리합니다.

## 3. 검수 보고서 중복 제거

`review_state.collect_reviews`가 직접 검수, 재사용 검수, 수정 후보를 같은 기준으로 수집합니다. 보고서 ID별 한 항목을 유지하고 높은 후보 버전을 선택하므로, 조건·완료 노드가 이전 보고서를 다시 전달해도 최신 수정문을 덮어쓰지 않습니다.

화면·JSON 보고서·사람 결정·승인 CSV 모두 이 기준을 사용합니다. 기존 실행에 후보 메타데이터가 없으면 기존 검수 제안을 그대로 사용합니다.

## 4. 긴 문서 검색 복구

문서 합계가 45,000자를 넘을 때 호출하는 `execute_node`를 가져오도록 수정했습니다. 등록된 검색 실행 코드를 사용하고, 관련 구간이 없으면 근거가 없다는 안내를 반환합니다. 시연용 응답으로 대체하지 않습니다.

## 검증 범위

- 긴 문서의 실제 검색 경로·인용·관련 문서 없음.
- 검수 후 수정, 연속 수정, 원래 보고서 보존, 승인·거절·반복 승인과 CSV.
- 조건 전달 후 보고서 2건 유지, 뒤늦은 이전 결과가 최신 후보를 덮어쓰지 않음.
- 재사용의 text/reviews/artifact 선택, 같은 흐름 두 번 호출, 중첩 재사용·승인 API.
- 승인 전 내보내기 저장 거부, 이전 저장 설정 재시도 차단, 진단 보고서 저장 유지.
- SQLite·실행 기록·HTTP 서버 재시작 후 복원, 기존 예약·복구 테스트.

자동 테스트는 격리된 임시 데이터와 모의 모델 응답을 사용합니다. 실제 AI 품질이나 API 연결을 새로 검증한 결과는 아닙니다. 운영 데이터와 API 키는 변경하지 않았습니다.
