# P1 지원 판단 유지 수정·검증 — 2026-10-27

## 결론
이전 ZIP에서 4/4 재현한 manual_review/clarify → 생성 → ready → 일반 확인 → saved 우회를 수정했다. 이번 핵심은 분류 문구가 아니라, 미해결 상태를 그래프·재개·최종 저장까지 강제하는 것이다.

## 수정된 동작
| 판정/상황 | 수정 후 |
|---|---|
| clarify | 질문·24자리 hex 질문ID 전달, 답변 대기. 생성·저장 없음 |
| manual_review | validation_failed로 중단, 검토/요청 보완 후 재판정 필요 |
| 모르겠어/안내 선택 | 같은 질문·기존 조건 유지, 값 임의 확정 없음 |
| 반복 모르겠어/나중에 결정 | 보류 표시와 질문 대기 유지, 나중 답변 후 재판정 |
| existing_tools | 미해결 항목 없음＋현재 입력 hash 일치 시 조건/생성 단계로 진행 |
| 일반 confirm | 미해결·오래된 판정이면 거부. 생성된 정상 초안만으로 해제 불가 |
| 요청·자료·상태·카탈로그 변경 | 과거 판정으로 생성/저장 불가, 재판정 필요 |
| 생성 실패 후 같은 요청 재시도 | 유효한 기존 판정으로 재시도, 불필요한 중복 판정 없음 |
| 생성 실패 후 변경 요청 | 지원 판단부터 다시 수행 |
| 이전 ready 체크포인트 | 새 유효성 hash가 없거나 미해결이면 확인 차단. 새 설명→재판정→새 확인 필요 |
| 기존 enforce 세션 재연결 | 기본 off/shadow로 자동 약화되지 않음 |

## 구현 위치
- capability_gate.py: 사용자 발언·현재 자원·입력 상태·16개 등록 도구·앱 지원 기능 hash와 공통 차단 규칙.
- nodes/capability_check.py: clarify/manual_review 분리, 질문ID/답변 기록, 보류 처리, 입력 장애 우선.
- graph.py: 답변/수정 재판정, generation_gate와 생성/템플릿 함수 내부 검사. 체크포인트가 생성 노드로 직접 재개돼도 차단.
- nodes/supervisor.py: 앞선 미해결 판정을 후속 ready가 덮지 못하도록 검사.
- nodes/await_input.py: 잘못된 확인/질문ID 후 대기 유지와 정상 답변 복구.
- nodes/save.py 및 storage.py: 공통 강제 판정·확인 규칙 적용. 저장 노드는 기존 초안 구조 검증도 재수행.
- worker.py: 일반 확인 검사, 변경된 실패 재시도의 재판정, 오래된 ready 응답을 검토 필요로 표시.
- nodes/condition_check.py, nodes/verification.py, models.py: 이전 강제 상태를 재연결 기본값 때문에 약화하지 않도록 required 상태 보존.
- API 질문ID 형식(24자리 hex)에 맞춤. 프론트 표시·전달에 필요한 pending_questions 포맷 유지.

Node API 검사는 요청 함수와 자식 프로세스를 실제 사용했지만 HTTP 서버/브라우저를 띄운 사용자 클릭 검사는 아니다. 모델/생성 초안은 통제해 상태 전환을 분리 검증했으며 새로운 실제 모델 호출은 0회다. 이전 Qwen 정확도 실험을 이번 수정의 새 모델 점수로 사용하지 않는다.

압축 해제한 복사본의 재검사 및 ZIP 내부 해시 결과는 PACKAGE_VALIDATION.json과 validation/에 별도로 포함한다. 신규 의존성 설치는 검증하지 않았다.

## 검사에서 추가로 발견·보완한 부분
1. 실패한 생성 노드에 머문 뒤 새 요청이 들어오면 이전 판정으로 곧바로 생성할 여지: worker 재진입과 생성 함수 내부 검사로 차단.
2. 잘못된 confirm 이후 interrupt 재개가 꼬이면 정상 답변도 막힐 여지: 예외만 발생시키지 않고 새 interrupt로 계속 대기해 회복 확인.
3. 질문ID 접두사를 붙이면 기존 Node API의 24자리 hex 검사와 불일치: 기존 규격에 맞추고 실제 API 경로에서 확인.
4. 기존 enforce 상태가 재연결 off/shadow에 의해 약화될 여지: capability 및 조건/별도 verifier의 강제 정책 유지.

## 범위와 남은 연결
- 현재 신규 세션 기본 모드는 기존 off 유지. enforce로 선택한 세션과 이전 enforce 체크포인트에 강제 규칙이 적용됨. 해제가 필요하면 새 세션/별도 명시적 마이그레이션이 필요.
- 현재 등록 도구는 16개다. 62개 통합 도구 연결은 별도 작업이며 이번 수정에 포함하지 않음.
- 실제 PDF 파서·이전 파서 원시 실패·RDS·팀 UI·임시 도구 원래 runtime 삽입·실운영 예약 검증은 완료로 표시하지 않음.
- 이미 저장된 과거 에이전트는 자동 삭제·소급 재검증하지 않았으므로 실제 사용 전 별도 확인 필요.
- 이 검사는 상태 전환 불변 조건을 확인한다. 사용자 의도 전체의 정확성, 임의 문구의 모델 판단, 모든 결함 부재를 보장하는 것은 아님.
- 커밋·push·배포·실서비스 자료 변경·새 모델 다운로드/학습·외부 유료 API 호출 없음.
