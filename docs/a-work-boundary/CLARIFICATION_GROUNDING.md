# 조건 근거·답변 보존·Ollama 출력 규격 보완

## 적용 범위
- 모호한 비교 방식과 파일 형식을 사용자 확정값으로 추측하지 않음.
- 명시된 초과/이상/미만/이하, 특정 열의 빈 값 정책, 중복 첫/마지막 행 정책, 정렬 금지를 장부와 초안 설정에 대조.
- 요청·자료·도구·조회 상태가 그대로이고 미해결 조건에 대한 전체 답변이 모르겠어/보류인 경우에만 기존 지원 판정을 재사용. 조건은 계속 미정/보류이며 생성·저장 허가로 취급하지 않음. 자료가 바뀌면 재판정.
- 자료가 이미 연결됐으면 추가 업로드 대신 연결 자료 확인 안내.
- Ollama 송신용 스키마 사본에서 ID 정규식의 지원되지 않는 escape와 maxLength=2000의 grammar 확장 문제를 우회. 원본 Pydantic 길이 검사는 유지. 노드 ID 송신 규칙은 영문 시작, 이후 영문·숫자·밑줄·하이픈으로 한정됨.
- 검증된 단일 상수 선별 조건은 생성 스키마에도 반영: 열·비교·수치·자료형, 비교 열 null, 결측·중복·출력·정렬 정책을 고정. 읽기/저장 등 비필터 노드의 execution_plan은 null로 제한. 생성 후 기존 검증을 다시 수행하며, 잘못된 값을 저장 직전에 조용히 고치는 방식은 아님. 도구 카탈로그·자료를 이미 읽었으면 중복 조회를 노출하지 않음. 최종 workflow는 모델에게 검증 인자를 다시 작성시키지 않고 앱 코드가 동일 검증 도구에 직접 전달하며 이후 그래프 검증·사용자 확인·저장 gate를 유지. 모델 도구 호출과 코드 검증은 trace에 구분하여 기록.
- 구조화 결과가 누락되면 최종 AI 메시지의 실제 JSON 객체만 파싱 후보로 삼고 기존 검증을 적용. 설명문·null·배열·도구 응답·필수 항목 누락은 명확한 오류로 차단. None 응답 형식/일반 JSON/도구 전용 호출은 그대로 유지. OpenAI/vLLM 어댑터에는 적용하지 않음.

## 유지한 경계
기본 활성화 설정(off), 프런트엔드, 파서, DB 스키마, 런타임 도구 구현, requirements 및 .gitignore는 이번 보완에서 변경하지 않음. 공개 인수인계 데이터 형식은 유지하고 기존 장부의 근거를 재검사. 모든 자연어 해석을 증명하는 범용 의미 검증기는 아님. 한 단계 상수 선별 계약을 넘는 요청은 기존 검토 경로를 유지.

## 로컬 모델 실행 전제
Ollama 0.33.0/qwen3:8b에서 기존 ID 정규식 및 purpose/explanation maxLength=2000이 각각 HTTP400 grammar 초기화 오류를 일으켰다. 2×2 비교에서 둘을 함께 조정한 전체 스키마만 3/3 수락됐다. 이는 출력 스키마 수락 검사이며 업무 성공률이 아니다.
추가 실험에서 작은 기본 문맥 한도로 설계 입력이 잘리는 로그가 확인됐다. 진단 서버는 OLLAMA_CONTEXT_LENGTH=16384, OLLAMA_NUM_PARALLEL=1로 실행했다. 이는 실험 프로세스 설정이며 저장소의 .env/운영 설정을 자동 변경한 것이 아니다. 실제 배포 환경의 문맥·출력 토큰·동시성은 별도로 맞춰야 한다.

## 회귀 검사
신규 test_clarification_grounding.py는 비교 경계값의 실제 도구 실행, 명시 답변/기존 장부 재검사, 조건 누락·모순, 추가 상태 필터·정렬 차단, 맥락별 안내, 실제 어댑터 송신 사본, 기존 길이 제한 유지, 비응답 재사용 및 자료 변경 재판정을 검사한다. 고정 추출 응답을 쓰는 회귀 검사는 모델 자연어 정확도와 구분한다.
상세 실행 수치와 실모델 결과는 최종 검증 보고서에 기록한다. 이전 ASSESSMENT_CONSISTENCY.md의 666개 검사는 앞선 단계의 기록이며 최신 검사 수치와 중복 합산하지 않는다.
