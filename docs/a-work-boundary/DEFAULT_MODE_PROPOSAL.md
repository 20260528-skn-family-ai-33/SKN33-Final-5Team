# 지원 판정·조건 판정을 켜고 진행 (2026-10-29, A 결정 · 팀 공유)

A 파트는 판정을 켠 상태(enforce)로 진행하기로 했다. `.env.example`에 `A4B_CAPABILITY_MODE=enforce`, `A4B_CONDITION_MODE=enforce`를 넣었다. **코드 기본값은 off 그대로**이므로 `.env`에 두 줄이 없는 환경과 테스트는 기존과 같다. 각 파트는 아래 "결정이 필요한 사람" 항목을 확인해 주기 바란다.

## 왜 문제인가
실제 앱(프런트 → `worker.py`)은 위 두 값을 넘기지 않아 기본값 off로 실행된다. off에서는:

- 조건 장부(확정·미정·충돌)와 **질문 ID가 생성되지 않는다** (`nodes/await_input.py`는 `condition_enforced`일 때만 질문 기록을 붙임). 프런트의 `question_id` 연결·보류·"모르겠어" 처리가 동작하지 않는다.
- 확정 조건 반영 감사(`audit_conditions`)가 실행되지 않는다.
- 미지원 판정이 Deep Agent 초안에만 의존한다.

## 관측: 반복 평가 (qwen3.5:4b + num_ctx 16384, 앱 진입점 `worker.handle`, 같은 요청 5회씩)
| 요청 (기대) | off (현재 코드 기본) | enforce | 응답 중앙값 off→enforce |
|---|---:|---:|---|
| 모호한 요청 + "모르겠어" → 되묻기 | 4/5, 질문 ID 0/5 | **5/5**, 질문 ID 5/5 | 58→29초 |
| 명확한 요청 → 올바른 초안 | **0/5** (틀린 초안 ready 통과 1) | 2/5 (나머지는 저장 전 차단 2, 길이 중단 1) | 105→227초 |
| 이메일 발송 → 미지원 | 1/5 | **5/5** | 60→28초 |
| 첫 행/마지막 행 모순 → 되묻기 | 5/5 (질문 ID 없음) | 3/5 → **판정 규칙 보완 후 5/5** | 60→30초 |

- 명확한 요청의 실패는 판정이 아니라 Deep Agent 초안 생성(노드 누락)에서 나온다. 생성 담당 전달: `GENERATION_HANDOFF.md`.
- 모순 요청 보완(2026-10-31, `capability_judgement.py`): "조건 모순·미정 기준은 기능 부족이 아니라 사용자 결정"을 판정·재검토 프롬프트에 일반 규칙으로 추가. 보완 후 지원 판정만 반복: 모순 요청 미지원 오판 **0/10**(이전 앱 흐름 2/5), 이메일 미지원 5/5 유지, 명확한 요청 지원 5/5 유지. 앱 흐름 모순 요청 5/5 되묻기(질문 ID 포함).
- 소수 반복 탐색이며 일반 정확도가 아니다. 근거: `research/a4b_scopefix_20261029/` (보고서, `default_path/repeat_eval_5x/`, `capability_conflict_fix_20261031/`, 실행 노트북).

## 켜면 바뀌는 것 (비용)
- 요청마다 지원 판정 1~2회 + 조건 추출 1회의 모델 호출이 추가된다 (판정 자체 약 25~35초).
- 단, 되묻기·미지원으로 끝나면 초안 생성(Deep Agent)을 건너뛰어 전체 응답은 오히려 짧았다 (관측 off 약 50~70초 → enforce 약 26~29초). 조건이 모두 확정되어 초안까지 만드는 요청은 판정 시간이 더해지며 실행마다 편차가 크다 (같은 요청 off 96~216초, enforce 119~226초).
- 판정이 틀리면 지원되는 업무가 미지원/재질문으로 막힐 수 있다 (보완 전 모순 요청 오판 2/5, 보완 후 관측 0/15).
- 한 번 enforce로 시작한 세션은 이후 off로 약화되지 않는다 (기존 설계).

## 켜는 방법 (합의 후)
`.env`에 다음 두 줄을 추가한다. 코드 기본값은 그대로 둔다.
```
A4B_CAPABILITY_MODE=enforce
A4B_CONDITION_MODE=enforce
```

## 함께 필요한 설정
Ollama `/v1` 경로는 요청별 `num_ctx`를 지정할 수 없어, 기본 4096에서 앱의 첫 요청(약 6k 토큰)의 자료·도구 문맥 메시지가 **오류 없이 통째로 빠진다**. `Backend/scripts/setup-ollama-model.sh`로 `a4b-qwen35-4b-16k`를 만들어 `A4B_LLM_MODEL`에 지정한다. RunPod 설치 스크립트(`scripts/setup-runpod-ollama.sh`)에도 같은 단계가 필요하다(담당자 확인 필요).

## 결정이 필요한 사람
프런트(질문 ID·보류 화면), 생성·실행 담당, 운영(RunPod) 담당.
