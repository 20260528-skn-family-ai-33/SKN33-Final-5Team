# 부족 기능과 확인 필요 조건의 동시 보존

지원 판단이 `missing_capability`인 경우, 원문과 부족 동작을 보존하고 별도로 `a4b.gap-condition-review.v1` 검토 정보를 만든다. 이 정보는 기존 확정 조건 장부가 있으면 복사하고 원문 발언과 일부 확인 후보를 함께 보존한다. 후보는 입력 문장의 제한적인 단어 패턴을 사용하므로 모두 `review_required`다. 완전한 조건 목록이 아니며 값이 누락됐다는 단정도 아니다. 후보가 없더라도 원문을 다시 검사해야 한다.

도구 부족 자료와 선택 응답에 같은 검토 정보가 전달되며 검토 정보는 상태 지문에 포함된다. 제작 의도 자체의 엄격한 기존 스키마는 유지하고 제작 담당자는 같은 gap 자료의 `condition_review`를 함께 받아야 한다. 재설계 문맥 및 승인된 생성 인계에도 같은 검토 자료를 전달한다. 생성 전 다시 판정·검증·사용자 확인이 필요하다. 자동 생성·등록·실행 허용을 의미하지 않는다.

후보 선택 규칙은 현재 금액 선별, 예약 시각, 이메일 수신에 관한 대표 표현만 감지한다. 다른 표현·첨부 자료·상충 조건 전체를 처리하는 의미 분석기가 아니다. 실제 누락 여부는 통합 후 원문, 자료, 기존 대화를 확인하여 판정해야 한다.

중복 처리 충돌 뒤에 사용자가 이전 질문의 단일 선택을 명시한 경우 새 발언을 근거로 선택을 갱신한다. 복합 범위는 기존과 같이 보수적으로 검토하고 다른 모순이 없다는 이유만으로 생성하지 않는다. 통제 모델 응답을 이용한 그래프/SQLite 회귀와 실제 모델 사례를 구분해 기록한다.
