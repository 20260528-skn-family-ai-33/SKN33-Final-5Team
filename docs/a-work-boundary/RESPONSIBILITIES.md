# 팀원 A 담당 경계 제안 — 2026-10-27

팀원의 실제 합의 전인 작업 경계 제안이다. 팀원에게 메시지를 보내거나 담당을 확정한 것은 아니다.

| 항목 | A가 구현·검증해 전달 | 상대 파트 연결 |
|---|---|---|
| 조건·지원 판단 | 자료/대화/실제 도구 목록 입력, 질문/근거/보류/도구 부족 판정과 오류 분리 | 실제 파일/DB 상태와 카탈로그 공급 |
| 제작 명세 | 검토 명세·입출력·미정 조건·평가 자료 형식 검증, 현재 요청/동의 연결 | 업무별 명세와 독립 정답 검수 담당 지정 |
| 제작 처리 | 사용자 선택, 중복 방지, Qwen 후보 생성·격리 검사·결과 보존·복구 | 프론트 표시/진행 조회 및 서버 내부 호출 연결 |
| 재설계 | 원래 요구/변경 제안/도구 대안/사용자 동의 규격, 저장·변경·보류 검증 | 생성 담당이 실제 대안과 워크플로우 JSON 생성 |
| 실행 | 후보 해시·규격·검사 결과를 전달. 정식 등록/실행 허가를 자동 부여하지 않음 | 실행 담당이 임시 도구의 포트/버전/권한 계약과 실제 런타임 연결 |
| 공동 검증 | 새 사례 판단, 제작·선택·실패·철회·복구 검사 기록 | 실제 파서/DB/화면/전체 실행 통합 |

A의 명세 검증기는 사용자 의도에 대한 완전한 증명이나 정답 생성기가 아니다. 샘플을 사람이 승인했는지의 진술과 자동 개발 예제를 구분한다.
프론트 선택에는 제작과 재설계 동의를 넣되, 업무 결과/요구 변경/정식 등록 동의를 하나로 합치지 않는다.

## 후속 완료 경계

A는 재설계의 `대안 제안 → 변경점 확인·거절·보류 → 승인된 유효 요청 전달` 계약과 저장/버전 검사를 제공한다. 실제 대안과 최종 Workflow JSON 작성은 생성 담당 연결 대상으로 남긴다. 승인 후에도 조건 재검사·초안 코드 검증·저장 확인이 필요하다.
실제 파서/DB 최신 응답은 현재 사용자도 확인하지 못했으므로 해당 공동 검증은 대기다. 이를 가상 응답으로 완료 처리하지 않는다.
