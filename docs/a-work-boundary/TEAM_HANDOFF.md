## 전달 상태
구현·개발용 검사와 전달 규격을 제공한다. 팀 담당 합의, 사람 검수 미사용 평가, 실파서/실DB/프론트 통합과 전체 업무 성공 검증은 미완료다. 이 문서를 팀원 합의서로 사용하지 않는다.

## A가 작업한 내용
1. 조건·근거 장부: 확정·미정·충돌과 사용자 발언/자료 근거, 이미 확정한 조건 유지.
2. 되묻기: 필수 조건 질문, 모르겠어/아직 결정 못 했어요에 임의 값 미주입, 보류·이후 답변 반영.
3. 입력 검사: 미첨부 자료의 설계/실행 시점 구분, 파싱 부분 실패·DB 조회 실패를 사용자 정보 부족과 분리.
4. 도구 지원 검토: 실제 등록 도구/조합, 앱 일·주 예약 정보, 부족 기능 재검토. 선택형 off 기본 유지.
5. 없는 도구 선택: 새 도구 제작 / 기존 도구로 흐름 재설정 / 나중에 결정. 상태·버전·동의 보존.
6. 제작 연결: 현재 동의 확인→검토 명세→실제 Qwen 후보 코드→QuickJS 격리 검사→결과 기록·조회. 자동 정식 등록/원래 runtime 삽입은 없음.
7. 재설계 계약: 원래 요구·변경점·제약 보존, 별도 승인/거절/보류, 승인 뒤에도 초안 재검증·저장 확인 필요.
8. 복구: 중복 제작 방지, 소유권·만료·철회/오래된 결과 차단, 새 선택 후 재시도.
9. 워크플로우 검증: 형식·근거·포트·연결·확정 조건 대조. 좁은 순차 표 처리 컴파일 경로도 제공. 구조 통과를 업무 정답으로 취급하지 않음.
10. 예약: 기존 서버 트리거 경로 확인, DST 시간 비교 수정, 실제 예약→등록 도구→CSV 확인, 운영 한계 문서화.

## 팀에서 받을 것
- 파서: 정상/부분 실패/변환 실패 샘플, parser_status·경고·문서/페이지 식별자.
- DB: 성공/빈 결과/실패 구분, 세션·revision·문서 버전, 기존 답변 조회 상태. 실패를 빈 배열로 바꾸지 않음.
- 생성 담당: 대안/요구 변경 명세를 생성하고 승인된 effective_request로 실제 Workflow JSON 작성.
- 실행 담당: 임시 도구의 코드 해시·포트·버전·권한·자원 제한 계약, 원래 워크플로우 삽입과 결과 정답 대조.
- 프론트: 질문/답변ID, 세 선택과 변경 동의, 현재 revision, 진행/실패/보류/결과 표시.
- 운영 담당: 상시 서버·지속 DB·예약 데이터 갱신·지연/겹침·실패 알림 정책.
