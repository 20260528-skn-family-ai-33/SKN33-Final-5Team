# 되묻기 경로의 결정형 규칙 목록 (2026-11-11)

목적: 문장 표현을 보고 **경로를 정하거나, 막거나, 값을 덮어쓰는** 규칙(결정형)을 찾아 교체 순서를 정한다.
값의 형식만 확인하는 규칙(검증형: 숫자·단위·요일·시간대·등록 도구 ID·원문 근거 일치)은 대상이 늘지 않으므로 유지한다.

판단 기준

1. 사용자 표현이 늘어날 때마다 고쳐야 하는가 → 그렇다면 결정형 후보.
2. 그 규칙이 결정을 내리는가, 모델이 낸 값을 검증만 하는가 → 결정이면 교체 대상.

규모: 되묻기 경로의 정규식·고정 목록 상수 약 136개 (`condition_readiness.py` 41, `capability_judgement.py` 18,
`question_contract.py` 12, `runtime_inputs.py` 11, `document_rows_template.py` 11, `file_timing.py` 10, `gmail_summary.py` 7, …).

## 2. 검증형 — 유지

| 규칙 | 이유 |
|---|---|
| 금액·단위 해석 `_amounts`, `column_amount`, `_COMPARATOR_SPAN` | 숫자·단위는 닫힌 집합. 원문에 같은 값이 있는지만 확인 |
| 예약 시각·요일 `schedule_literals`, 시간대 | 요일 7개, IANA 시간대 목록 |
| 원문 근거 일치 (`user_quotes`, 추출 구간 근거 확인) | 결정하지 않고 모델 출력을 검증 |
| Gmail 날짜 조회 값 `gmail_schedule._PLACEHOLDER` | 앱이 정한 고정 문법 2종 (`previous_day`, `today`) |
| 한글 수량 검증 `gmail_slots._NATIVE` | 모델이 읽은 수를 원문과 대조하는 데만 사용 |
| 관계 술어 `question_contract._RELATION_PREDICATE` | 문법상 닫힌 부류(있는·포함된·관련된 등). 결정이 아니라 추출 결과 검증에 사용 |

## 3. 교체 순서

1. **2단계 (진행 중):** Gmail 고정 흐름 → 칸 추출 구조. RunPod 측정 후 기본값 결정.
2. **3단계:** 답변 종류·짧은 동의·선택지·별도 질문 판정을 "규칙(확실한 경우) → 소형 LLM → 실패 시 규칙" 구조로. 소형 LLM은 RunPod 비교 후 선택.
3. **4단계:** 표 조건 장부의 결정형 규칙(범위 분기, 모호 표현, 예약 보호, 작업 취소)을 병합 규칙과 의미 추출로 대체. 다른 팀원 작성 코드라 공유 후 진행.

각 교체는 설정값으로 켜고 끄며, `scripts/verify/clarification/`의 평가셋(cases_v2, cases_team)으로 기존 방식과 비교한 뒤 기본값을 바꾼다.
