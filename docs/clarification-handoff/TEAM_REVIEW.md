# 팀 공유용 검토 항목

목표: 팀원 A의 되묻기·조건 판정을 파서·DB·도구 추천·생성·화면 파트와 연결.

현재 상태: 규격 초안·샘플·어댑터 준비. **팀 합의와 실제 서비스 통합은 대기 상태**.

| 검토할 파트 | 먼저 확인할 사항 | 제공받을 최소 샘플 | 완료 기준 |
|---|---|---|---|
| 파서 | 실제 반환이 text/pages인지 canonical_text/blocks인지, 부분 처리·원본 쪽 번호 표현 | 정상 1건, 부분 실패 1건의 JSON | 변환 상태·본문·원본 페이지가 손실 없이 대응 |
| DB·세션 | ID·버전·revision 발급 주체, 이전 조건·질문·답변 저장 위치, 조회 실패 표현 | 정상 조회와 조회 실패 JSON, 수정 후 revision 예 | 다른 세션·오래된 응답 차단, 재시작 후 조건·질문 이력 복원 |
| 도구·실행 | 실제 실행 카탈로그 ID·버전·포트, 현재 정식 지원 범위 | 현재 카탈로그 1건 | 지문 및 지원 범위 일치. 불일치를 업무 미지원으로 처리하지 않음 |
| ML 추천 | 원시 추천과 build_advice 중 무엇을 전달하는지, 모델 버전·fallback 사유 | 정상 추천·fallback·장애 각 1건 | 전체 도구 유지, 후보·점수 보존, 추천 실패 시에도 범위 판정과 구분 |
| 생성 | READY와 사용자 승인의 구분, 어떤 generator_context 필드를 읽는지 | 생성 함수가 받는 입력과 반환 1건 | 확정 조건·실제 자료 ID 사용, 저장 전 코드 검증 및 사용자 확인 |
| 화면 | question ID 전달 여부, 자유 답변·보류·시스템 오류의 표시 방식 | 질문 표시·답변 전송 payload 각 1건 | questionId→question_id 연결, 시스템 오류를 업무 질문으로 표시하지 않음 |

합의할 결정:

1. 이 초안의 필드·6개 상태를 그대로 사용할지, 변경이 필요한지.
2. session/revision과 자료 버전의 실제 발급·갱신 주체.
3. 일부 페이지만 처리한 자료를 허용할 업무 범위와 원본 page_no 보존 방법.
4. SVM 결과 형식과 생성 파트의 실제 소비 위치.
5. 공동 통합 사례: 정상 → 추가 질문 → 답변 반영 → 생성 / 파싱 실패 / DB 장애 / 미지원.

팀원 A가 이미 준비한 것은 README, 입출력 JSON Schema, 전체 도구 카탈로그, 9쌍의 샘플, 순수 어댑터와 검증 명령이다. 팀원에게 메시지를 보내거나 API를 바꾼 것은 아니다. 합의 후 위 실제 샘플과 연결해 결과를 남긴다.
