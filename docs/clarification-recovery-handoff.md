# 되묻기·초안 보존 작업 인계 (2026-11-16)

작업 PR: #134 / 브랜치: `codex/preserve-draft-edit-failures`

## 현재 동작과 변경

- 운영 모니터링에서 Gmail 노드 수정과 재시도가 requirements 단계의 응답 검증 실패로 끝난 기록을 확인했다. 원문 모델 응답은 확인하지 않았으며, 정확히 어떤 응답 항목이 잘못됐는지는 운영 기록만으로 확정할 수 없다.
- 요구사항 추출 실패 시 기존 초안을 비우지 않고 변경·저장만 차단한다. 같은 요청의 반복 실패 횟수와 확인 가능한 실패 원인을 표시한다.
- 이전 버전에서 비워진 초안은 자료 버전이 같고 사용자 승인 대기에 도달했던 최근 40개 체크포인트 안의 초안에서만 복원한다. 중간 검증 후보를 승인된 초안처럼 복원하지 않는다.
- 재시도 시 원래 사용자 요청·답변을 유지하고 실제 파이프라인을 다시 실행한다. 이전 실패 안내는 현재 요청 문맥에서 정리하며 저장 승인 상태를 초기화한다.
- Gmail의 건수만 바꾸는 팝업 요청은 노드 ID·이름·기존 값과 요청 전체가 정확히 일치할 때에만 기존 검토 결과에 새 건수를 적용한다. 이 최적화는 Gmail에 한정된다.

## 추가한 범용 되묻기 처리 — 검증 계속 필요

- 지원 판단·조건 확인에서 질문용 임시 초안을 만들 때 기존 workflow와 실행 설정을 유지하고 현재 질문·선택지만 갱신하도록 변경했다. 요구사항 단계는 기존 초안 복사 동작을 유지한다.
- 지원 판단·조건 확인의 오류 안내에 실패 단계를 넣고 반복 실패 횟수를 기록한다.
- 화면의 재시도 버튼이 requirement_failure뿐 아니라 system_failure도 처리하도록 변경했다.
- 이는 모든 생성기·검증기·외부 API 오류에 대한 완전한 공통 복구가 아니다. 생성·검증 후의 후보 교체, 질문 취소·보류, 자료 변경, 저장된 작업 수정의 영향도 더 확인해야 한다.

## 완료한 검증

- Gmail 전체 그래프: 미읽음 메일 요약 생성 → 팝업의 100 → 5 변경 → ready. 미읽음 필터와 2단계 workflow 보존 및 추가 모델 호출 없음 확인.
- 신규 복원·재시도 회귀 테스트 12개 통과. 저장 차단·이전 초안 재열기·자료 버전 불일치·승인 전 후보 거부 포함.
- 기본 수정본의 관련 Python 묶음 62개·185개·161개 각각 통과(중복 포함).
- 기본 수정본의 전체 프론트 430개: 429개 통과, 로컬 접속 권한이 필요한 프록시 테스트 1개도 별도 실행 통과.
- 범용 되묻기 확대 후 clarification core + failed edit 테스트 68개 통과. 프론트 타입 검사·Vite 빌드 통과.
- 범용 되묻기 확대 후 전체 프론트 및 전체 지원 판단·조건 확인 회귀 테스트는 아직 다시 실행하지 않았다.
- 운영 생성 요청은 추가 실행하지 않았다. RunPod 없이 주입한 모델 응답으로 자동 테스트했다.

## 내일 이어서 할 일

1. Gmail 외 표·문서 요청에서 질문 → 답변 → 추가 질문 → 모델 실패 → 재시도 과정을 테스트한다.
2. 질문 ID·선택지·이미 확정한 답변이 초안 보존 과정에서 섞이거나 반복되지 않는지 확인한다.
3. 지원 판단·조건 확인의 system_failure 재시도 화면을 DOM 테스트에 추가하고 반복 실패 횟수·현재 단계·저장 차단을 확인한다.
4. 새 정상 초안 생성 후 실패·재시도 안내가 사라지는지, 잘못된 후보를 기존 초안으로 복원하지 않는지 확인한다.
5. 범용 확대 변경의 전체 회귀 테스트를 실행하고 PR을 재검토한다. 승인 후 병합·배포한다.

## 로컬 시험 상태

- 운영 배포는 #133까지 완료됐다. #134는 draft 상태이며 미병합·미배포다.
- 로컬 서버는 아직 실행하지 않았다. 준비한 시험 포트는 3042이며 시험 데이터는 별도 SQLite 폴더를 사용한다.
- 현재 PC의 `runtime/start-local-pr134.mjs`에 로컬 시작용 도구를 준비했지만 이 파일은 PR에 포함하지 않았다. 기본 모드는 AI 주소를 localhost로 설정해 RunPod를 호출하지 않으며, 로컬 AI가 없으면 화면만 확인할 수 있다.
- 실제 AI 되묻기·생성 실험에는 RunPod 또는 별도 AI가 필요하다. RunPod가 꺼진 동안에도 화면·자동 회귀 테스트는 가능하다.
- 프로젝트 Python 환경에 누락돼 있던 Babel 2.17.0을 설치했다. 원래 작업 폴더의 미커밋 수정과 `.env`는 유지했다.
