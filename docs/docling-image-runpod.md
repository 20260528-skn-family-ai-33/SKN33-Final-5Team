# 이미지 표 보완의 RunPod Docling 연결

## 문제와 변경

이미지의 layout/PaddleOCR 요청은 RunPod를 사용하지만 표 영역은 AWS의 로컬 Docling으로 실행됐다. 2026-11-18 합성 영수증 요청에서 `image_table:dependency_missing`, `route=cpu_local`, `ModuleNotFoundError: No module named 'docling'`을 확인했다.

정규화된 PNG 표 영역 및 전체 이미지 비교를 `POST /v1/docling-image`로 보낸다. 202 작업 ID를 받고 `GET /v1/docling-image/{id}`로 결과를 조회하며 실패·취소 시 DELETE한다. 원본 PNG SHA-256, Docling 엔진·버전·CUDA 결과를 검사한다. 반환된 기존 blocks/cells 계약을 그대로 사용하므로 원본 영역·좌표 연결은 기존 파이프라인이 보존한다.

PDF와 이미지 Docling은 하나의 작업 슬롯과 취소·기한·polling lease를 공유한다. 입력은 8MiB 이하 PNG, 디코딩 크기는 4천만 픽셀 이하, 결과 JSON은 6MiB 이하이다. 이미지 실패를 로컬 Docling 재시도로 숨기지 않는다. 부분 추출 및 표 구조 누락은 계속 검토 대상으로 남는다.

Pod 내부 PDF worker는 `A4B_DOCLING_LOCAL_ONLY=1`로 이미 점유한 슬롯에 다시 요청하지 않는다. AWS에서는 이 값을 설정하지 않는다. Word/PPT/HWP 경로와 검산·CSV 저장 조건은 변경하지 않는다.

## 배포 순서

1. PR의 `Backend/documents`와 `scripts/runpod` 수정본을 포함한 새 RunPod 릴리스를 준비한다. 기존 Docling Python·모델을 재사용하며 패키지 변경은 없다.
2. 별도 localhost 포트와 독립 테스트 키로 이미지·PDF 계약을 검증한다. 운영 키를 복사하거나 로그에 출력하지 않는다.
3. 운영 파서의 진행 중 작업을 확인하고 새 릴리스로 파서 서비스를 전환·재시작한다. `/health`의 `docling_image_jobs=true` 및 인증된 이미지 요청을 확인한다. 시작 시 사용하는 릴리스 경로도 갱신한다.
4. 그 다음 AWS 코드를 배포한다. main 병합 시 기존 EC2 Actions 배포 대상은 backend이다. RunPod는 이 Actions로 자동 갱신되지 않는다. 기존 `A4B_PARSER_URL`, `A4B_PARSER_API_KEY`를 사용한다.
5. 같은 합성 영수증으로 홈페이지 표 추출을 재검증한다. 연결 성공과 숫자 정확도는 따로 판정한다.

되돌릴 때는 AWS 호출 코드를 먼저 이전 버전으로 돌린 뒤 RunPod를 복귀한다. AWS 새 코드가 이전 RunPod를 호출하면 404로 표 보완 실패가 기록된다. PR 검증용 별도 서버를 운영 반영 완료로 간주하지 않는다.

## 리뷰 보완: 경합·시간 예산·작업 경로

- AWS API가 자식 프로세스에 실제 종료 예정 시각(`A4B_DOCUMENT_DEADLINE_UNIX_MS`)을 전달한다. `LocalEngines`는 생성 시 문서 전체의 이미지 보완 예산을 한 번만 계산한다. 기본 상한은 120초이며, AWS 종료까지 남은 시간에서 20초를 뺀 값보다 클 수 없다. 검사·layout·OCR 및 앞선 표 보완에 쓴 시간도 차감한다. 직접 CLI 호출은 `A4B_DOCUMENT_TIMEOUT_MS`/`A4B_PDF_TIMEOUT_MS`(기본 300초)를 기준으로 계산한다.
- 표마다 240초를 새로 부여하지 않는다. 이미 소진한 예산은 새 영역·전체 이미지 비교에서도 재설정하지 않는다. 취소 요청은 최대 2초이며, 결과 직렬화·정리를 위한 여유 안에서 수행한다.
- 429 입장 대기는 최대 10초 범위이며 PDF와 동일한 5초 간격으로 재시도한다. 계속 바쁘거나 기한이 소진되면 이번 문서의 후속 이미지 Docling 요청도 건너뛴다. `image_table:busy`/`image_table:timeout`과 이미 끝난 OCR을 포함한 부분 결과를 반환한다. 이 방식은 빈번한 재시도 차이를 줄이지만 FIFO 공정성을 보장하는 서버 큐는 아니다.
- 작업에 `pdf`/`docling-image` 종류를 기록한다. 다른 경로의 조회·취소는 404로 처리하며 polling lease·delivered·취소 상태를 변경하지 않는다.
- 별도 활성화 플래그는 추가하지 않았다. RunPod 우선 반영 후 AWS 배포 순서는 유지한다. Office 로컬 Docling 및 기존 Windows POSIX 테스트 문제는 이번 연결 수정 범위 밖이다.
- 리뷰 보완 로컬 검증: Python 72 tests + 6 subtests 통과, API 문서 분석 통합 테스트 2개 및 Backend API TypeScript 검사 통과. 가짜 시계에서 연속 429인 표 2개는 5초 후 busy로 종료했고 두 번째 영역은 재요청하지 않았다. 이미 30초를 사용한 60초 작업은 40초 시점에 취소해 결과 저장 여유를 남긴다.
- RunPod 실제 PDF·이미지 경합 검증: PDF가 슬롯을 점유하는 동안 합성 영수증은 9.46초에 `partial` + `image_table:busy`를 반환하고 OCR을 보존했다. 이미지 경로로 해당 PDF의 조회/취소를 요청하면 모두 404였다.
- 경합 해소 후 해당 PDF는 정상 완료됐으며, 동일 합성 영수증의 새 실행은 22.19초에 Docling GPU 보완까지 성공했다. 검증용 서버만 종료하고 운영 파서는 기존 릴리스를 유지했다.

## 표 OCR 대조 및 품질 검사

- 이미지 표 crop에도 PaddleOCR을 실행하고 `table_ocr.rec_texts/rec_boxes/rec_scores`를 layout 부모 블록에 보존한다. 좌표는 해당 crop의 픽셀이며 `crop_origin`과 함께 해석한다. 검증 OCR은 본문에 중복 투영하지 않는다. 기본 본문·Docling·비교 결과를 먼저 확보한 뒤 표 crop별 OCR을 독립 호출한다. 검증과 원격 실패 후 CPU 재시도는 기존 문서 전체 이미지 보완 deadline을 공유하며, 기한 소진 시 기본 결과를 보존한 partial로 끝난다.
- `table_quality.py`는 Docling 좌표 단위를 픽셀로 추정하지 않는다. 동일한 OCR 이미지에서 정확히 일치하는 유일한 문자열을 기존 셀의 행·열에 연결한다. 기존 반복 값은 확정 행·일치 문자열·열 경계 구간으로 대조해 머리글/본문의 좌우 정렬 차이를 허용한다. OCR과 셀은 일대일로 대응하며 중복 검출은 다른 행을 확인한 근거가 되지 않는다.
- 누락 복구에서는 기준 개수와 무관하게 겹치는 모든 열을 먼저 세어 다중 열 OCR을 거부한다. 후보가 유일한 뒤에만 점수 0.98 이상, 유일한 행, 서로 다른 두 행 이상의 열 기준, 각 축의 짧은 상자 대비 65% 이상 겹침 요건을 적용한다. 임계값은 보수적인 초기 정책이며 정확도 보장은 아니다. 일치 문자열도 잘못 인식됐을 가능성이 있으므로 독립적인 원본 검토를 대체하지 않는다.
- 기존 셀·빈 문자열·병합 범위를 덮어쓰지 않는다. 충돌, 낮은 점수, 여러 OCR 후보, 좌표 부재는 검토 대상이다. 셀 객체가 없는 슬롯은 빈칸으로 확정하지 않는다. 남은 슬롯은 `unknown_cell_slots`로 기록한다. 검사량은 OCR/셀 각각 2,000개, 슬롯 20,000개로 제한하며 초과 시 검토 처리한다.
- 복구 시 원본 셀·텍스트·HTML을 `original_*`에 남기고 보완 근거를 새 셀의 `recovery`와 `table_quality.repairs`에 기록한다. 출력 텍스트는 셀에서 다시 만든다. 희소 표의 빈 셀을 HTML로 발명하지 않기 위해 복구 후 HTML은 비우고 구조화된 cells를 사용한다.
- 미해결 품질 문제는 표의 `review_required` 및 문서의 `partial`/경고로 전파된다. CSV 누락 셀·병합 셀·검토 상태의 차단은 유지한다. 이 오류는 `TableStructureError`로 구분해 고정 문서→CSV 흐름에서 일반 확인 질문 대신 `document_table_structure` 검증 실패로 종료한다.

### 회귀 증거와 한계

`Backend/tests/fixtures/receipt_table_ocr.json`은 2026-11-18 합성 영수증 진단의 PaddleOCR 문자·상자·점수와 Docling 셀 목록만 추린 재생 fixture다. 계정·서버·파일 저장 경로는 포함하지 않는다. 전체 이미지 OCR 중 표 범위를 사용하므로, 표 crop을 새로 인식한 GPU 결과와 동일하다는 주장은 하지 않는다.

재생 검사에서 초콜릿 `(5, 0)`, 수량 2 `(5, 1)`, 할인 -420 `(8, 3)`을 복구한다. 하단 요약 행의 나머지 누락 셀 객체는 원래 빈칸인지 확정할 수 없어 전체 영수증은 검토 상태로 유지한다. 따라서 이 변경은 해당 영수증의 무조건적인 CSV 저장 성공을 보장하지 않는다. 별도의 완전한 표 fixture로 복구→행 추출→CSV 실행 및 파일 읽기를 검증한다. 실제 영수증의 요약 행을 품목과 구분하는 정책은 별도 워크플로우 범위이며, 이번 변경에서 임의로 제거하지 않는다.

이번 PR 작업에서는 운영 배포·서비스 재시작을 수행하지 않는다. 머지·배포 전에는 실제 GPU OCR의 crop 결과와 홈페이지 업로드부터 저장·실행까지의 흐름을 별도로 검증해야 한다.

- 여러 열을 가로지르는 `2 1200`이 수량 하나로 저장되던 재현을 차단한다. 기준이 한 행뿐인 열도 모호성 검사에 포함한다.

- 한글 fixture 읽기는 UTF-8을 명시했다. Windows 실행 자체를 검증했다는 의미는 아니다.

### PR #157 추가 경계 검증

- 누락 셀 복구에도 열 경계 구간 전체 포함 조건을 적용한다. 옆 열 글자에 닿지 않아도 경계를 넘는 OCR(예: 경계 190, 오른쪽 끝 190.001/215/230)은 보류한다.
- 선택적 OCR 응답은 객체·배열·동일 길이·문자열·유한한 좌표/점수까지 검사한 후 저장한다. null, 잘못된 배열, NaN/무한대, 바깥 응답 형식 오류는 기본 본문과 표를 보존한 검토 상태로 처리한다.
- 증거·원본 사본·복구는 표별로 임시 반영하고 문서 전체 6 MiB 및 호환 응답 12 MiB/본문 제한을 검사한다. 여유가 없으면 해당 증거와 복구를 모두 되돌리고 원본 셀·본문을 유지한다. 최종 검증에서 한도를 넘는 경우에도 선택적 변경을 역순으로 되돌린다. 원본 분석 자체가 기존 제한을 넘는 경우의 제한은 유지한다.
- 문서 경고는 `review_scopes`에 전역(null) 또는 영향받는 블록 ID 목록을 함께 기록한다. 기본 문서 읽기에는 기존 문서 전체 검토 상태가 유지된다. `document_table_id`가 명시된 경우에만 선택 표의 상태·부모 영역·전역 오류를 적용한다. 범위 정보가 없거나 알 수 없는 경고는 보수적으로 차단한다. 문서 경고 자체는 제거하지 않는다.
- 파서가 검토 대상으로 지정한 표는 cells가 비어 있어도 구조 오류로 처리한다. 일반 텍스트의 좌표 부재 안내는 유지한다.
- 재현: 35×21 표가 있는 16프레임 TIFF의 일부 보완이 용량 한도로 보류돼도 원본 표 16개가 모두 반환된다. 두 표 중 정상 표만 선택하는 실제 설계→저장→실행→CSV 경로와 전역/선택 표/부모/레거시 경고 차단을 검증한다. GPU 및 운영 서비스에는 변경하지 않는다.

### 행 경계 추가 보완

- 행 후보에서도 모든 양의 겹침을 먼저 확인하고, OCR 상자 전체가 독립 기준 셀에서 계산한 행 구간에 들어와야 확인·복구한다. 이웃 행 사이 공백은 중간점으로 나누며, 후보 OCR 자체가 행 구간을 넓히지 않는다.
- 다음 행 글자에 닿지 않아도 행 구간을 넘는 상자와 다음 행을 조금만 겹치는 상자를 모두 보류한다. 이웃 근거 부재·표 끝에서는 알려진 범위까지만 허용한다. 겹치거나 역전된 행과 세로 병합에 걸린 행은 자동 복구 근거로 사용하지 않는다.
- `test_table_row_boundaries.py`에서 하단 120인 `2 3` 오복구, 경계 접촉/미세 초과, 가변 행 간격, 위쪽 초과, 이웃 근거 부재, 병합, 여러 줄 텍스트, OCR 순서를 검사한다. 잘못된 입력은 CSV 생성 전 차단하고 정상 입력은 실제 export executor의 CSV를 저장·재조회한다. 문자열 형식으로 수량을 추측하는 규칙은 추가하지 않았다.

### 세 번째 리뷰: 근거 부재·기존 값·본문 용량·체크포인트·성능

- 열 구간은 바로 이웃한 논리 열의 OCR 근거로만 계산한다. 이웃 논리 열이 있으나 근거가 없으면 현재 열의 알려진 범위까지만 허용하며, 중간의 근거 없는 열을 건너뛰지 않는다. 실제 첫/마지막 열의 바깥 방향은 기존 정책을 유지한다.
- 기존 반복 값 확인은 다른 행과 양의 겹침이 없는 유일한 행, 충분한 겹침, 정확한 문자열, 일대일 대응을 사용한다. 행 구간 전체 포함은 새 값 복구에 적용한다. 작은 상자 차이로 정상 수량을 차단하지 않으며, 다른 행을 걸치는 상자는 기존 값이라도 보류한다.
- 최종 분석/호환 응답 용량 초과 시 본문 OCR의 선택적 `ocr_texts`/`ocr_boxes`도 제거할 수 있다. 기본 본문·점수·원점·배율과 표는 보존하고 범위가 있는 경고를 기록한다. 15프레임 TIFF, 표 15개, 본문 450조각 및 용량 경계용 모델 데이터를 사용해 실제 12 MiB 상한에서 되돌림과 6 MiB 분석 한도 준수를 검사했다.
- 구버전 체크포인트에 `selected_table_review_required` 키가 없는 경우에만 원본 동등성 비교에서 제외한다. 이미 있는 키의 변경, 본문 변경, 청크 누락은 허용하지 않는다.
- 문서의 ID 집합·전역/블록별 검토 범위는 청크 생성당 한 번 계산한다. 6,000블록의 전역/국소/알 수 없는 경고 회귀 테스트를 추가했다. 동일 로컬 환경의 전역 경고 비교는 수정 전 약 1.93초, 수정 후 약 0.018초였다. 시간 수치 자체를 테스트 합격 조건으로 사용하지 않는다.
- 추가 검사는 `test_table_review_round_three.py`와 `test_document_review_compatibility.py`에 있으며 모델·장애는 대역이다. 운영 GPU/홈페이지 전체 흐름 검증을 대신하지 않는다.

### 유일 문자열의 위치 일관성 검증

- 정확하고 유일한 OCR 문자열 대응도 즉시 확정하지 않는다. 확정 후보 전체의 행/열 논리 범위와 OCR 상자 순서를 먼저 대조한다. 서로 떨어진 논리 범위의 상자가 겹치거나 순서가 뒤집히면 `anchor_geometry_conflict`로 표 전체를 검토 대상으로 남긴다.
- 모순된 기준 집합은 기존 셀 확인 및 새 셀 복구에 사용하지 않으며 원본 값을 재배치하지 않는다. 병합 셀은 실제 row_span/col_span을 고려해 범위 밖 셀과 비교한다. 정렬 차이와 여러 줄 텍스트에 대해 같은 열의 문자 상자가 반드시 겹쳐야 한다는 조건을 추가하지 않는다.
- 검사는 축별 정렬과 순회를 사용해 후보 수의 제곱에 비례하는 전수 쌍 비교를 피한다.
- `test_unique_anchor_positions.py`의 22개 검사는 수량 행 교환·같은 행 열 교환·3행 순환·다른 문자열의 동일/겹침 상자·유일/반복값 혼합·모순된 기준과 누락 셀을 포함한다. 모든 오류 사례에서 파이프라인 partial/경고, 원본 보존, CSV 차단을 확인한다. 정상 정렬·여러 줄·OCR 순서·좌표 이동/확대·경계 접촉은 파이프라인 succeeded 및 실제 CSV 저장/읽기를 확인하며 수평/수직 병합도 보존한다.
- 이전 bad541d에서 행이 바뀐 수량이 succeeded/경고 없음으로 잘못된 CSV에 저장되는 것을 별도 재생으로 확인했다. 이 검사는 대역 기반이며 운영 GPU/홈페이지 검증이 아니다.
