# 문서 추출·내보내기 계약

## 출력 열과 행 완전성

`export_result.fields`는 출력 열 선택이다. 일반 레코드와 영수증 항목에도
사용할 수 있으며, 그 자체로 `row_coverage=complete`를 요구하지 않는다.
`fields` 모드의 항목별 `field/value` 레코드는 파일 ID별로 묶어 출력한다.
같은 파일의 중복 항목이나 없는 출력 열은 추측하지 않고 거절한다.

반면 `row_coverage=unverified`인 모델 행 추출은 CSV와 JSON 모두 계속 차단한다.
값의 인용이 유효하다는 사실만으로 모든 원본 행이 추출됐다고 보장할 수 없다.
알려진 입력 자료에 표 좌표가 없거나 미해결 표·병합 셀 등이 있으면 설계 단계에서
이유와 다음 행동을 안내하고 저장을 막는다. 기존 저장 워크플로도 실행 검사를 우회하지 않는다.

## 문서 공통 값과 행 값

표 밖의 `거래일자: 2026-11-18`처럼 항목명과 값이 같은 줄에 명시되고,
한 파일 안에서 값이 하나로 확정되는 경우만 모든 행에 복사한다.
행 식별과 완전성은 여전히 파서 셀 좌표로 확인하고, 공통 값은 별도 원문 근거를 보존한다.
값 충돌, 표에 없는 열, 임의 별칭, 줄이 나뉜 메타데이터는 자동으로 추측하지 않는다.

명시적인 첫/마지막 품목 하나 선택은 네이티브 행에서 직접 선택한다.
전체 품목 요청·취소·제외 표현을 단일 값 선택으로 해석하지 않는다.

## 표 선택 워크플로의 새 파일

문서 읽기 노드가 하나이고 새 문서가 하나일 때, 원본 선택 표의 전체 머리글과
행·열 병합 구조가 일치하는 표가 새 문서에 정확히 하나 있으면 다시 연결한다.
파일 이름이나 파서 블록 ID의 일치만으로 허용하지 않는다.
후보가 없거나 여러 개이면 표를 다시 선택하도록 안내한다.
원본이 삭제되어 구조를 대조할 수 없거나 읽기 노드가 여러 개이면 자동 교체하지 않는다.

## 검산 경고

CSV에는 요청 열만 유지한다. 검산 불일치·확인 불가 경고는 결과 파일의
`warnings` 메타데이터와 사용자에게 표시되는 실행 답변에 보존한다.
따라서 CSV 파일 자체만 따로 전달하면 경고는 포함되지 않는다.
검산 일치는 추가 경고를 만들지 않으며 원문 값은 수정하지 않는다.

## 검증 범위

파서 계약 픽스처와 SQLite 저장·실행을 사용해 회귀를 검증한다.
운영 OCR, 실제 모델, 운영 PostgreSQL과 화면 전체 동작을 검증한 것으로 간주하지 않는다.

## PR #152 리뷰 보완

- 필드 결과의 변환 여부는 연결된 추출 노드의 모드로 결정한다. `status` 같은 사용자 항목과 내부 상태 키가 겹쳐도 값이 바뀌지 않는다.
- 공통 값은 청크를 오프셋으로 합친 원문 줄에서 읽고, 빈 구분자와 제외 문구는 값/선택으로 인정하지 않는다.
- 표 교체는 병합 제목 행을 포함해 실제 열 머리글 행까지 비교하고 실행 전 자료 검사에도 적용한다.
- 저장 자료 선택은 실행의 선택 함수를 공유하며 좌표 확인 실패(None)와 정상 0행([])을 구분한다.
- 품목 금액 검산은 실제 표 열에서 추출한 금액에만 적용하고 문서 공통 금액은 합산하지 않는다.
