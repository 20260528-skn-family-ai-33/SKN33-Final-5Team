## 추가 실행 요청의 지원 범위

- 기존 조건 처리 결과에 추가 선별·정렬을 적용한다. 저장된 조건을 대체하지 않는다.
- 예: `주문상태 = 완료; 주문금액 >= 100000; 주문번호 오름차순`.
- 예: `금액 100,000 이상`, `금액 숫자 내림차순`. 구분자는 세미콜론 또는 줄바꿈이다.
- `완료 주문만`은 상태/주문상태 열이 하나로 명확할 때 지원한다.
- `=`/`!=`는 문자 그대로 비교하여 `00123` 같은 식별자를 보존한다. 숫자 대소 비교는 숫자로 비교한다. 정렬은 기본 문자, `숫자`를 명시하면 숫자 정렬이다.
- 필터에 필요한 값이 비어 있으면 임의로 포함하지 않고 오류를 안내한다.
- 기본 read_table/calculate_columns/filter_sort/write_result의 단일 순차 흐름을 지원한다. 분기·중첩·canonical 작업·다중 파일·기존 계산/출력 열 변경은 설정 수정이 필요하다.
- 해석할 수 없는 명시적 변경 요청은 실행 전에 안내한다. 기존 클라이언트의 단순 실행 설명 문장은 호환성을 유지하고 적용되지 않았다는 안내를 남긴다.
- UI나 공개 요청 형식을 추가하지 않았다. 실행 기록의 기존 config_snapshot을 사용한다.

## 남은 확인

1. 실서비스 S5 조건 판정 실패와 재시도 후 불필요한 중복 질문의 원인 분석. 현재 배포 커밋, 모델 이름, 해당 요청의 서버 `ConditionContractError` 진단(`contract_error`)이 필요하다. 키·토큰·개인정보는 필요하지 않다.

3. 탭 재진입 후 저장 불가 사례의 해당 세션/API 상태 확인. 현재 백엔드 회귀에서는 재현되지 않았다.
4. 실제 모델 서버/Gmail 연결 장애 및 서비스 응답 시간 측정.
5. 추가 실행 요청의 임의 자연어·계산·복합 흐름 변경은 현재 지원 범위 밖이다.

사용자는 서버에 접근할 수 없다고 답했다. 따라서 서버 로그 수집과 실제 배포 버전 확인은 운영 담당자의 지원이 필요하며, 이 항목을 완료로 표시하지 않는다.

프런트·로딩 및 OCR/parser 작업은 남은 백엔드 작업으로 세지 않는다. 위의 구현·자동 검증 완료를 원본 피드백 전체의 실서비스 해결 완료와 동일시하지 않는다.
