# 오케스트레이션 일반화 오류 분석

**H18 통합 판정 보류.** 당시 측정본은 뉴욕 현지 시각과 서머타임(DST)을 정답으로 사용했다. 이후 main의 PR #90이 예약 시간대를 서울로 고정했으므로, 이 보고서의 H18 통과 건수는 해당 과거 측정본에만 적용한다.

## 분석 기준

분석 시점의 기본 작업 트리 `main@525f6632`에는 미추적 모듈과 테스트만 일부 남아 있었다. 질문 재개와 의미 해석까지 연결한 1차 구현은 등록된 작업 트리 `output/pr-orchestration-ledgers-20261111`의 `c932680f`에 있다. 해당 작업 트리의 초기 Git 상태는 추적 파일 변경 0개와 별도 사용자가 만든 미추적 실행 디렉터리 1개였다. 수정은 이 작업 트리에서 진행했다. 체크아웃, 원격 업데이트, 기존 평가 파일 덮어쓰기는 수행하지 않았다.

첨부본과 저장소 보고서의 87건 수치는 같다. 저장소판에는 1차 측정 이후 `977858b5`에 통합한 이력이 추가됐다. 1차 측정 manifest의 248개 파일을 현재 수정 전 커밋의 Git blob과 대조한 결과 231개가 바이트 단위로 같았다. 나머지 17개에는 서빙 설정, 세션 복구, 화면 코드가 있다. 따라서 과거 trace는 원인 분석의 기준이지만 두 빌드가 완전히 동일하다고 전제할 수 없다.

원본은 기본 작업 트리의 `docs/local-public9b-verification/release/{legacy52,independent35}.complete.json`에 있다. 원문 응답, 턴별 질문 ID, 단계별 장부 전후 값, 최종 초안 및 기존 판정이 저장돼 있다. 기존 35건 전체를 점검한 1차 결과는 14건 성공·21건 실패이며 이번 상세 분석은 명시된 실패 12건을 대상으로 한다. 초기 52건 보고서 및 실패 분석은 이 작업 트리의 `docs/qwen-live-evaluation-report.md`, `docs/qwen-live-failure-analysis.md`와 바탕화면에서 확인했다. `clarification-root-cause-analysis.md`는 검색한 사용자 폴더 및 로컬 Git 이력에서 발견하지 못했다.

## 검산 가능한 오라클

- H20은 최초 LA 현지 기준일의 구간 `[1830153600, 1830240000)`을 두 턴에서 유지하고, 후속 Gmail 조회 한도만 2로 변경해야 한다.
- H21은 `batch`의 마지막 원본 행을 선택해 CSV에서 seq 3, 4, 5를 유지해야 한다. H29는 먼저 seq 2, 3, 5를 선별한 뒤 batch의 첫 생존 행 seq 2, 3을 내보내야 한다.
- H13~H16의 Gmail 조회 경계는 순서대로 `[1835460900, 1835547300)`, `[1806188400, 1806271200)`, `[1824933600, 1825023600)`, `[1835362800, 1835449200)`이다. 각 구간을 실제 조회 인자와 비교한다.
- H24의 `저장 작업`은 제목이고 `삭제라는 단어는 예시다.`는 본문이다. 수신자는 `night-shift@example.invalid`이며 실제 발송 없이 초안의 인자를 검증한다.
- H32의 두 산출물은 파일 두 개와 의미가 다르다. 다운로드 Markdown 한 개와 한 번의 메일 발송 설계가 같은 요약 텍스트에 바인딩돼야 한다.
