# 오케스트레이션 성능 측정

**H18 통합 판정 보류.** 당시 측정본은 뉴욕 현지 시각과 서머타임(DST)을 정답으로 사용했다. 이후 main의 PR #90이 예약 시간대를 서울로 고정했으므로, 이 보고서의 H18 통과 건수는 해당 과거 측정본에만 적용한다.

## H32 단건 추가 측정

동일한 로컬 Qwen3.5 9B와 평가 프로필에서 변경 전에는 200.95초·모델 응답 9회·검증 실패, 변경 후에는 154.31초·8회·READY였다. 수정본에서는 초안 생성 1회로 Markdown과 메일 본문이 같은 요약 출력을 참조했다. 두 실행 모두 문서 요약 실행·파일 생성·메일 발송을 수행하지 않았다. 사례 한 건의 개별 기록이며 기존 코호트의 지연 분포는 다시 측정하지 않았다. ## 측정 범위와 비교 조건

`scripts/verify/profile-qwen-stages.py`는 보존된 응답에서 사례별·단계별 시간을 집계한다. 전송 횟수는 실제 HTTP 요청 시도를 센다. 토큰은 Ollama 원본 사용량 또는 LangChain 메시지의 usage_metadata에서 가져온다. 의미 추출과 검토는 성공적으로 해석된 응답의 스키마로 구분하고, 분류할 수 없는 응답은 별도 집계한다. 같은 사용자 턴이 Validator를 거친 뒤 conversation에 다시 들어가면 Repair로 집계한다. 표의 단계 시간에는 모델 호출 시간이 포함된다. 사례 시간을 각 단계 시간에 다시 더하지 않는다. 모델 접속 점검은 모든 표에서 제외한다.

Ollama 0.40.16, RTX 4060 Ti 8GB, 공개 Qwen3.5:9b Q4_K_M, context 32768, 출력 4096, temperature 0, seed 42를 사용한다. 공개 가중치 SHA-256은 `02d45dc1cf451ba2475ac33b301c2dd8f985abe4c182ce04a1f2f5bf0260278d`이다. 현재 호스트는 버전 조회에 응답했다. 1차 H21 진단에서 GPU 상주 5,604,082,973바이트를 확인했다. 과거 trace와 첫 진단의 모델·서버·하드웨어·Python 패키지·프로필·하니스 항목은 모두 같았다. 앱 소스 자체에는 기능 통합 이력이 있으므로 첫 보고서에서 현재까지의 변화 전부를 이번 패치의 효과로 단정할 수 없다.

## 선별 실측 기록

첫 H21 진단은 52.83초, 사례 모델 요청 3회였다. 질문 ID는 전달됐고 Condition 모델은 `last`를 반환했다. 정책을 재질문하고 필터 열까지 물어 전체 요청은 실패했다. `runtime/generalization-focused/h21-first.json`에는 이 중간 빌드의 코드 manifest, 실제 응답과 두 턴 체크포인트가 남아 있다. 릴리스 후보 지표는 해당 후보에서 완료한 실측만으로 계산한다.


## 처음 완료된 사례 묶음

동일한 모델·서버·평가 환경에서 H01·H18·H28 세 사례는 기존 0/3에서 고정한 수정본 3/3으로 바뀌었다. H01·H18은 Qwen의 실제 응답이 각각 4개였고, H28은 실행기의 다운로드 한도를 적용해 코드만으로 분기했다. 세 건의 호출은 15회에서 8회, 같은 턴의 생성 재시도는 3회에서 0회로 줄었다. 세 건의 전체 사례 시간 합계는 323.75초에서 234.80초로 줄었지만 p50은 109.73초에서 116.34초로 늘었다. p95는 121.40초에서 117.97초가 됐다. 동시 CPU 테스트 등 호스트 부하를 통제한 반복 실험은 하지 않았다. 이 구간의 p50은 초기 목표인 30초를 충족하지 못했다.

H21은 이전 릴리스의 실패 응답이 48.00초이었지만, 정책을 재질문하고 생성까지 가지 못했다. 첫 복구 실측은 후속 답변, 생성·검증, 실제 합성 CSV 실행까지 포함해 139.07초, 모델 5회였다. 실패를 더 일찍 반환하는 경로와의 시간 차이를 같은 양의 작업에 대한 모델 성능 차이로 계산하지 않았다.
