# PR #139: 조건 보존과 후속 답변 계약

## 원인

기존 코드는 문장 전체에서 `인 행`만 찾았기 때문에 `지역이 서울이고`를 비교 조건으로 보존하지 못했다. 취소 질문은 텍스트·숫자 여부와 확인 중인 의도를 함께 추적하지 않았고, 출력 판정은 조건 답변의 `모두`까지 파일 개수로 읽었다. 저장 검증을 강화해도 앞 단계에서 빠진 조건은 되살릴 수 없었다.

## 변경한 경계

1. `text_filter_parser.py`는 열·값·연결어의 위치를 반환한다. 문장의 최종 선택 동사는 replay 계층에서 판단한다. 인식하지 못한 명시적 선별 피연산자는 질문으로 남기며, 기존 숫자·중복·빈값 판정의 책임을 가져오지 않는다.
2. `text_filter_contract.py`는 시간순으로 조건과 편집 이벤트를 적용한다. `PendingFilterDecision`은 값의 종류와 독립적으로 질문 이유와 기존 값 유지 가능 여부를 기록한다. 확인 중인 취소는 실제 삭제와 다르다.
3. `filter_dialogue.py`는 유지·교체·AND/OR 답변 계약을 공유한다. 질문 ID에 연결된 유지 답변은 모델을 다시 부르지 않고 재검증한다. 답변 기록에는 질문 당시 확정된 숫자 조건을 함께 보존하므로 열 이름 없는 기준값 답변도 이후 질문의 소유권을 잃지 않는다. 이전 체크포인트에는 검증된 조건 장부를 호환 경로로 사용한다. 출력 범위 판정도 이 답변 계약을 사용한다.
4. `literal_text_slots()`가 replay 결과를 기존 슬롯에 투영한다. 조건 판정과 요구사항 생성이 다른 텍스트 추출기를 사용하지 않는다. 생성·저장 검사는 기존 조건 및 데이터 경로 검증을 유지한다.
5. 배포 전 테스트 목록에 조건 선택지, 복합 생성 파이프라인, 편집 시퀀스 및 새 텍스트 대화 회귀를 포함했다.

## 검증 범위

- 두 개·세 개 텍스트 조건의 순서 변경, `이고/이며/이면서`, 쉼표, `인 것만`, 값-열 역순, 따옴표 값.
- 숫자 조건과 텍스트 조건의 결합, 텍스트만 있는 요청, 모델의 연산자·기준값 누락.
- 숫자/텍스트 취소 질문의 일반 입력·폼 답변 → 유지 → 저장 → 실제 SQLite 실행.
- JSON 산출물 내용과 반환 행 대조, 일부 조건을 빠뜨린 초안의 검증·저장 차단.
- 다른 업무의 조건 소유권, 별도 출력 범위 검사, 출력 요청이 포함된 답변 보존.

## 남은 한계

이 변경은 일반 자연어 의미 해석기를 대체하지 않는다. 텍스트 OR와 복합 제외의 적용 범위는 자동으로 추측하지 않고 명시적으로 확인한다. 여러 출력에 대한 조건별 귀속도 이번 변경에서 자동 구현하지 않는다. 기존 다중 출력 보호 검사를 유지한다. 운영 LLM 정확도·운영 DB 검증은 별도 실측이 필요하다.

## 취소·유지 변경의 공통 계약

취소 판정은 숫자·텍스트 처리의 별도 정규식 분기 대신 `filter_edit_events()`가 반환하는 `FilterEdit(start, end, action, fields, scope)` 목록을 사용한다. 열 이름은 연결된 표의 스키마에서 가져오고, 나열된 열에는 같은 취소·유지 동사를 적용한다. 숫자 범위는 확정된 숫자 조건과 자료의 열 타입을 사용하며 텍스트 조건에 확대하지 않는다.

- 문장 전체가 취소 문구 하나와 일치할 필요가 없다. 여러 절과 문장에서도 동사의 대상과 범위를 해석한다.
- 대상이 불명확하거나 같은 열의 취소·유지가 충돌하면 변경 목록의 취소를 보류하고 질문한다. 부분 취소를 먼저 확정하지 않는다.
- 부정된 취소는 유지로, 의문·미정 표현은 미확정으로 처리한다. 인용문과 파일 이름·설명 안의 취소 문구는 필터 변경으로 사용하지 않는다.
- 취소 뒤 같은 차례에 명시한 새 숫자 기준은 새 조건으로 유지한다. 모든 선별 조건이 확정적으로 취소됐으면 이전 슬롯의 빈 기준값을 다시 묻지 않고 선별 작업을 제거한다.
- 취소된 대표 숫자 슬롯이 유지된 텍스트 조건을 가리지 않도록 기존 슬롯 투영도 갱신한다. 취소된 조건을 다시 넣은 초안은 저장 검증에서 거부한다.

일반 대화와 질문 ID가 있는 폼 답변, 이미 준비된 초안의 후속 취소를 실제 그래프·SQLite 저장·실행 결과로 검증한다. 이 계약은 모든 자연어 표현을 지원한다는 의미가 아니며, 인식한 필터 변경의 대상을 확정하지 못하면 이전 조건으로 조용히 진행하지 않는 것을 원칙으로 한다.

확정된 한 조건을 취소해도 다른 미확정 조건은 삭제하지 않는다. 예를 들어 비용 기준만 취소하고 수량 기준이 아직 비어 있으면 수량 질문을 유지하고, 이후 수량 답변으로 그 조건을 완성한다. 기존 조건이 하나도 남지 않으면 질문에 유지할 조건이 있는 것처럼 표시하지 않는다.
