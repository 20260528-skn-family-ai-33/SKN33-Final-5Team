검증일: 2026-11-18. 수정 전 기준: `324c94c`.

## 리뷰 입력과 수정

| 항목 | 같은 입력에서 확인한 수정 전 동작 | 수정 후 동작 |
|---|---|---|
| T02 뒤 `네.` | 모델이 완료 주문을 취소 주문으로 바꾼 목록도 추출 검증 통과 | 자동 생성 가능 여부와 별도로 원문의 상태·계산·집계·정렬·출력 조건을 검증하고 변경 응답을 거부 |
| `CSV 저장은 취소해줘.` | CSV 작업이 남은 응답도 통과 | 취소한 형식을 기록하고 업무 목록과 실제 설계 양쪽에서 해당 writer를 거부 |
| `같은 열을 JSON으로 저장해줘.` | 이전 CSV 작업이 그대로 남아도 통과 | 최신 사용자 턴의 단일 출력 형식으로 검증. 이후 `네.`에도 JSON을 유지 |

세 입력을 수정 전 모듈과 수정 후 모듈에 각각 적용해 이전에는 모두 잘못 통과하고 수정 후에는 모두 거부되는 것을 확인했다. 검증을 없애거나 오답을 정답으로 인정하는 방식으로 변경하지 않았다.

## 원문 보존과 실제 변경의 구분

- 확인 답변, 자료 프로필 없음, 참고 자료 추가, 저장본 기반 설계에서도 T02 전체 조건을 대조한다.
- 합계와 행 개수는 같은 선별·계산 원본에서 분기해야 한다. count가 집계된 결과를 다시 세거나 다른 원본을 읽는 경우, 결합 입력을 잘못 연결한 경우, 결측 정책을 바꾼 경우를 저장 전에 거부한다.
- 사용자가 명시한 상태 변경, 계산식 변경, 정렬 방향 변경, CSV/JSON 변경은 해당 조건만 갱신한다. 검증 가능한 변경 문법 밖의 추가 지시는 원래 요청에서 지우지 않고 중단한다. 모든 자연어 후속 변경을 지원한다는 의미는 아니다.
- 독립적인 sum/count 분기의 나열 순서는 허용한다. 전체 spec을 하나씩 대응시켜 원문과의 일치를 확인하고, 공통 입력·최종 결합 의존성은 유지한다.
- 요청하지 않은 JSON만 취소해도 기존 CSV는 유지한다. CSV+JSON 중 한 형식을 취소하거나 취소한 형식을 다시 요청하는 경우도 검증한다.
- 저장 취소는 숫자 선별 조건까지 취소하는 뜻이 아니다. writer가 없는 상태에서는 최종 표/레코드 경로에 선별 조건이 적용됐는지 확인한다.

## 로컬 서비스 저장·실행 결과

## 검증 범위

- 조건·형식 누락 응답의 거부뿐 아니라 정상 후속 변경이 저장·실행까지 끝나는지 검사한다.

- 이미 운영에 저장된 잘못된 그래프는 자동 변경하지 않는다. 수정 버전으로 새 설계·저장이 필요하다.
- 병합, 운영 배포·재시작, 운영 파일·DB 변경, 토큰 설정 변경을 하지 않았다.
