## 원인

1. 요구사항 추출 결과는 원문 전체를 인용하면서 실제 작업은 `read` 하나만 기록했다. 모델 응답의 문법적 유효성만으로 업무의 완전성을 보장할 수 없었다.
2. 후속 설계 모델은 계산·상태 선별·지역별 합계·정렬·CSV 출력의 6노드를 생성했지만, 행 개수 집계와 출력 열 이름 변경은 누락했다.
3. 저장 전 coverage 검사는 불완전한 요구사항 목록의 `read`만 확인했다. 원문에 있던 행 개수와 열 이름 요구가 검사 대상에서 빠져 잘못된 저장본이 생성됐다.
4. 최신 main에는 PR #151의 원문 기반 T02 추출·합계/건수 연결·누락 검사가 아직 반영되지 않았다. 토큰 확대 여부만으로 설명할 수 있는 문제가 아니다.

모델 내부에서 왜 `read` 하나를 선택했는지까지 입증한 것은 아니다. 위 원인은 저장된 요구사항, 그래프, 검사 기록, 실제 CSV로 확인한 서비스 처리상의 결함이다.

## 이번 보완

- 운영의 불완전한 요구사항·6노드 설계·CSV를 합성 키트 기반 fixture로 기록했다. 업로드 UUID만 치환했고, PR 기준 스키마에 없는 `document_table_id=null`은 명시적으로 제거했다. 업무 설정과 결과 값은 수정하지 않았다.
- 기존 저장 상태의 fingerprint가 현재 값과 같더라도 불완전한 목록을 승인하지 않는지 검사한다. T02 전체 원문은 기존 PR 로직으로 10개 요구사항을 다시 구성하고, 과거 6노드 설계는 저장 검증에서 거부한다.
- 자동 생성 경로의 적용 조건과 필수 업무 누락 검사를 분리했다. `네.` 후속 답변, 기존 저장본을 기반으로 한 설계, 정렬 자료형 프로필 없음, 참고 문서 추가로 자동 생성 경로를 사용하지 못해도, 원문에서 확인한 합계·행 개수·열 이름·최종 열 목록을 검사한다. 모델이 계산이나 합계 하나만 남겨도 전체 요구를 충족한 것으로 간주하지 않는다.
- 같은 턴에 결과 설명을 요청해도 계산·정렬·저장 지시를 버리지 않는다. 인용된 예시와 설명만 묻는 문장은 처리 지시로 취급하지 않는다.
- 이전 최종 검토에서 확인한 동일 턴 `CSV 말고 JSON으로 저장해줘.` 회귀도 수정했다. 출력 열은 유지하고 최종 선택 형식을 적용하며, 이전 형식이 남은 응답은 거부한다.

새 누락 검사 또한 원문 전체를 인식하는 제한된 문법에 기반한다. 임의의 자연어·조건 변경을 모두 처리한다고 주장하지 않는다.
