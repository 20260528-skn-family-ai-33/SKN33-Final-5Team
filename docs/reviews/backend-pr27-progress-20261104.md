# PR27 통합 수정 현황과 확인 순서

작성일: 2026-11-04 (한국시간). PR27의 최초 수정과 이후 로컬 수정사항을 함께 설명한다. 모델 가중치와 학습 데이터는 바꾸지 않았다.

## 1. 문제가 있던 부분

ML이 도구 후보를 제시한 뒤에도 생성기·저장 검사·실행기가 서로 다른 설정과 입력을 기대했다. 따라서 올바른 도구를 골라도 두 파일을 읽지 못하거나, 결합한 표의 집계·정렬이 실패할 수 있었다. 실행 상태가 성공이어도 Qwen이 임의 필터를 추가해 결과를 모두 지우거나 요청한 처리 일부를 빠뜨리는 사례도 있었다.

## 2. 해결한 내용

### 최초 PR27에 있던 수정

- 생성기에 기본 도구 설정과 확장 operation의 실제 인자·포트를 구분해 제공한다.
- 실행 전 파일 검사와 실제 파일 읽기가 같은 선택 함수를 사용한다. 서로 다른 원본을 동일한 실행 파일로 잘못 연결하면 읽기 전에 차단한다.
- 결합 등으로 만든 표에 단일 원본 file_id가 없어도 집계·정렬할 수 있게 한다.
- 원본 파일 operation과 하위 워크플로 입력을 각각의 실행 계약에 맞게 검사한다.
- 응답 계약 오류를 제한된 수정 재시도 안에서 처리한다.

### 이번에 같은 PR에 추가하는 수정

- 기본 설정과 확장 operation 인자를 섞어 넣어도 조용히 무시되지 않게 한다. 생성 검증·노드 저장·실행에서 계약을 확인한다.
- 표 읽기·결과 저장 포트를 실제 실행 코드에 맞춘다. 저장 본문 일부가 사라지는 연결, 잘못된 출력 형식, 종료 뒤 작업을 차단한다.
- 확장 필터의 인자 규격과 실제 operation 로그를 맞춘다. 재사용 도구의 출력 열을 모르면 확인되지 않은 것으로 표시한다.
- API와 Python의 모델 호출 필요 여부를 같은 카탈로그로 맞춘다. 22개 기본 경로와 88개 확장 operation, 총 110개 경로를 대조했다. 모델의 56개 ID 중 미등록 ID는 0개다. ID 대응은 모든 외부 계정·실행 환경의 준비 완료를 뜻하지 않는다.
- 생성 전에 사용자 요청만으로 업무 목록을 별도 추출한다. 기존 초안이나 ML 점수는 이 추출기에 주지 않는다.
- 계산식·열·선별 경계·정렬·집계·결합 정책·출력 형식을 실제 노드 설정과 대조하고, 처리 결과가 최종 저장까지 연결되는지 확인한다. 요청·자료·카탈로그 또는 업무 목록이 바뀌면 저장 전에 다시 검사한다.
- 모델의 통과 판정이나 사용자 확인만으로 업무 누락을 덮어쓸 수 없게 한다. 읽기·저장만 남기는 축소 초안도 확인한다.
- 검증 모델로 보낼 때 불필요한 null 설정을 복사본에서 제거한다. 원래 초안과 고정 검증 패키지는 유지한다.
- 기본 표 계산·열 이름 변경 후의 열 추적을 서비스 연결 계층에서 보완한다. 실제 원본 열과 유효한 실행 설정으로 증명된 경우에만 기존 검증기의 잘못된 열 경고를 재판정한다. 원래 경고·경로·재검사 근거를 함께 기록하며 모델 응답은 바꾸지 않는다. 실시간 및 지연 일괄 검증에 같은 기록 스냅샷을 사용한다.

### 활성화 설정과 적용 범위

| 설정 | 기본값과 동작 |
| --- | --- |
| `A4B_REQUIREMENT_MODE` | 코드 기본값 `off`. `enforce`는 요청 업무 추출과 저장 전 대조를 활성화한다. `.env.example`은 활성화 예시이며, 팀 배포 환경을 자동 변경하지 않는다. |
| `A4B_REQUIREMENT_GENERATION_MODE` | 기본값 `baseline`. 단계의 작성과 연결은 모델이 맡는다. 첨부 표 결합의 입력 자료형·상수 중복은 생성 계약에서도 제한한다. `bounded`는 번호별 필수 단계와 요청 상수, 출력 길이를 제한하는 실험 후보이며 기본 활성화하지 않는다. |
| `A4B_VERIFIER_MODE` | 이번 수정에서 팀 배포 설정을 강제로 바꾸지 않는다. 실제 Qwen 확인은 `shadow`였다. 한 표의 파생 열 오판은 실제 모델 응답으로 재검사했다. 두 표는 입력 예산 초과가 남아 강제 차단 전환을 확인한 상태가 아니다. |

업무 추출은 추가 모델 호출이 필요하고, 추출 자체의 의미 오류 가능성이 있다. 현재 업무 대조는 명시적인 단일 경로의 표 작업을 우선 지원한다. 분기·복수 결과 파일·자유 서술 등 확인되지 않는 작업은 자동 통과시키지 않는다. 대응하지 않은 operation도 지원 완료로 간주하지 않는다.

### 최종 수정본에서 실제로 확인한 결과

사용자가 지정한 공용 Pod `4a60senffyv91x`의 `a4b-qwen35-4b-16k`를 사용했다. SVM56 추천을 힌트로 전달하고, 기존 합성 CSV를 격리된 로컬 서비스 저장소에 연결했다. 모델·라벨 재학습이나 ML 테스트 데이터 생성은 하지 않았다.

| 요청 | 실제 생성 → 확인 저장 → 실행 | 저장 JSON 내용 | 업무 누락·설정 오류 대조 |
| --- | --- | --- | --- |
| 한 표: 계산 → 선별 → 숫자 내림차순 → JSON | 성공. 생성·검사 58.38초 | B amount=40, A amount=30. 실행 행·응답 본문·디스크 파일 일치 | 계산식 변경·선별 삭제·정렬 삭제·출력 형식 변경·처리 결과 우회 5건 모두 저장 차단 |
| 두 표: left join → 곱셈 → 그룹 합계 → 정렬 → JSON | 성공. 생성·검사 44.31초 | A sum=40, B sum=10. 실행 행·응답 본문·디스크 파일 일치 | 계산식 변경·정렬 삭제·합계→개수 변경·좌우 결합 반전·출력 형식 변경·처리 결과 우회 6건 모두 저장 차단 |

각 정상 요청은 최종 버전에서 1회씩 확인했다. 11개 대조 사례는 생성된 그래프를 일부러 잘못 바꾼 검사이며, Qwen이 독립적으로 11회 생성한 결과가 아니다. 처리 시간 역시 이 두 사례의 관측값이며 평균 응답 시간이나 일반 성공률이 아니다.

이번 실제 생성 과정에서 추가로 수정한 내용은 다음과 같다.

- 생성 입력에 중복되던 도구 설명을 줄였다. 전체 ID는 유지하며 선택된 도구의 상세 계약과 `inspect_tool` 조회도 유지한다. 이전 입력 진단에서는 16,384토큰 문맥 중 입력이 15,297토큰이었다. 4,096은 출력 요청 한도이고, 이를 늘리는 것만으로는 입력 포화를 해결하지 못했다.
- 로컬 생성 응답이 실제 길이 초과로 끝나면 같은 요청·규격으로 한 번만 출력 예산을 4,096에서 최대 8,192로 늘려 재시도한다. 잘린 JSON을 저장하거나 무제한 반복하지 않는다.
- 첫 단계의 입력 연결 항목을 없애면서 필수 입력 제약까지 사라지던 생성 규격을 수정했다. 입력 없이 수행할 수 없는 기본 도구를 첫 단계 후보에서 제외한다. 상수 표를 실제로 제공한 계산은 유지하되 첫 단계의 미래 `$binding` 참조는 허용하지 않는다.
- 원문 업무 목록과 첨부 자료가 일치하는 표 결합에서는 표용 `join` 계약을 제공한다. 레코드용 `join_records`와 혼동하거나 연결한 left/right를 빈 상수 표로 다시 지정하는 것을 방지한다. 파일 선택·결합 방향·연산 값·단계 연결은 모델이 작성하고 이후 코드가 대조한다. 완성 그래프를 코드가 대신 삽입하지 않는다.
- 한 표의 실제 Qwen 검증 응답은 pass였으나 원래 코드 검사는 새 `amount` 열을 없다고 판단했다. 서비스 연결 계층에서 실제 원본 열과 계산 경로를 증명해 해당 경고만 재검사했다. 원래 판정과 경고, 재검사 근거를 함께 저장했고 다른 오류는 유지했다.

최종 Python 전체 검사: **1,680 통과, 2 건너뜀, subtest 4 통과**. TEMP/TMP는 쓰기 가능한 작업 폴더로 지정했다. 타입 검사·빌드와 API/Python 110개 경로 대조는 앞선 통합 검사 결과이며 이번에 Node 전체 검사를 다시 실행한 것은 아니다. 기존 시간 초과와 과거 재실행 기록은 이전 문서에 보존한다.

## 3. 미해결 사항

1. **두 표 흐름의 별도 검증 모델은 호출되지 않았다.** 생성·저장·실행과 요청 업무 대조는 성공했지만, 검증기 입력의 보수적 예산 계산값이 35,200으로 허용값 32,768을 넘었다. 이는 실측 토큰 수가 아니다. 결과는 `manual_review`로 보존했고, 결합 뒤 표 스키마를 확인하지 못했다는 경고도 남아 있다. 이번 실행은 `shadow`이므로 해당 경고로 실행을 막지 않았다. 검증기 강제 적용까지 통과했다고 설명하면 안 된다.
2. **입력 예산 조정과 결합 후 열 추적은 추가 작업이다.** 문서나 경고를 버리거나 제한을 무작정 높여 통과시키지 않았다. 원본 계약과 근거를 유지하는 입력 전달 방법을 정리한 뒤 실제 검증 호출과 잘못된 초안 차단을 함께 확인해야 한다. 고정 검증 패키지와 SYSTEM은 그대로 보존했다.
3. **배포된 웹 화면 확인은 남았다.** 이번 확인은 실제 팀 Qwen을 호출하는 로컬 서비스 핸들러로 수행했다. 공개 서비스의 로그인 → 파일 첨부 → 설계 → 저장 → 실행 → 다운로드를 확인한 결과는 아니다. 운영 DB/S3에는 쓰지 않았다.
4. **적용 범위 확대가 필요하다.** 분기·복수 결과 파일·문서 작업·외부 계정 동작 및 다른 복합 요청까지 같은 수준으로 검증한 것은 아니다. 요청 업무 추출 자체도 AI 판단이므로 잘못 추출할 가능성이 있다.
5. **공용 GPU는 그대로 유지했다.** 새 Pod를 만들지 않았고 지정된 팀 Pod의 설정 변경·재시작·중지를 하지 않았다. 기존 팀 환경 파일과 인증키도 PR에 넣지 않는다.

## 다음 순서

1. 이 PR에서 실행 계약 수정, 입력 연결 제약, 업무 누락 차단과 위 두 실제 실행 근거를 함께 검토한다.
2. 두 표 검증기의 입력 예산과 결합 후 열 추적을 보완하고 `enforce` 적용 가능 여부를 별도로 확인한다. 현재 결과는 한 표와 두 표의 실제 실행 성공 및 두 표 검증 제한을 구분해서 전달한다.
3. 팀이 정한 설정으로 병합·배포한 뒤 실제 화면의 첨부부터 결과 다운로드까지 확인한다. 이번 작업에서 병합·배포는 실행하지 않는다.
4. 이후 추가 복합 업무·분기·검수 도구·외부 계정을 순서대로 확대한다.
