## 1. 문제가 있던 부분과 수정

## 2. 검증 결과

- 수정 전: 첫 회귀 검사 16건 중 11 실패, 5 통과. 리뷰의 7개 문제 유형을 모두 재현했다. 실패 수는 문제 유형 수와 다르다.
- 수정 후: 새 회귀 사례 24건을 포함한 관련 검사 **87 통과**.
- Python 전체: **1,704 통과, 2 건너뜀, subtest 4 통과**, 실패/오류 0, 105.60초.
- 실행 명령: Backend에서 `python -m pytest tests -q --tb=short`. 이 작업용 TEMP/TMP를 별도 지정했다.
- `docker compose --env-file .env.example config --format json`: requirement=enforce, generation=baseline, verifier=shadow 전달 확인. 환경에서 requirement=off를 명시했을 때 off 전달도 확인.
- 실제 vLLM 클라이언트에서 추출 스키마를 포함한 요청을 구성했으며 HTTP 호출은 하지 않았다.
- `git diff --check` 통과. 이번 변경은 Python과 Compose이며 Node 전체 검사·웹 배포 검증은 재실행하지 않았다.
- 별도 사본에서 JSON/XLSX 생성·파일 내용 대조 및 저장 차단을 확인했다. 외부 업무 실행·전송, GPU 실행, ML 학습/평가용 데이터 생성은 하지 않았다.

## 3. 미해결 사항 및 팀 연계

- 이번 7건은 코드와 로컬 회귀 검사까지 반영했다. 리뷰 스레드는 팀원의 재검토를 위해 열린 상태로 유지한다.
- 실제 Qwen의 생성·저장·실행 기록은 이전 `8471263` 기준이다. 이번 후속 수정본을 실제 모델로 다시 확인한 결과가 아니다.
- 두 표의 별도 검증기 입력 예산 초과와 결합 후 열 추적은 이번 7건 수정에 포함하지 않았다. verifier=shadow 성공을 enforce 통과로 표현하지 않는다.
- 분기 실행 시 파일 선택 문제는 수정했으나, 분기별 업무 전체를 증명하는 requirement 검사와 복수 최종 파일 요구사항은 계속 추가 검토 대상으로 남긴다.
- XLSX는 처리된 표를 단일 시트로 연결하는 범위를 확인했다. 여러 시트에 서로 다른 업무 결과를 넣는 요청은 별도 확인이 필요하다.
- 팀원 A1~A4는 아직 진행 중이다. 이 수정으로 완료됐다고 표시하지 않는다. 완료 후 통합 회귀 확인이 필요하다.
- 파인튜닝 가중치·워크플로 출력 스키마를 변경하지 않았다. 학습 후보에 잘못된 출처·최종 출력 우회 사례가 있다면 수정된 검사로 다시 검증하고 제외/정정한다. 이번 백엔드 수정만으로 기존 학습을 재시작할 필요는 없다.
