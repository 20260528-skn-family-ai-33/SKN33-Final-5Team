## 대화 경로

- 첨부 확인을 resources 직후로 이동했다. 새 대화, 조건 답변, 지원 판단 답변, 초안 변경 요청이 모두 같은 확인을 거친다. 파일이 없으면 지원 판단 모델보다 먼저 업로드를 안내한다.
- “네”처럼 열 이름·기준값을 주지 않는 답은 기존 지원 판단을 재사용하고 조건 질문을 유지한다. 요청·자료의 fingerprint가 바뀌면 기존 판정을 재사용하지 않는다.
- 중복 모두 유지만 남은 조건은 ready로 처리한다. 빈 작업 목록을 단일 작업 템플릿으로 보내지 않고 일반 설계에서 실제 입력·출력을 구성한다.
- 비교·증감·반품·정정 등은 표 선별 전용 조건 모델에서 전체 설계기로 위임한다. 위임은 지원 확정이나 저장 승인과 다르며 일반 검증·사용자 승인을 계속 거친다.
- 모델 explanation을 화면에 그대로 보여주지 않고 앱이 소유한 짧은 상태 문구를 표시한다. 두 설계 경로와 프론트엔드의 미지원 표시에서 내부 동작 이름을 제거했다. 원래 미지원 기록은 검토용 데이터로 보존한다.
- 기존 영수증 업로드 후 이전 표 정리 요청 복원 회귀 테스트를 유지한다. 실제 XLSX 요청은 CSV 고정 흐름으로 바꾸지 않는다.

## 실행 계약과 배포

- 서비스 실행기에서 프로세스 공통 Google 토큰으로 계정을 자동 구성하는 경로를 삭제했다. 현재 저장소에 주입된 커넥터만 사용한다. 사용자별 OAuth 연결 UI/저장 기능을 새로 구현한 것은 아니다. 연결이 없으면 외부 실행은 차단된다.
- read_table/read_document의 명시적 file_ids가 실행 파일 전체 목록보다 우선한다. 명시적 선택이 없으면 기존 실행 파일 우선 규칙을 유지한다. 서로 다른 두 실행 파일을 읽고 join하는 테스트를 추가했다.
- 실행 시 파일도 읽기 노드의 파일 참조 검증에 포함한다. 저장 시에는 실행 파일을 가정해 허용하지 않는다.
- join.keys의 빈 목록·빈 문자열·공백 문자열을 저장 전 인자 검증에서 거부한다.
- 한국어 카탈로그 JSON은 UTF-8로 명시해 읽는다. Docker는 PYTHONUTF8=1 및 링크 검사 허용 호스트 설정을 전달한다. 공통 Google 토큰 전달 설정은 추가하지 않는다.

## 검증과 한계

실제 파일 두 개의 읽기·결합·결과 생성, 공통 Google 토큰 비사용, 빈 결합 기준 거부, enforce 모드에서 업로드 전 모델 미호출, 체크포인트를 거친 “네” 답변 유지 등을 회귀 검증한다. 합성 자료와 모델 대체 응답 테스트를 실제 Qwen 품질 검증으로 계산하지 않는다.

첫 수정 때의 로컬 연결 실패는 접근 제한 안에서 확인한 결과였다. 후속 재검증에서는 허용된 실행 경로로 Ollama 연결을 확인하고 아래 실모델 검증을 수행했다. 실제 Google 계정에 접속하거나 메일·일정을 변경하지 않았다. SVM 모델 파일·해시·기본 힌트 설정도 임의로 변경하지 않았다. 전체 56개 도구의 실제 모델 생성 성공은 별도 실모델 검증이 필요하다.

### 실제 Qwen 4B 결과

합성 자료, a4b-qwen35-4b-16k, SVM 힌트 off, verifier off로 검증했다. 모델 대체 응답이 아니다. 기본 deepagent 경로에서 계산 요청은 생성·저장·실행 후 23을 반환했고, XLSX 요청은 생성·저장·실행 후 실제 파일의 Data 시트가 id/amount, A/10, B/20과 일치했다. 각 한 번의 성공이며 56개 전체의 품질 보증은 아니다.

선택 설정인 direct/v8에서는 계산 생성 시간 초과(지원 판단은 통과), XLSX 구성 실패와 뒤이은 잘못된 미지원 응답이 재현됐다. 이 생성 품질 문제는 해결 완료로 계산하지 않는다. 미지원 판정 충돌 방어는 이 관찰 후 추가했다. 실제 Google 호출과 배포 환경 검증은 하지 않았다.

## SVM 힌트 기본 활성화

사용자 요청에 따라 추천 모드 기본값을 hint, backend 기본값을 svm56으로 변경했다. Docker Compose의 힌트와 Docker 이미지의 ML 의존성 설치도 기본으로 켰다. 로컬 npm run setup은 ML 의존성도 설치한다. 모델·카탈로그는 저장소 기준 runtime/ml-bundle에서 찾으므로 서버 실행 디렉터리를 바꿔도 기본 경로가 유지된다. 명시적인 off/legacy 설정은 계속 가능하다.

팀 패키지의 기준 모델(df14a313…dbbea)과 카탈로그(cd956b51…dd2a)를 해시 검증 후 로컬 runtime에 배치했다. 모델 파일은 기존 전달 정책대로 Git에 포함하지 않는다. 다른 PC/배포 환경에도 패키지를 배치해야 하며, 누락·해시 불일치는 ml_status에 기록된다.

환경변수로 모드·backend·모델 경로를 지정하지 않은 기본 설정에서 실제 SVM 추천 → Qwen 4B deepagent 생성 → 저장 → CSV 선별 실행이 통과했다. amount 50/100/150 중 100·150인 B/C 두 행만 JSON 결과에 남았다. 생성기 trace에서도 candidates_available와 SVM 후보 전달을 확인했다. 실제 모델 추천과 서비스 규칙 후보의 출처는 각각 svm56/service_contract로 구분한다. 이 검증은 합성 입력 한 건, verifier off이므로 전체 도구·독립 검증 성공을 의미하지 않는다.

## 최신 main 통합 및 새 파일 재실행 회귀 수정

첨부 message-3.txt의 두 지적을 재확인했다. acccf64의 읽기 노드는 저장 파일을 항상 우선해 새 실행 파일을 무시할 수 있었다. 이는 앞선 두 파일 결합 수정이 만든 회귀이며, 이전 검증 범위에서 빠졌다. 최신 origin/main은 3e481bf로 갱신되어 API와 Compose 충돌도 실제 발생했다.

- 단일 표·문서 읽기는 이번 실행에 전달한 해당 종류의 파일을 사용한다.
- 같은 종류의 읽기 노드가 여러 개면 제공된 실제 ID가 일치하는 선택을 우선한다. 새 ID로 교체한 경우 원래 파일 이름과 유일하게 일치하는 파일에 연결한다. 업로드 순서로 왼쪽·오른쪽을 추측하지 않는다.
- 여러 파일의 이름이 중복되거나 원래 파일과 대응하지 않으면 실행을 실패시키고 파일 선택 수정을 안내한다. 이전 파일로 조용히 대체하지 않는다.
- 정책 문서와 교체 가능한 표를 함께 읽는 기존 예약·검수 흐름은 표만 새로 제공했을 때 저장된 정책 문서를 유지한다. 이 혼합 자료 회귀도 전체 테스트에 포함한다.
- 단일 표·문서 교체, 두 새 파일 역순 첨부 후 결합, 중복·변경된 파일명 거부를 실제 저장된 워크플로 실행으로 검증했다.

origin/main의 AWS S3·RunPod 설정과 업로드/보고서 저장 경로를 보존해 충돌을 해결했다. PR의 SVM 기본 활성화·UTF-8·확장 보고서 형식도 유지했다. 바이너리 보고서는 Base64를 해독한 실제 바이트로 S3에 저장·조회하도록 맞춰 XLSX/PDF 등의 손상을 방지했다. 실 AWS 계정 호출·배포는 수행하지 않았다.
