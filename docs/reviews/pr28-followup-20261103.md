# PR28 재검토 후속 수정·검증

기준: PR #28 06e1a2d. 작업 브랜치 codex/pr28-short-reply-review. 팀원 브랜치·main을 수정하거나 원격 댓글·병합·배포를 수행하지 않았다.

## 재현 → 수정 → 재검증

1. 기존 PR28의 ‘12자 이하·숫자/작업 단어 없음’ 규칙은 `메일은 취소`, `이메일은 안 해`, `요약만`, `메일 빼`, `슬랙 안함`까지 단순 응답으로 취급했다. 수정 전 추가 테스트 15개가 실패했다.
2. 판정 재사용은 명시적으로 나열한 수동 응답에만 적용한다. `네`, `알겠어요`, `모두 유지`, `그만할래` 등 기존 회귀는 유지한다. 모르는 짧은 문장은 변경이 없다고 추정하지 않고 재판정한다. fingerprint 검증을 유지한다.
3. 이 수정만으로는 실제 RunPod에서 과거 이메일 요청을 계속 미지원으로 반환했다. 최신 사용자 변경이 이전 요청과 assistant 판정보다 우선한다는 규칙을 최초 판단·미지원 재검토 양쪽에 전달한다. 대화 원문·미철회 조건을 유지하며 취소만으로 지원을 코드에서 강제하지 않는다.
4. 반대 표현 `메일은 취소하지 마`가 실제 모델에서 발송 취소로 오인되기도 했다. 단독 발송 유지·재요청 표현은 구조화된 지시로 전달한다. 모델이 지원 가능이라 하면서 실제 email.send 후보를 누락하면 manual_review로 막는다. 등록되지 않은 채널을 지원으로 승격하지 않으며 기존 미지원 검사를 유지한다.
5. SQLite 체크포인트를 재개해 취소 후 지원 재판정·자료 질문으로 이어지는 테스트를 추가했다. 미해결 질문이 남아 있으면 저장을 거부한다.

## 실제 RunPod 재검증

- 범위 축소 7회: `메일은 취소` 2회, `요약만` 2회, `이메일은 안 해`, `메일 빼`, `슬랙 안함` 각 1회. 모두 철회된 발송을 제외하고 재판정했다.
- 반대 표현 3회: `메일은 취소하지 마` 2회, `메일로는 보내줘` 1회. 최종 재실측에서 발송 요구를 유지했고 필요 조건은 clarify로 반환했다. 모델이 다시 발송을 누락할 경우 정상 확정 대신 보류하는 코드 회귀도 검증했다.
- 반품·환불 맥락의 선별 2회: gt 1,000,000 / gte 500,000, 빈 값 exclude·중복 keep·JSON 조건을 원문대로 확정했다.
- `네.`·`모두 유지`·`그만할래` 3회는 모델 호출 0으로 이전 판정을 보존했다. 이것은 실제 모델 호출 횟수에 포함하지 않는다.
- 총 실제 모델 평가 12개 사례이며 이전 미지원 상태는 통제한 fixture다. 실제 이메일 계정 연결이나 전체 워크플로 생성·저장·실행의 성공률 검증은 아니다. 단발·소수 실측으로 일반 자연어 처리 정확도를 보장하지 않는다.

중간 실측의 실패도 JSON에 보존했다. 기존 반품/비교 우회·예약·범위 제외·문서 취소 테스트는 유지했다. Gmail 미연결 정책 일원화, 한국 시간대 기본값, OAuth 구현은 이번 수정에서 임의로 결정하지 않았다.

## 실제 파일·전체 서비스 실행 추가 검증

실제 파일 파서로 CSV 7행과 영수증 TXT를 업로드한 뒤 실제 RunPod Qwen 4B와 서비스의 new_session/upload/message/confirm/test 경로를 사용했다. SVM 힌트는 켰고 독립 검증 모델은 defer다. 화면 브라우저 조작 검증은 아니다.

실측에서 추가로 두 오류를 찾아 수정했다.

- `중복 거래ID는 마지막 행만 남기고 정렬하지 말고`에서 뒤의 정렬 부정 표현이 앞의 중복 기준까지 무효화했다. 부정 판단 범위를 해당 절로 제한했다. 실제 중복 정책 부정 표현은 보수적으로 유지한다.
- 숫자와 비교 연산자를 함께 답한 `100만원 이상`을 값 응답으로 확정하지 못해 값을 다시 묻기도 했다. 숫자 열과 미해결 값 질문이 확인되는 경우에만 정확한 금액·비교 표현을 해석한다. 대략값·범위·부정 표현은 자동 확정하지 않는다.

최종 실제 대화 5개가 모두 기대 결과를 냈다.

1. 비용 100만원 초과·빈 값 제외·거래ID 마지막 행·정렬 안 함: 추가 질문 없이 생성·저장·실행. 결과 E(200만원), B(180만원).
2. 100만원 미만 제외: 연산자 확인에 `100만원 이상` 답변 후 실행. B,D,E,B이며 정확히 100만원인 D를 포함했다.
3. 이메일 포함 요청 뒤 `메일은 취소`: 발송을 제거하고 표 작업을 저장·실행. B,E,B. 계정 미연결 시 최초 unsupported 정책 자체를 바꾼 것은 아니다.
4. 중복 열 질문에 `네`: 같은 질문을 유지하고 종료하지 않았다. `거래ID` 답변 후 첫 B를 남기고 실행. 빈 비용 행도 유지했다.
5. 영수증 추출 항목 질문 뒤 `그만할래`: 질문·워크플로 생성 없이 중단. 영수증 추출 완료 검증은 아니다.

실행한 네 워크플로 모두 실제 저장 JSON 파일과 실행 rows가 일치했다. 생성된 첫 워크플로에 새 CSV를 넣어 Z 한 행만 출력되는지, 잘못된 숫자는 실행 실패로 거부되는지, 전부 빈 비용이면 빈 배열 파일이 저장되는지도 검증했다. 추가 경계 사례 3개 모두 기대 결과다.

실측 중 테스트 기대값도 정정했다. 마지막 중복 행 유지 시 원래 순서는 E→B이며 CSV 숫자는 문자열로 파싱된다. 이를 B→E/숫자 타입으로 기대했던 초기 검증 실패는 서비스 오류가 아니다. 실제 서비스 오류 두 건과 구분했다.

근거: pr28-data-execution-20261103.json. 최종 코드 전체 Python 회귀는 위 1,709/1,729개 결과이며 Node/API/UI 751개와 빌드도 재확인했다. 기존 일곱 복합 업무 시나리오 전체나 임의 자연어에 오류가 없다는 의미는 아니다. 수정은 로컬에 있으며 이번 검증에서 커밋·푸시는 하지 않았다.
