# 임시 도구 생성·검증 실험 경로

2026-10-26 / `a4b-tool-lab-v1`

현재 코드 규격은 `transform-function-v2`다. `a4b-tool-lab-v1`은 평가 자료 형식이며 이전 함수 본문 방식과는 코드 규격이 다르다. 과거 결과를 재현할 때는 해당 실행의 소스 스냅샷을 사용하고 현재 실행기로 같은 코드라고 가정하지 않는다.

## 범위

서비스의 미지원 처리를 바꾸기 전, 같은 명세와 평가 자료로 모델을 비교하는 독립 CLI다. 실제 서비스 API·도구 레지스트리·SVM·저장된 워크플로우에는 연결하지 않는다. 시험 통과는 정식 등록이나 모든 입력의 정확성을 뜻하지 않는다.

첫 실행 언어는 **JavaScript**다. 저장소에 있는 `Frontend/server/sandbox.ts`의 QuickJS WASM 실행기를 재사용한다. 기존 Python 도구 구현과는 별도이며, Python 소스 생성/실행은 이번 범위에 포함하지 않는다. Docker나 새 패키지를 설치하지 않는다.

지원하는 작업은 JSON 행 배열을 JSON 행 배열로 바꾸는 동기식 변환이다. 표 계산·문자열·날짜 처리를 대상으로 하며 네트워크·파일·DB·외부 전송·패키지 설치·비동기 작업은 제공하지 않는다. 각 행의 열 값은 문자열·유한한 숫자·불리언·null로 제한한다. 명세에 미정 조건이 남으면 모델 호출 전에 보류한다.

## 처리 순서

1. 입력·출력 열, 자료형, 처리 기준, 미정 조건과 공개/숨긴 사례를 검증한다.
2. 모델에는 명세와 공개 예시만 보낸다. 숨긴 입력·정답은 보내지 않는다.
3. 모델 응답을 candidate / needs_clarification / out_of_scope로 구분한다. 질문·범위 안내의 코드는 실행하지 않는다.
4. candidate는 `function transform(rows) { ... }` 선언 하나로 제한한다. AST로 형식·동기 함수·인자·문법을 확인한다. 원본 행을 넘기는 호출 코드는 실행기가 고정하여 추가한다. 형식 검사는 보안이나 정답의 증명이 아니다.
5. candidate만 새 QuickJS VM에서 사례별로 실행한다. 호스트 `process`, `require`, `fetch`, `Buffer`는 제공하지 않는다. 실험 경로에서는 VM 준비 최대 10초와 실제 실행 최대 2초를 분리하며 VM 메모리는 32MB로 제한한다. 기존 서비스의 기본 2초 제한은 유지한다.
6. 실제 출력 열·자료형·결과·예상 오류 메시지를 대조한다. 정상 종료만으로 통과시키지 않는다.
7. 수정은 0~2회로 제한한다. 응답 계약·소스 계약 오류의 구체적인 이유와 공개 예시 실패를 전달한다. 숨긴 시험은 실패 여부만 알리며 숨긴 입력·정답·실제 출력은 전달하지 않는다. 이전 잘못된 코드를 새로운 요구로 취급하지 않는다.
8. 코드·해시·모델 설정·응답·토큰 사용량·처리 시간·실패·평가 결과를 새 실행 폴더에 저장한다. 자동 정식 등록은 하지 않는다.

## 모델 없이 검증 체계 실행

`Frontend` 폴더에서:

```sh
npm run tool-lab:demo
```

달력 날짜·전화번호·부가세 계산 3개 업무, 총 12개 사례다. 수동 작성 정상 응답과 의도적으로 반올림을 잘못한 응답을 각각 실행한다. **이 결과는 Qwen/GPT 성능이 아니다.** 자료는 개발용으로 작성했으며 `human_reviewed=false`다.

기본 기록 위치는 워크스페이스의 `research/a4b_tool_lab_20261026/<실행 UUID>/`다. 다른 위치는 `--output`으로 명시한다. 기존 기록을 덮어쓰지 않는다.

## 실제 모델 연결

Ollama·vLLM·OpenAI 어댑터를 제공한다. 아래 명령은 사용자가 직접 실행할 때 모델을 호출한다. OpenAI는 선택한 모델이 Chat Completions의 JSON Schema 응답을 지원해야 한다. 지원되지 않으면 호출 오류로 기록하며 다른 모델로 자동 전환하지 않는다.

```sh
# 동일한 평가 파일을 각 모델에 사용한다. 경로는 실제 demo 실행 폴더로 바꾼다.
npm run tool-lab -- --provider ollama --model qwen3.5:4b --dataset /절대경로/실행폴더/dataset.json --repairs 1

# OPENAI_API_KEY는 사용자의 실행 환경에서 제공한다. 명령 인자나 기록에 키를 넣지 않는다.
npm run tool-lab -- --provider openai --model 사용할_모델_ID --dataset /절대경로/실행폴더/dataset.json --repairs 1

npm run tool-lab -- --provider vllm --model 서버에_등록된_모델_ID --endpoint http://127.0.0.1:8000/v1 --dataset /절대경로/실행폴더/dataset.json --repairs 1
```

vLLM 인증이 필요하면 `A4B_TOOL_LAB_API_KEY`를 실행 환경에 제공한다. 서비스의 `.env`나 저장된 사용자 계정은 자동으로 읽지 않는다. 외부 모델을 선택하면 공개 예시와 명세가 해당 모델 서버로 전달되므로 실제 고객 자료를 쓰기 전에 전달 범위를 확인한다. 제공된 시연 자료는 합성 자료다.

## 결과 비교

```sh
npm run tool-lab -- --compare '/첫번째/실행폴더,/두번째/실행폴더'
```

평가 자료 해시·수정 한도·실행 코드·Node/QuickJS 환경이 같아야 한다. 수동 응답 시연과 실제 모델 시험을 섞어 비교하지 않는다. 모델별 추론 설정은 manifest에 남으므로 같은 샘플링 분포라고 가정하지 않는다.

- `first_pass_tasks`: 첫 응답이 모든 사례를 통과한 업무 수.
- `passed_within_budget_tasks`: 수정 한도 내에 모든 사례를 통과한 업무 수.
- `task_count`, `blocked_tasks`: 전체 업무와 조건 부족으로 호출하지 않은 업무를 별도 표시.
- `generation_error_attempts`: 연결·응답 형식 오류를 제외하지 않고 기록.
- `source_error_attempts`: 함수 이름·호출 형식·문법 등 소스 계약 오류를 별도 기록.
- `generation_calls`: 수동 응답을 포함한 생성 연결부 호출 수. `model_calls`는 수동 시연에서 0.
- `generation_ms`, `execution_ms`: 생성과 격리 실행 시간 구분.
- `cost_usd`: 아직 계산하지 않으므로 null. null을 0원으로 해석하지 않는다. 토큰·요금·서버 비용을 추가 확인해야 한다.

한 번의 소규모 실행은 모델 우위나 운영 정확도를 증명하지 않는다. 사람 검수된 미사용 평가 사례와 반복 실행이 필요하다. 자동 평가 자체의 오답 허용률과 운영 정답률도 아직 측정하지 않았다.

## 기록과 제한

manifest에는 명세·자료 해시, 실행 코드 스냅샷/해시, QuickJS 잠금 버전, Node 버전과 설정을 남긴다. 후보 파일에는 코드 해시와 `registration_status=unregistered`를 기록한다. 요청·응답과 평가 입력/정답은 로컬 파일에 저장되며 평가 로그는 비밀 저장소가 아니다. 파일은 권한 0600, 새 실행 폴더는 0700으로 생성한다. 기존 상위 폴더 권한이나 외부 백업까지 통제하는 것은 아니다.

격리는 코드의 정답이나 완전한 보안 증명이 아니다. 첫 시제품은 제한된 입력·출력과 자원 제한을 적용하는 실험용 실행기다. Python, 외부 API 연결, DB 변경은 별도 실행·권한 설계가 필요하다. 정식 도구 승격에는 개발자 검토, 별도 검증 자료, 레지스트리·포트·버전·SVM 라벨 정책 검토가 필요하다.

## 검증 명령

```sh
npm run check
```

실제 외부 API나 로컬 모델 호출 없이도 조건 보류, 응답 계약, 숨긴 평가 분리, 오류 기록, 경계값 차단, 자원 제한, 모델 교체 요청 형식을 검사한다. 실제 provider 연결 성공과 모델 품질 비교는 별도 검증이다.

## v2 실제 Qwen 재시험

Qwen3.5:4B의 기존 3개 업무·29개 개발 사례로 재시험했다. 5개 응답에서 응답·함수 형식 오류는 없었지만, 업무 전체 통과는 첫 생성 0/3·수정 후 0/3이다. 날짜는 최종 6/10, 부가세는 최종 8/10, 전화번호는 명세가 충분함에도 질문으로 전환했다. 이 결과를 독립 정확도나 전체 12개 업무의 재평가로 해석하지 않는다. 자동 서비스 사용 경로는 여전히 연결하지 않았다.

## 2026-10-27 후속: 선택형 코드 품질 후보

기존 기본 프롬프트는 v2다. `tool-lab:gap --prompt v3/v4/v5/v6/v7`로 선택하는 개발 후보를 추가했다. 프롬프트 문구·명세 표현·응답 제약이 다르므로 모델 자체의 비교와 구분한다. `compareExperiments`는 서로 다른 prompt_version을 같은 모델 비교로 합치지 않는다.

- v3/v4: 구현 점검·반올림/예외/보존 구분과 원래 명세의 재제시.
- v5: 명세에 정확히 있는 제한된 문구를 원문 인용과 함께 구조화하고, 숨긴 실패의 종류만 전달. 숨긴 입력·기대값·실제값·사례 ID·건수는 전송하지 않음.
- v6: 영어 지침·실패 코드 재전송 생략 실험. 코드+질문 혼합 오류 등 부정 결과도 보존.
- v7: 한국어 v5 계열 지침, 인용한 문자열 규칙의 전체 정규식 제약, Ollama의 조건부 응답 스키마. candidate는 코드가 있고 질문은 없어야 하며 clarification은 코드 없이 질문을 반환. 응답 후 기존 코드 검증도 유지.

`literalPolicyHints`는 완전한 자연어 해석기가 아니다. 특정 표기와 안전한 범위만 인식하고 부정·범위 오류 등은 보조를 생략한다. `아니면` 같은 오류 처리 조건과 실제 부정도 구분한다. 보조가 없다고 정책이 확정됐다는 뜻이 아니며 원래 명세를 계속 제공한다. 정규식·연산 힌트는 코드로 제공한 제약이므로 무보조 코드 생성 성능으로 해석하지 않는다.

직접 호출 시 v7은 `remoteGenerator({provider:'ollama', model:..., conditionalStatus:true})`와 `runExperiment(..., {promptVersion:'v7', ...})`를 함께 선택해야 한다. gap CLI가 이 조합을 구성한다. 기본 서비스 모델·기본 프롬프트·격리 제한·수정 상한·등록 정책은 바꾸지 않았다.

개발 비교·부정 결과·시간·추가 자동작성 스트레스 검사는 작업공간 `research/a4b_tool_quality_20261027`에 보관한다. 기존 29건을 개발에 사용했으므로 사람 검수 미사용 평가셋의 일반화 검증이 별도로 필요하다.

최종 v7 개발 실행은 기존 29개 사례에서 업무 3/3·사례 29/29를 첫 생성에 통과했고 동일 소스 반복에서도 같았다. 추가 자동작성 30개 스트레스 사례(기존 공개 3개+새 27개)도 두 실행의 코드가 통과했다. 첫 최종 반환 평균 47.0초·반복 34.8초이며 속도 차이의 원인을 통제한 시험은 아니다. 기본 v2의 과거 0/3 기록을 수정하지 않으며 사람 검수 미사용 평가·실제 도구 누락 판정·원래 워크플로우 자동 연결은 별도다.
