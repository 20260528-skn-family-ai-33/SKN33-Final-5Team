# 문서 결과 채택·검토 구현 및 실제 파일 검증

검증일: 2026-10-28. 브랜치: `feat/JHD/document-analysis-routing`.

## 구현한 동작

- 자료 상세의 **원본·대조 후보 검토**에서 기본 추출 내용·후보 본문·표 셀 내용과 위치·병합을 비교한다. 이미지 전체, 해당 표 영역, PDF 원본 또는 한글 변환 PDF를 열 수 있다.
- 후보마다 **후보 채택·기본 결과 유지·보류**와 메모를 저장한다. 채택하면 해당 범위의 기본 결과를 후보로 교체하고, 보류·기본 유지는 원래 선택을 사용한다.
- 미결·보류 항목이 있으면 완료를 막는다. 원본·파서 주의사항 확인을 체크한 뒤 검토 완료를 저장한다. 완료 상태의 결정을 바꾸려면 검토를 다시 연다.
- `document_reviews`에 현재 검토 상태, `document_review_events`에 변경 이력을 저장한다. 화면에는 최근 50개를 표시하고 DB에는 전체 이력을 남긴다.
- 원본·최초 파서 JSON·엔진 결과 파일은 수정하지 않는다. 저장된 자산을 조회할 때 검토 결정을 적용해 본문·표·문서 읽기·검색 근거에 반영한다.
- 원본 SHA256·분석 결과 SHA256·예상 검토 버전과 요청 UUID를 검사한다. 같은 요청은 중복 적용하지 않으며 오래된 화면·동시 저장·위조 후보·분석 변경은 거부한다.
- 검토 시 자산 버전을 갱신한다. 이전 자산 버전으로 만든 설계는 바로 확정할 수 없고, 업무 설명을 다시 보내 현재 자료와 근거를 확인해야 한다.

사람의 검토 완료는 문서 전체 정확도의 보증이 아니다. 원래 `parser_status=partial`과 자동 검사 사유를 유지하며 사람의 확인은 `parser_metadata.document_review`에 분리한다. 채택 단위는 이미지 문맥·PDF 페이지·Office 문서 전체이며 개별 셀 편집이나 후보 간 셀 혼합은 제공하지 않는다.

## 실제 HTTP·엔진 검증

기본 `.env`와 실제 서비스 실행 스크립트로 새 시험 DB를 만들고 PDF·문자 PNG·한글 표 PNG 3건을 업로드했다. 파서 모델은 대체하지 않았다. MinerU 4.0.12, PaddleOCR 3.7.0, Docling 2.133.0을 실제 실행했다.

| 검사 | 결과 |
|---|---|
| 실제 업로드·필수 엔진 실행 | 3/3 통과 |
| 지정 문자열 | 10/10 보존 |
| 한글 표의 채택 전 대조 후보 | 16/16 셀 내용·위치·병합 일치 |
| 보류 저장 | `deferred`, 기본 표 0개 유지, 완료 거부 |
| 후보 채택 | 기본 표 결과 0개 → 1개 |
| 기본 결과 복원 | 표 0개·최초 기본 본문과 일치 |
| 재채택·완료 | 표 1개, 사람 검토 `completed`, 최초 파서 `partial` 유지 |
| 요청 재전송 | 같은 요청 UUID의 이력·버전 중복 증가 없음 |
| 오래된 화면·확인 누락 | 저장 거부 |
| 최초 결과 파일·원본 | 해시 보존 |
| 서비스 재시작 | 검토 완료·선택 블록·분석 메타데이터 보존 |

등록 도구가 사용하는 `agent_builder.workflow_runtime.document_chunks`로 저장된 자산도 읽었다. 채택한 후보 블록 4개만 반환됐고 기존 크롭/OCR 본문 블록은 제외됐다. 원시 자산의 표는 0개, 검토 적용 자산의 표는 1개로 분리됐다. 문서 읽기 근거에는 검토 완료·검토 버전이 들어갔고 최초 파서의 `partial` 상태는 유지됐다.

## 실제 브라우저 검증

별도 로컬 서비스와 시험 DB에서 동일한 한글 표 PNG를 브라우저의 자료 연결로 업로드했다. 자료 상세에서 원본 표 영역과 기본 추출·후보 셀을 열어 다음 동작을 확인했다.

1. 후보를 결정하지 않으면 원본 확인을 체크해도 완료 버튼이 비활성이다.
2. 보류·메모 저장 후 **보류 있음**, 저장 버전 1이 표시된다.
3. 후보 채택 후 **후보 채택**, 저장 버전 2가 표시되고 현재 본문에 구조화된 표가 반영된다.
4. 원본·주의사항 확인 후 완료하면 **사람 검토 완료**, 저장 버전 3과 완료 시각이 표시된다.

원본의 여백 때문에 표를 읽기 어려웠던 화면을 보완해 전체 이미지는 펼쳐 볼 수 있게 하고 관련 표 영역을 바로 표시했다. 좁은 화면에서는 기본·후보를 세로로 배치하고, 넓은 화면에는 두 열을 사용한다. 표 HTML을 실행하지 않고 셀 문자열로 표시한다. 미리보기는 저장된 객체 ID로만 접근하고 작업 폴더 밖 경로는 거부한다.
