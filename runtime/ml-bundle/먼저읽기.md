# SVM 모델 전달 — 2026-11-04

이 묶음은 현재 main이 지정한 기준 SVM 모델입니다. 새 재학습 모델로 교체하는 작업이 아닙니다.
모델 바이너리는 GitHub에 올리지 않고 이 ZIP으로 별도 전달합니다.

## 어디에 무엇을 두나요?

- GitHub 코드: 추천 실행 코드와 설치/진단 명령. PR38: https://github.com/20260528-skn-family-ai-33/SKN33-Final-5Team/pull/38
- EC2: 아래 model/와 catalog/를 서비스가 읽는 폴더에 배치합니다.
- 팀원 PC: 로컬에서 추천을 실행할 사람만 같은 파일이 필요합니다. EC2 웹서비스를 이용하기만 하면 설치할 필요가 없습니다.

## 필요한 파일

```
ml-bundle/
  model/
    recommender_char_svm_5431.joblib
  catalog/
    catalog_56.json
```

이름이 recommender로 시작하는 joblib가 모델 파일입니다. “recommender 코드”를 말한 것이라면
현재 서비스의 추론 클래스는 `Backend/ml/svm56/inference_adapter.py`의 `ToolRecommender`입니다.
연결 진입점은 `Backend/ml/advice/tool_recommendation.py`이며 `svm56_service_hook.py`와
관련 어댑터를 함께 사용합니다. 이 코드는 이미 main에 있으므로 임의의 다른 recommender.py를 덮어쓰지 않습니다.

## 팀원 PC의 기본 설치 경로

```
<팀 저장소 루트>/runtime/ml-bundle/model/recommender_char_svm_5431.joblib
<팀 저장소 루트>/runtime/ml-bundle/catalog/catalog_56.json
```

PR38 반영 버전에서 저장소 루트에서 실행:

```
npm run ml:install -- --source "<이 ZIP을 풀어 나온 폴더>"
npm run ml:check -- --probe
```

Python 환경이 없으면 `npm run setup`을 먼저 실행합니다. 이 설치 명령은 다른 기존 모델이나 .env를 덮어쓰지 않습니다.

## EC2는 이 순서로 확인

EC2의 실제 호스트 폴더는 현재 컨테이너 마운트를 봐야 확정할 수 있습니다.
아래 명령은 조회만 합니다. 전체 환경변수나 인증키를 공유할 필요가 없습니다.

```
docker inspect -f '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}' a4b-jhd-aws
```

컨테이너 안에서 모델을 읽는 경로는 호스트(EC2) 경로와 다를 수 있습니다.
Compose 기본 구성은 호스트 묶음을 `/app/ml-bundle`에 연결하며 그 안의 model/, catalog/를 읽습니다.
기존 EC2 배포는 Compose 설정을 자동 적용하지 않고 현재 환경변수·마운트를 유지하므로
main을 새로 배포하는 것만으로 모델이 설치되거나 off 설정이 바뀌지는 않습니다.

PR38 코드가 배포된 뒤, 실제 서비스 컨테이너에서 확인:

```
docker exec -w /app/Backend a4b-jhd-aws /app/Backend/.venv-agent/bin/python -m ml.svm56.bundle_cli check --probe
```

배포 담당자가 확인할 설정은 `A4B_TOOL_ADVICE_MODE=hint`, `A4B_TOOL_ADVICE_BACKEND=svm56`,
모델·카탈로그의 컨테이너 내부 경로와 이를 연결하는 호스트 폴더입니다.
기존 배포 스크립트는 마운트 수를 제한하므로 임의로 새 마운트를 추가하지 말고 현재 배포 방식과 함께 반영합니다.

`svm_candidates_verified`는 그 컨테이너에서 SVM 후보가 나온다는 뜻입니다.
이후 실제 설계 trace에서 `tool_advice_status`와 `tool_advice_candidates`의 `source=svm56`을 확인합니다.
이 ZIP을 만든 로컬에서는 파일 설치와 실제 SVM 추천을 확인했지만 운영 EC2는 아직 확인하지 않았습니다.
