# 9B Planner / Capability 비교 조건

비교 대상은 통합 안정본과 첫째 Planner만 바꾼 사본, 둘째 Capability만 바꾼 사본이다. H01, H21, H32 순서로 같은 워커와 동결 입력을 사용한다. 초기 모델 접속 점검과 사용자 응답 대기는 제외한다. 사례 세 건의 중앙값은 이 세 요청에 한정한다.

- H01은 요청 필터, CSV 형식, 원래 행 순서 및 동결 예상 행을 확인한다.
- H21은 정책 질문 하나, 해당 질문 ID 답변, 확정 last와 결과 CSV를 확인한다. 최초 발화부터 유효한 질문까지와 답변부터 검증 완료까지 worker.message의 실제 왕복 시간을 각각 비교한다.
- H32는 원자료, 동일한 요약 출력에 연결된 Markdown 및 메일 본문, 확정한 수신자·제목과 추가 질문 0건을 검사한다. 외부 커넥터를 실행하지 않는다.
- 앱 파일별 해시·모델 digest·GPU 상주량·프로필·하니스·동결 정답을 대조한다. 케이스당 실제 입출력 토큰·모델 호출 수·모델 로드 시간·단계 지연·전체 지연을 보존한다. 단계 합산과 SDK 내부 미기록을 구분한다.
- 정상 및 반대 사례에서 의미·질문·검증이 유지되어야 한다. 실제 전후 비교에서 희망한 절감이 관측되지 않거나 불필요한 질문·의미 회귀가 생기면 후보를 회수한다. 속도 차이가 작거나 로드 상태가 다르면 동일 상주 조건으로 전후를 다시 확인한다. 각 후보에는 변경에 영향을 받은 사례와 영향을 받지 않은 대조 사례를 구분한다.
- 두 후보가 각각 통과하면 채택할 조합에서도 실제 세 사례를 확인한다. 한 후보만 통과하면 그 소스와 최종본이 같은지 확인하고 변동 큰 개선은 재측정한다. 전체 평가 및 외부 메일 발송은 수행하지 않는다.
