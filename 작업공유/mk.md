## 목표 동작

사용자가 서비스에 로그인해서 다음 작업을 할 수 있어야 해.

1. ‘내 자료’에서 ‘영수증’ 같은 폴더와 하위 폴더를 만든다.
2. 해당 폴더에 PDF·이미지 등 현재 지원하는 파일을 업로드한다.
3. 저장된 워크플로우의 입력으로 폴더를 선택한다.
4. ‘매일 오전 9시, 이 폴더의 미처리 파일을 처리’하도록 예약한다.
5. 서버가 예약 시각에 대상 파일을 확정하고 파일별로 처리한다.
6. 실행 결과와 파일별 성공·실패·건너뜀 상태를 화면에서 확인한다.

사용자가 브라우저를 닫아도 서버가 실행 중이면 예약 작업이 동작해야 한다.

## 1. 사용자와 접근 권한

- 기존 로그인·인증 기능이 있으면 재사용해 줘.
- 인증 기능이 없다면 단일 서버에서 사용할 수 있는 최소한의 로그인·세션 구조를 먼저 마련해 줘. 화면에서 사용자 ID만 고르는 방식으로 사용자별 격리를 구현하지 마.
- 사용자 소유권은 서버가 인증된 세션을 기준으로 판단해야 해. 클라이언트가 보낸 사용자 ID를 그대로 신뢰하지 마.
- 폴더·파일·워크플로우·예약·실행 기록·원본 다운로드·결과 다운로드에 소유권 검사를 적용해 줘.
- 다른 사용자의 ID를 직접 요청해도 조회·수정·실행·다운로드할 수 없어야 해.

## 2. 서비스 내부의 논리적 폴더

폴더는 사용자의 PC 경로가 아니라 서비스 안에서 관리하는 자료 분류 구조로 만들어 줘.

- 폴더 생성·이름 변경·이동·삭제
- 하위 폴더 생성
- 폴더별 파일 목록과 파일 업로드
- 파일 이동과 삭제
- 자기 자신이나 자신의 하위 폴더로 이동하는 순환 구조 방지

DB에는 사용자·폴더·상하위 관계·파일 소속·파일 버전·처리 상태 등을 저장하고, 원본 파일은 기존 서버 파일 저장 방식을 재사용해 줘.

이번 구현에 S3를 필수로 추가하지 마. 향후 파일 저장소를 변경할 수 있도록 파일의 논리적 정보와 물리적 저장 위치는 분리해 줘.

비어 있지 않은 폴더 삭제와 예약 대상 폴더 삭제는 명확한 정책을 적용해 줘. 초기 구현에서는 삭제를 제한하고 이유를 안내하는 방식도 괜찮아.

## 3. 폴더를 예약 자료원으로 연결

- 기존 단일 파일 자료원과 폴더 자료원을 구분해 저장해 줘.
- 사용자가 소유한 폴더와 저장된 워크플로우를 연결할 수 있어야 해.
- 일간·주간 예약과 시간대 설정 등 기존 기능을 재사용해 줘.
- 기본 예시는 `Asia/Seoul` 기준 매일 오전 9시야.
- 기본 처리 범위는 선택한 폴더의 직속 파일로 하고, 하위 폴더 포함 여부는 명확하게 정의해 줘.
- 예약 활성화 전에 워크플로우와 대상 파일 형식이 호환되는지 검사해 줘.

## 4. 폴더 예약을 파일별 실행으로 확장

기존 워크플로우 엔진에 새로운 반복·병렬 그래프 기능을 크게 추가하기보다는, 예약 작업이 파일별 실행을 생성하고 기존 실행기를 호출하는 방식을 우선 검토해 줘.

- 예약 작업 하나에 대상 파일 목록과 버전을 확정해서 저장해 줘.
- 확정 이후 업로드된 파일은 다음 예약에서 처리해 줘.
- 파일별로 기존 파서와 워크플로우 실행 기능을 재사용해 줘.
- 이미 업로드 과정에서 파싱한 파일은 유효한 분석 결과를 재사용해 불필요한 재파싱을 피해야 해.
- 각 파일이 실제 실행 입력으로 전달되도록 해 줘. 기존 설계에 연결된 샘플 파일이 대신 처리되면 안 돼.
- 파일 하나가 실패해도 다른 파일의 처리는 계속하고, 실패 항목을 개별 기록해 줘.
- GPU 작업이 몰릴 때를 고려해서 동시 실행 수에 제한을 두고, 초기 기본값은 순차 실행으로 해 줘.
- 예약 때마다 설계를 다시 생성하지 말고 저장된 워크플로우의 확정 버전을 실행해 줘.
- 이번 범위는 파일별 처리와 결과 목록 제공이야. 여러 파일을 하나로 합치는 집계 기능은 기존 워크플로우에서 지원하는 범위를 넘어 임의로 추가하지 마.

## 5. 미처리 파일 판정과 재시도

‘이미 처리한 파일’을 폴더 전체의 단일 상태로 관리하지 마.

- 예약 또는 워크플로우와 파일 버전의 관계를 기준으로 처리 이력을 관리해 줘.
- 다른 업무에서 처리한 파일도 새 워크플로우에서는 처리할 수 있어야 해.
- 같은 예약·같은 파일 버전의 성공 항목은 기본적으로 다시 실행하지 마.
- 파일 내용이나 워크플로우 버전이 바뀌었을 때의 재처리 기준을 정의하고 문서화해 줘.
- 실패 항목은 사용자가 재시도할 수 있어야 해.
- 스케줄러가 중복 실행되거나 서버가 재시작돼도 같은 작업이 동시에 처리되지 않도록 기존 잠금·작업 ID·중복 방지 구조를 활용해 줘.
- 대상 파일이 없으면 오류 대신 ‘처리할 파일 없음’으로 기록해 줘.
- 예약 시각에 서버가 꺼져 있었다가 켜진 경우의 실행 정책도 명확히 정해 줘.

## 6. 프론트 화면

기존 화면 디자인과 사용 흐름을 최대한 재사용해 줘.

필요한 화면은 다음과 같아.

- 내 자료: 폴더 탐색·생성·이동·파일 업로드
- 예약 설정: 워크플로우·대상 폴더·요일/시간·시간대 선택
- 예약 실행 내역: 예정 시각·실제 시작 시각·전체 진행 상태
- 파일별 결과: 성공·실패·건너뜀·결과 보기·재시도

예약 시각은 작업 시작을 요청하는 시각이고, 대기 중이면 실제 시작이 늦어질 수 있다는 점을 화면 상태로 표현해 줘.

## 7. DB 변경과 기존 데이터

- 현재 사용하는 SQLite 구조를 우선 유지해 줘.
- 기존 DB에 안전하게 적용되는 마이그레이션을 작성해 줘.
- 기존 자료·워크플로우·단일 파일 예약을 보존해 줘.
- 기존 데이터의 사용자 귀속 정책을 정하고 문서화해 줘. 모든 사용자에게 기존 자료가 자동 노출되면 안 돼.
- 소유권·폴더 관계·파일 버전·작업 상태를 조회할 때 필요한 제약과 인덱스를 마련해 줘.

## 8. 검증과 완료 보고

다음 동작을 의미 있는 테스트로 확인해 줘.

1. 사용자 A가 사용자 B의 자료·예약·결과에 접근할 수 없다.
2. 폴더 생성·이동·파일 업로드가 정상 동작하고 순환 이동은 차단된다.
3. 지정 시간대의 예약이 대상 폴더 파일을 선택한다.
4. 같은 예약이 중복 확인돼도 같은 파일 작업이 중복 생성되지 않는다.
5. 성공한 파일은 건너뛰고 새 파일·변경 파일은 정책에 따라 처리한다.
6. 파일 하나의 실패가 다른 파일 처리를 막지 않는다.
7. 서버 재시작 후 실행 중이던 작업을 정책에 따라 복구한다.
8. 기존 단일 파일 예약과 수동 실행이 계속 동작한다.
9. 원본·결과 다운로드에도 소유권 검사가 적용된다.
